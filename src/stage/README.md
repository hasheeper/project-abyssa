# 固定画布舞台（共享基底）

「外 16:9 贴设备，内容等比缩放」。用于 shop / dice 这类**固定舞台型**界面
（几何关系有意义、必须整体等比的），不适用于 demo / studio 这类文档流型页面。

## 用法

```tsx
import { Stage } from "../stage";

export function MyPage() {
  return (
    <Stage background="#12100b">
      <div className="my-screen">…按设计原尺寸写，一个 px 都不用改…</div>
    </Stage>
  );
}
```

```ts
// main.tsx
import "../stage/stage.css";
```

```html
<!-- 应用的 HTML 入口 -->
<html class="abyssa-stage-root">
  <meta name="viewport"
        content="width=device-width, initial-scale=1.0, viewport-fit=cover, user-scalable=no" />
```

## 三条铁律

**1. 画布内一切尺寸用设计原值，禁用 vw / vh / cqi / cqh / %（宽度百分比除外）。**

整体 `scale` 的前提就是内容保持设计原值。视口相关单位会与外层 scale 叠加成
二次缩放，构图必然漂移。shop 试点第一版就是把外框改成 `cqh`、内容留 `px`，
结果外框缩了内容没缩，实测溢出 219px 被裁。

**2. 不要用媒体查询在画布内重排。**

视口变小时是**整个画布连同内部一起缩小**，内部布局在任何视口下都是同一套
设计尺寸。此时按视口宽切换 `grid-template-columns` 会与外层 scale 叠加成
「缩放 + 重排」混合态：内容被塞进单列却仍被整体缩放，构图彻底错位。

手机横屏由 16:9 贴合 + 等比缩放覆盖。若日后要支持手机**竖屏**（比例差太多，
等比缩放会小得没法用），正确做法是用 `@container` 查询舞台自身尺寸来重排，
而不是查视口。

**3. 边框、外壳这类装饰，要和内容一起纳入缩放，不要单独调数值。**

这是 shop 试点第二轮的教训。当画布尺寸与原型不同时，边框的**绝对数值**没变
但**相对占比**会变，看起来就「变粗了」。此时若手工把 `22px` 调成 `16px`，
等于把「当前画布尺寸」焊死进样式，换个画布又要重调一轮，基底就失去意义。

正确做法：让整组（外壳 + 边框 + 内容）按「参照尺寸 → 实际画布」的比例
统一缩放，边框视觉占比自然与原型一致。见 shop 的 `--shop-frame-k`。

## 为什么 16:9

按 contain 适配算有效面积占屏比：

| 基准 | 手机横屏 2.17 | Pixel 2.22 | iPad 1.44 | 1920×1080 | MBP14 1.54 |
|---|---|---|---|---|---|
| **16:9** | **82.0%** | **80.0%** | 80.9% | **100%** | 86.6% |
| 16:10 | 73.8% | 72.0% | 89.9% | 90.0% | 96.2% |
| 3:2 | 69.2% | 67.5% | 95.9% | 84.4% | 97.4% |

只有 16:9 在「手机横屏 + 桌面」两端都不低于 80%，而这正是目标场景。
内容板可以另锁自己的比例（shop 用 3:2），差值交给外圈边框吸收。

## 为什么缩放系数必须由 JS 给

等比缩放需要无量纲系数 `k = min(容器宽/画布宽, 容器高/画布高)`，而 CSS 的
`calc()` 不支持长度÷长度→数字，纯 CSS 拿不到 `k`。详见 `useStageScale.ts`
顶部，那里记录了两条失败的替代路线。

## 验证方法

改动后务必实测，不要靠估算。做法：构建产物 + headless 浏览器注入量测脚本，
读 `getBoundingClientRect()` 并除以 `k` 还原设计值。判据：

- 画布比例 = 1.77778
- 左右间隙差 ≈ 0（`margin:auto` 那个 bug 的判据就是这里不为 0）
- **不同视口下内容的设计值必须完全一致** —— 这是等比的硬证据
- 无页面滚动、内容无溢出

## 画框契约

`stage.css` 的 `:root` 里有一组共享令牌，规定了「中间主要显示区域」的几何。

| 令牌 | 值 | 含义 |
|---|---|---|
| `--abyssa-frame-interior-w/h` | 1250×787 | **内容可用区**。所有 UI 都画在这个矩形里 |
| `--abyssa-frame-rail` | 22px | 外层木质压条厚度 |
| `--abyssa-frame-brass` | 3px | 黄铜夹层厚度 |
| `--abyssa-frame-border` / `-hair` | 2px / 1px | 三层描边 |
| `--abyssa-frame-k` | 0.87229 | 整组缩放系数（所有应用共享） |

### 画框几何全部共享，内容才是各应用自己的

`board` / `shell` 尺寸、`padding`、招牌露出高**全部在契约里**。

曾经错过一次：让各应用保留自己的 `padding`（误以为「边框随本来样式」指
padding），board 改由 `interior + 各自 padding` 推导。结果 padding 不同
→ board 不同 → shell 不同 → **所有可见边缘全部错位**：

```
shell / brass / board   Δ 最大 22.68px
招牌                    Δ 最大 87.23px
interior                Δ  0.00px   ← 唯一对齐的，恰恰是唯一看不见的
```

教训：**画框是给人看的，不变量必须定在可见边缘的绝对位置上。**
`padding` 决定画框宽度，属于几何，必须共享；「样式」只指皮肤（渐变、
高光、纹理、金属角有无），不含任何影响尺寸的量。

### 不变量为什么是「屏幕厚度」而不是「占比」

board 尺寸不同时这两者互斥：

- 占比恒定 = 把同一张画框照片放大缩小 → 大 board 的框更粗
- **厚度恒定** = 同一批木料铜条做的画框，不同尺寸的画用同宽压条

后者才是「一套」的物理隐喻。因为所有应用共享同一个 `k`，令牌里的设计 px
恒定即等价于屏幕厚度恒定。

### 接入新应用

1. `board` 尺寸由 interior + 自己的 padding 推导，不要写死：
   ```css
   width: calc(var(--abyssa-frame-interior-w) + <padL> + <padR> + var(--abyssa-frame-border) * 2);
   ```
2. 内容自然尺寸若不等于 interior，用**无单位除法**算 fit 系数：
   ```css
   --k2: 0.94697;  /* = min(1250/自然宽, 787/自然高) */
   transform: scale(var(--k2));
   margin-inline: calc((<自然宽>px * var(--k2) - <自然宽>px) / 2);
   ```
   长度÷数字在 `calc()` 里合法；长度÷长度不合法（铁律见上）。
3. 余量交给 `place-items: center`，**绝不手算偏移** —— 那是 dice 偏右
   219.5px 的成因。

### 验证标准：所有可见层逐项比对

只查 interior 和 rail 两个数是不够的 —— 那正是上一次得出错误结论的原因。
必须把 `header / shell / brass / board / interior` 五层的 **x / y / w / h**
全部换算到画布坐标系（1600×900）逐项比对，任一项差值 >1px 即失败。

实测基准（画布坐标系，shop vs dice）：

```
层           Δx     Δy     Δw     Δh
header盒    0.00   0.01   0.00   0.00
招牌svg     0.00   0.01   0.00   0.00
shell       0.00   0.02   0.00   0.00
brass       0.00   0.02   0.00   0.00
board       0.00   0.02   0.00   0.00
interior    0.00   0.02   0.00   0.00
content     0.01     —    0.00     —    高度差属内容比例不同，已知
```

四个视口（1920 / 1366 / 1024 / 852）最大偏差均为 0.020px。

`content` 的高度允许不同：内容自然比例本就不同（shop 1250×783、
dice 1320×739），各自 fit 进同一个 interior 后竖向留白不同。
