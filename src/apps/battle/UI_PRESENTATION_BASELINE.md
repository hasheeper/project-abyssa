# Battle UI 表现层基线

> 状态：概念原型基线
> 更新日期：2026-09-06
> 适用入口：`battle.html` / `npm run dev:battle`

本文描述裂隙远征的画框、主题、布局、场景气氛、场景交接和骰子动效。战斗 command、canonical state、RNG、存档与结算规则仍以 [`README.md`](README.md)、[`DEVELOPMENT_GUIDE.md`](DEVELOPMENT_GUIDE.md) 和 `domain/` 文档为准。

## 1. 所有权边界

- UI 皮肤描述整场战斗的编队或场所美术，不描述单张角色卡的阵营。
- 混编队伍进入战斗后仍只使用一套外框；角色力竭、换目标或换回合都不会自动换肤。
- `uiSkin` 是 React 表现状态，不进入 canonical battle state、undo、存档 DTO、规则版本或事件 trace。
- 右上角 `UI FRAME` 按钮是原型期的人工巡检入口，正式流程可以由编队或剧情在进入战斗时传入受控 `uiSkin`。

`ExpeditionBattleScreen` 同时支持：

- `uiSkin` + `onUiSkinChange`：受控模式；
- `defaultUiSkin`：独立演示时的非受控初值；
- 未传参数：默认 `timber`。

外层 `App` 持有当前皮肤，并把同一个值同时交给 Stage 背景类和战斗面板，防止“外面青色、里面金色”这类不同步。

## 2. 五套皮肤

| ID | 界面语义 | 外框构成 | 背景倾向 |
| --- | --- | --- | --- |
| `timber` | 原生木框 | 不加载阵营 PNG；保留木质 rail、黄铜层和原始几何 | 棕黑、低饱和 |
| `hero-party` | 勇者小队 | 金色顶饰与四角；四边以连续金属脊线为主，只留极淡编织压纹 | 青黑底、暖金高光 |
| `demon-cadre` | 四席摄政 | 青色顶饰、四角与完整编织边 | 冷青、灰黑 |
| `demon-lord` | 魔王亲征 | 猩红顶饰、四角与完整编织边 | 暗红、黑褐 |
| `old-manor` | 克雷格旧庄园，副本配色预适配 | 暗黑木框与招牌、灰麻布姓名签、悬吊顶栏与连续内沿红线 | 冷灰月光，仓库迎客门厅背景 |

皮肤清单与资产只在 `battleUiSkins.ts` 登记。`ExpeditionBattleScreen.tsx` 根据 definition 决定是否渲染顶饰、角件和 `FrameEdgeWeave`；不要在 JSX 中为某一套皮肤另写第二张结构树。

### 2.1 角件与四边衔接

层级从下到上为：

```text
shell / rails → edge weave (z5) → corner ornaments (z6)
header panel (z2) → top ornaments (z3) → subtitle / controls
```

四边从距角件 82px 处开始，在角件下方重叠，角件负责遮住接缝。勇者主题不能只挂四角 PNG 而关闭四边层，否则角件的长尾会在半途突然断开；它使用同一 `FrameEdgeWeave` DOM，但由 hero 专属 CSS 隐去 overpass、弱化 strand，只留下连续金色 rail。

### 2.2 旧庄园配色预适配

右上角 `UI FRAME` 第五项为“克雷格旧庄园”；默认仍为 `timber`。`old-manor` 使用同一画框与组件树，经皮肤定义的 `frameOverlayUrl` 加载一张完整的红线 SVG，替代分开的顶饰、角饰与 `FrameEdgeWeave`。配色集中在 `expedition-manor.css`，不加载其他阵营的顶饰或角件。

专用 SVG 位于 [`assets/ui/old-manor`](../../assets/ui/old-manor/README.md)。上方密一些：招牌两肩保留成束向上牵引的红线，维持悬吊与破窗感；移除两侧脱离线束、单独从上方落下的长竖线。松线从两肩下垂至框角，与内沿双股长线和局部回线连续相接。整图共享画框坐标，上方延伸 62px，不改变框体或内容几何。花窗、黑铁包角、钥匙、缝针、垂布等具象装饰已按用户要求去除；红线不使用链环形编织。SVG 为本地独立文件，无外部图床、字体或嵌入位图依赖。

上方的疏密由受力与松弛区分：主线束较实，细暗余线挂在已有线束或框角之间，包含浅垂跨顶线、左右垂度不同的松弧，以及从肩部绕结自然垂下的短线尾。长线有接点、弯垂遵循重力方向，不用等距平行或镜像复制来填满留白。

黑木为主体（`#090b0b` / `#171b1b`），文字以旧白布色（`#cec9bb`）为主；招牌和账本题头保持暗色，姓名签使用暗灰麻布底（`#303831`–`#424b3e`）与浅色字（`#c6c7b7`），不铺成亮白色条。姓名签的 `::before` 仅负责描边，背景必须透明；选中状态保持相同文字对比。暗红用于悬线、连续内沿、招牌细描边、当前皮肤标记与主操作按钮；外框金属高光保持收敛，丝线没有发光和模糊滤镜。

骰框的角色染色降低饱和度，骰面品质、生命、致命、治疗和格挡仍保持语义色。布面纹理由静态 CSS 渐变构成，不新增持续动画；顶栏、框体和骰盘不以高亮边框争夺战场注意力。

外层 Stage 与内场都引用仓库 `backgrounds/old-manor/welcoming-hall.jpg` 作配色预览，等比 cover；当前狭长敌方窗口会裁剪原画上下区域，正式副本舞台接入时仍需重新标定取景。此次不注册庄园遭遇、不替换敌人、不改地点与首通事实。服务走廊、宴会厅、敌人立绘及机制继续等待独立接入。

### 2.3 敌方舞台流雾

皮肤定义的 `enemyAtmosphere: "mist"` 启用雾效，当前用于 `old-manor`。`EnemyMist` 是独立表现组件：单个透明 WebGL 画布放在静态 haze 之上、敌人 formation 之下，不覆盖姓名、意图或点击区域，也不改变敌方容器的 overflow，避免裁掉战斗意图连线。

两层连续噪声以不同速度平移、卷动和变形：底部较厚，上方较薄；冷灰色受光向门厅中央花窗聚拢。密度由噪声决定，边缘渐隐；不使用反复移入的圆形光斑、发光粒子或整张图片左右摇摆。噪声纹理仅在初始化时生成，使用独立固定种子，不消费游戏 RNG，也无外部素材或新增依赖。

性能与生命周期约束：

- 上限 24fps、内部画布宽度上限 640，软雾不随 Retina 像素比扩大填充量；没有逐帧 React 状态更新、布局测量或模糊滤镜。
- 页面隐藏时停止帧循环，恢复时从原时间继续；`prefers-reduced-motion` 实时切换为静态雾。
- 切换主题／离开战斗释放帧回调、监听与 GPU 资源；WebGL 上下文恢复后重建。WebGL 不可用时保留原静态 haze。
- 同机 Chromium 十组交错开关对照（每样本 800ms，1860×1196 视口）：关闭／开启的平均样本 P95 为 16.80／16.85ms，两组均无 >25ms 帧间隔、布局耗时均为 0。该尺寸下雾画布为 612×189；此数据不代替其他设备测试。

生命周期测试、实际着色器编译、减少动态效果、上下文丢失／恢复、主题切换、掷骰与选中交互均纳入验证。

## 3. 颜色契约

主题变量分为四组：

- `--battle-skin-*`：强调色、亮色、柔和色与弱文字；
- `--battle-frame-*` / `--battle-board-*`：外框、金属、最内层底板和结构线；
- `--battle-detail-*`：账本、意图、骰盘、按钮、弹窗等内部结构色；
- `--battle-scene-*`：战斗背景图上的色调与遮罩；旧庄园主题另指定配色预览背景。

结构色可以随皮肤变化，战斗语义色不能被整页染色覆盖：

- 生命、受伤、致命与狂暴保持危险语义；
- 治疗、格挡和角色卡各自的功能色保持可辨认；
- 金币、晶石、材料与骰面品质继续使用内容语义色；
- 锈铭、金铭、封印灰与万能命数不因外框阵营而失去区分。

成牌提示遵守 D1 的资格规则：骰主存活、已掷、未封锁、命数醒；固定、已使用、空行动均不排除成牌。

- 沉眠面在原命数角标显示「眠」，悬停可查原点数及“不参与成牌”；沉眠仍可执行该面的合法行动。
- 已使用骰只淡化行动图案与强度，不整体压暗命数角标；参与当前牌型的点数继续点亮。力竭／封锁保留原禁用效果。
- 牌型槽显示本回合的**加成**（例如「一对 +0.1」），不是「×0.1」。品质抵消为零时仍显示牌型名和 +0.0。
- 悬停牌型槽显示核心返回的判定点数、贡献者及被排除骰子的原因，不在前端另算一份牌型。
- 回归例：Lv.1 的 3／1／2／3／2，柯萝萝的沉眠 3 排除、诺玛的已使用 2 保留，结算一对 +0.1；Lv.2 唤醒该 3 后为两对 +0.2。

主题最内层 board 在原有 `--battle-board-background` 上增加轻微黑色纵向罩层与内阴影，以获得更深的承托感；该处理不滤到怪物图片、文字或战斗特效。账本等内部面板继续从 `--battle-detail-surface-deep/surface/raised` 派生，禁止重新写死木棕色。

## 4. 画框与内容几何

外层 shell、rail、brass、board 的尺寸仍完全遵守 `shared/stage` 画框契约，五套皮肤不得改变可见外沿。战斗只在 board 内部减少空带：

| 项目 | 共享默认 | Battle 基线 |
| --- | ---: | ---: |
| 上内边距 | 60px | 36px（向上 bleed 24px） |
| 下内边距 | 38px | 20px（向下 bleed 18px） |
| 内容新增高度 | — | 42px |
| 敌方面板 | 280px | 322px |
| 我方面板 | 497px | 497px，不变 |

新增的 42px 全部交给敌方舞台；右侧账本随整个 interior 同步增高。我方角色卡、骰盘和五列锚点不缩放，底部 ActionDock 用下 bleed 抵消定位，仍压在原来的外框基线上。

这些数值集中在 `.abyssa-expedition-frame` 的 `--expedition-content-bleed-*` 派生变量中。调整时必须同时检查：

1. 顶饰与敌方面板之间仍有可读的空隙；
2. 右侧账本上下边与左右内容区平齐；
3. ActionDock 不掉出底框，也不遮住骰子；
4. 五套皮肤使用完全相同的几何。

## 5. 场景交接

战斗入口由 `SceneTransitionProvider reveal="panel-drop"` 包裹：

- `SceneArrivalTitle` 先在背景层显示区域名；
- `.abyssa-expedition-frame.abyssa-scene-panel` 随后从上方装入；
- Stage 战斗背景不会跟着实体面板下落；
- 首帧黑底由 `battle.html` 内联，避免跨文档导航白闪。

完整协议见 [`../../shared/transition/README.md`](../../shared/transition/README.md)。

## 8. 骰子动效与重绘范围

骰子沿用原版与 Dice Studio 共用的运动节奏：通过 `shared/presentation/roll/timing.ts` 为每枚骰子独立生成 **0.85–1.3 秒**时长，两个轴各翻滚 2–3 圈后转到目标面；减速曲线为 `cubic-bezier(.2, .75, .3, 1)`。起跳仍使用原来的 30% 抬升、60% 落下、100% 回位曲线，占旋转时长的 75%；不新增第二次回弹或统一所有骰子的落定时刻。

- 只有已提交 `dice-rolled.results` 中的骰子可以获得新旋转角度。固定、已使用、封印和力竭骰保留原姿态；最后一次重掷的自动固定不会提前取消本次旋转。
- 静止姿态直接对应实际 `faceIndex`。读档、撤回和刷新直接对齐骰面；掷骰旋转过渡仅在 `data-rolling` 存在时生效。回合结束后变为待 ROLL 的骰子用 **560ms ease-in-out** 从当前面转回投掷前的预览角度（X -18° / Y 28°），缓起缓停；解除固定时的小幅落回与旋转同步，不额外转圈或起跳。归位中点击 ROLL 可直接衔接掷骰，新回合不累加以前回合的转圈量。
- 视觉随机在 React state updater 之外采样，只影响演出，不消耗规则 RNG。
- 完整 SVG 骰面以 `memo` 复用，六个面分别限制绘制范围；旋转中不切换为低细节材质。仅滚动中的骰子申请旋转合成提示。
- 角色光束和敌方意图线独立合成，避免局部动画牵动静态场景重绘。掷骰、攻击、支援与敌方演出期间暂停这些装饰流动，保留指向关系与当前光束曲线，演出结束再恢复。
- 减少动态效果模式同时关闭旋转、归位、起跳、阴影过渡和锁定框入场，并缩短演出等待。
