# 远征／教学收获与通透结算

2026-09-24 已接入主应用的 `ManorBattleBinding`。正式页和 `battle-loot.html` 共用本目录的结算、收获条目、LOG 与悬浮详情，后续样式只维护这一份。测试样本和 F2 面板留在 `loot-lab`，没有进入正式依赖。

2026-09-25 教学关复用同一套组件，不再使用独立的单件发现页和旧领奖页：

- 教学赏金与四类固定战利品沿实际事件队列触发 `SceneFeedback`；通知宿主在剧情序列外，Boss 后切入 S3-5 不会吞掉通知。四条同时可见，其余排队展示，读档不补播；撤销或教学重试清理当前提示。
- 教学 LOG 展示真实未入袋／已入袋收获，物品点击、悬浮和键盘聚焦复用 `LootHoverDetail`。数量来自物品定义，未鉴定品不公开真实名称与品质。教学规则文案不套用普通远征失败减半。
- 完成 S3-5／S4-1 全部阅读后才打开 `LootSettlementView`。追回货物报酬计入上方待领取总额，四批战利品和剩余战备分开展示；点击“领取并返回洋馆”才提交原有结算事务。提交失败保留明确重试入口。
- 固定掉落、鉴定／出售价格、教学重试、角色卡、正文与存档格式不变。不启用随机掉落，也不把干黑面包变成可用食物。

## 正常流程

- 赏金、事件资金和 `loot-found` 在演出到达对应事件时触发通用侧上通知，多条向下叠加。读档不重播旧通知，撤销清掉待展示提示。
- LOG 分为未入袋与已入袋，仅这两组折叠。钱数来自引擎，道具来自 `carriedLoot` 与已结算层，不根据击杀临时编造道具。
- 失败、撤离、通关统一使用通透结算。庄园通关保留既有落幕 ADV 顺序、首通奖励与落幕回顾；普通溶洞直接显示结果，确认“返回洋馆”后结算。
- 带回道具与剩余战备分别展示。出发时携带的补给不会被算成本趟获得的战利品。
- 确认沿用正式结算事务并返回洋馆。提交期间禁用，失败可重试；已入账结果可重新打开，重开页面不再次发奖。三种结果都能从已保存终局恢复。

## 规则与存档

普通房间掉落在房间完成后产生，清层入袋；内容21按战斗房间的来源表抽取，原固定表仍可在战斗／事件房间发放。撤离保留已入袋道具，失败仅保留一半，本层未入袋道具遗失。终局 `lootLedger` 保留入袋与未入袋清单，`returnedLoot` 是实际入库清单；读取器对照完成房间和层记录验证，表驱动路线再核验 `lootProof` 的种子与完成房间。完整恢复及允许的存档复制保留遗失记录。

当前默认减半按独立物品实例（批次）计算：总实例数向下取半，各物品种类先取半，余数按拾取顺序分配。保持实例 ID，不复制或拆分一个实例。教程十二枚旧十字币仍是一批，教程完全沿用原有固定奖励和重试规则。

兼容边界：仅配置了普通房间固定掉落或来源表的路线启用道具终局字段。内容20旧档保留固定溶洞掉落，更早没有普通掉落的档案不增加字段；不改写旧数值与存档结构。出口本身不能配置奖励。旧 schema 1 裂隙兼容页和回忆战保留自身流程。

## 普通内容接入

普通新档25和AIRP26继承内容21的正式掉落表：两处目的地、三条路线，共12种常规战利品与4种鉴定品。来源表按开场绑定槽位抽取，召唤／重复击杀不增加抽取；途中20%获得鉴定品，末战保证一件，同趟排除重复。普通定义与教程独立，通知、LOG、通透结算与SHOP共用真实实例，普通鉴定收费300 G。同房间同物通知聚合数量，不同物或不同房间向下叠加；已知同类物在SHOP聚合并可按数量出售。

冻结的内容20保留五次固定溶洞掉落：螺壳×2、礁蟹硬壳×2、待鉴定铜环×1；内容17／18／19保留原教程物件。实验页的22件样品未进入正式内容。

三类纹记、共享五档品质及未知品质的组件能力保留；本批物件使用凡品／精良两档，鉴定前隐藏真实品质与身份。物件信息读取共享presentation元数据；完整弩簧、失效钟件、完整钟轮、旧银餐巾夹、报时钟音簧已更换独立Game-Icons图标，来源及授权见[素材清单](../../../assets/icons/items/loot/ATTRIBUTION.md)。未知圆盒仍使用封闭图标。战备拾取转为可使用补给的内容契约尚未添加，概率不启用；不改公款。

## 验收方式

按用户要求不启动浏览器、不录屏、不做视觉验收。覆盖真实命令的三种终局、拾取与入袋、重复结算、完整存档恢复、遗失记录防篡改、主页面绑定和通关剧情顺序；另外运行教程回归、类型检查和正式构建。

主应用初次接入时通过 58 项相关 Vitest 用例、8 项构建／样式契约用例、主应用类型检查、模块边界检查、`build:game` 与构建产物检查。失败用例另外使用同层两场战斗，确认第一场所得尚未入袋的道具在第二场失败后遗失。

初次接入时遗留的tooling类型错误已于09-25收口：补充原生工具函数契约、空值检查与Vite原始文本导入类型，core／application／app／tooling四层类型检查均通过。未重跑全套旧入场编排测试，当前主流程顺序由绑定测试验证。
