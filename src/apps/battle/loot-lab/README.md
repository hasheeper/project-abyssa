# 远征收获独立预览

2026-09-24：通透结算、收获条目、悬浮详情和 LOG 已提升为 [正式共享组件](../loot/README.md)，并接入主应用。此目录仍只负责独立测试、样本道具和 F2 调试；正式页面不引用样本生成器。


入口：`npm run dev:battle-loot` → http://127.0.0.1:5194/battle-loot.html 。构建：`npm run build:battle-loot`。

此入口独立加载。导航依赖中的正式游戏页面仍随构建提供，但实验页自身不被重定向到不存在的 `#/battle-loot` 正式路由；无页面归属标记的独立实验页保留原本的样式层叠，正式游戏仍按页面隔离样式。

## 当前行为

- 使用正式庄园规则、掷骰、固定、重掷、出手、敌方行动与房间推进。在独立内存档中运行，刷新或结算返回即可重开，不读写正式存档。
- 击败敌人时使用通用 SceneFeedback 叠加显示资金与道具。资金来自正式赏金；道具为暂定的 UI 样本，未修改普通关卡的生产掉落表。
- LOG 只对“未入袋 / 已入袋”提供折叠。组名后紧跟件数，规则位于下一行；金额和 SVG 开合箭头各自对齐。内部是图标、名称、数量自然换行的单行收获条目，没有物品槽、空位、容量限制或二级展开。大量条目可滚动查看。
- 类型通过图标角上的纹记区分：战备道具为盾纹、常规战利品为袋印、鉴定品为问号封签。品质沿用共享五档（凡品、精良、珍品、秘宝、神话），仅为物品图标点色；名称、数量和面板保持主题配色。不在条目下重复类型或品质文字。
- 道具悬停、键盘聚焦或触摸点击显示浮层说明：名称、数量、完整类型、品质和描述。浮层为实色底与单层边缘，不使用渐变或额外数量区。浮层在当前账本／模态内定位并避开边缘，不受道具列表裁切，点击详情不会触发账本外部关闭；Escape、滚动、移出或点击外部关闭。
- 鉴定品在展示数据中只持有 `unknown`，不携带真实品质；列表保持中性配色，详情显示“品质未知”，获得道具通知也不将未知品质归为凡品。
- 清层时资金按正式引擎结算，道具一起入袋。撤退保留已入袋收获；失败丢弃本层并保留一半已入袋收获；通关全带回。通关自动入账后从终局记录生成结算。
- 2026-09-22 按用户要求恢复此前通透结算，撤下实体面板与 SVG 占位，以此继续功能闭环。使用共享 UiModal 和战斗皮肤，直接显示收获和遗失明细，保留一个返回按钮。地点由调用方传入；资金动画只展示已结算记录，一次操作可补齐演出，减弱动态直接完成。
- F2 打开调试工具：混合收获、22 种道具（含三类与五档品质）、叠加提示、三个结算结果，以及无收获、单件道具、地点、皮肤和减弱动态预览。调试样本不改变真实战斗状态；继续真实行动后退出样本展示。

## 边界

此预览使用内容19的内存档及独立样本道具，不写入正式背包、商店出售或鉴定。正式主应用已接入真实掉落与交易，见[正式掉落表](../../../../docs/design/ORDINARY_DUNGEON_DROPS.md)。教程不套普通远征减半，公款不在范围内；战备样本不直接加入本趟可使用的补给。

`previewHalfItems` 是独立预览策略：保留已入袋总件数的一半（向下取整），各类先减半，余数按首次获得顺序分配。正式规则以游戏核心与掉落合同为准，不由此函数决定。掉落不会重置携带补给，也不会把出征时已有道具算成此次收获。

## 视觉参考与取舍

当前采用通透结算。被否定的实体面板方向、四张SVG占位及接线已移除，不再作为美术待办；早期讨论稿已在文档清理时移出仓库。

参照 [Darkest Dungeon HUD](https://www.ign.com/wikis/darkest-dungeon/HUD) 和 [Pillars of Eternity Inventory](https://pillarsofeternity.fandom.com/wiki/Inventory) 的游戏内信息层级与材质一致性。根据项目反馈，弃用仓库式方格与固定容量的表现，改为可收起的收获记录；只沿用 ABYSSA 当前战斗皮肤、字体、图标和反馈组件，不引入第三方截图素材。

## 预览测试与历史结果

- 2026-09-22 通透回退：结算与收获模型共 22 项、入口／样式契约 8 项通过；应用与工具类型检查、入口检查、独立构建通过。浏览器确认独立入口正常加载、通关结算恢复通透布局；构建同时保留实验页与正式游戏兼容入口。

- `loot-model.test.ts`：收获去重、入袋、三个结果、数量守恒、替换减半策略。
- `derive-loot.test.ts`：当前正式引擎从新开普通远征跑到通关/撤退/失败，逐步核对道具总量与资金，并验证撤回会删除掉落。
- 浏览器手动检查：掷骰→固定柯萝萝→击败候席客→LOG 显示 300 G 与一件道具；22 种条目换行、滚动和单级折叠；三类纹记、五档点色、未知品质；账本和结算内的悬浮详情；三种结算与回到独立战斗。
- 早期接线通过：应用类型检查、独立入口构建、收获模型14项、通用反馈10项，以及正式引擎投影集成4项。
- 早期接线曾发现：共享`ManorBattleBinding.test.tsx`的6项入场编排测试超时或阶段断言失败，当时未隔离基线。这里保留历史结果，不把它当作当前运行结论；最新专项范围见[项目状态](../../../../docs/DESIGN_DECISIONS_AND_CURRENT_STATUS.md)。
