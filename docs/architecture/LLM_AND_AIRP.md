# LLM 与 AIRP：当前运行链与权限

更新：2026-09-25。正式AIRP新档为内容28，普通默认新档27不要求模型在线。旧内容10／18／19保留各自冻结协议，不能用它们说明当前正式调用链。

## 1. 入口与模型职责

| 入口 | 内容 | 当前用途 |
| --- | --- | --- |
| 普通新游戏 | 27 | 固定开场、离线叙事、普通战斗／商店／生产 |
| AIRP 游玩（总管理起点） | 28 | 正式日度／副本调度与洋馆／战斗叙事，带商店和设施 |
| AIRP快速体验 | 18 | 早期静态药箱两场样本，兼容保留 |
| 显式旧在线档 | 10 | 通过相邻rp-style-lab服务的药箱样本 |

正式新洋馆任务使用 `lowContextVersion: 21`、`lowReadVersion: 6`，见[useDirector](../../src/game-client/airp-director/useDirector.ts)。当前场景每轮为 **正文 → 中文封装 → 场景GM评估**；场景GM决定结束或给下一轮范围，续轮继承玩家已选回应和已读内容。没有恢复旧的Sol写前正文大纲流程。

三槽共用[aiConfiguration](../../src/game-runtime/airp-configuration.ts)：GM负责日度／副本／场景判断，正文槽负责创作，辅助槽负责中文封装与独立结算。默认模型ID及每槽端点以[生成配置](../../src/game-runtime/airp-generation.ts)和玩家设置为准，不在文档复制成另一套配置。

## 2. 当前正式闭环

```text
洋馆日度GM → 当日安排 → 人物场景及玩家选择 → 明确接单
→ 地图编队与副本GM计划 → 确认出征 → 真实战斗／事件节点
→ 取得任务物品与普通战利品 → 撤离／失败／通关
→ 回馆反馈 → 有实物才可交付 → 独立结算／记忆 → 后续日度GM
```

固定／自由事件共用每天一个重点、最多一个轻量场景的预算和64日主题黑名单，允许留白，不以拒绝或完成为由立即补满。地图、副本节点、回馆和人物面板消费同一正式进度。

正式28“安排今日”会配置六人剧情调度：四位队员＋玛丽埃塔＋魔王艾比希斯。`residentCast` 独立于战斗角色解锁，保存为可重放配置；旧目录摘要与已生成任务不变。旧28在下一次新安排的安全检查点接入，不重写已经接纳的日程。两人可以被选择，也可以整天不出场。

[生活双库](../../st/setting/airp_household_guidance.md)提供6条固定世界／人物锚点和14个可变情境。指导通过完整资料进入日度、场景与副本GM；没有新建固定剧情链或每日抽取配额。原有硬目标fixed卡与这些创作指导分开：GM采用指导时构思free卡，保留玩家决定、主题复核和实际结算边界。接入与咨询记录见[实施计划](../plans/2026-09-25-airp-household-cast.md)。

新副本计划冻结 `commissionRewardVersion: 1`；现有作者巡守必须各安排一件指定任务物品，挂在既定目标节点。GM可选择合法取得时点与发现方式，不能挪动作者约定层数、改名定价或发明装备。实际发放、入袋、丢失、持有和交付由规则层执行，见[实物奖励验收](../audits/2026-09-25-airp-commission-physical-rewards.md)。

同一新出征计划另启用 `appraisalPlanVersion: 1`。程序按实际掉落种子预演奇物位并冻结实例、品质、价格；GM收到缇比完整卡，为每个槽位一次写完外观、身份与商店台词。`appraisalItems`独立于委托奖励，不占叙事节点，也不新增调用。战斗才实际发物，回店成功鉴定才揭示身份；选中、鉴定、成交和回看均在SHOP小对话框播放。旧帧未启用则维持固定文案，详见[奇物接入](../audits/2026-09-25-gm-special-appraisal.md)。

## 3. 数据和写入权威

| 数据 | 谁决定 |
| --- | --- |
| HP、骰子、敌人、随机、路线准入、钱包、补给和普通掉落 | 核心规则＋应用事务 |
| 当日候选、节点安排、场景是否续轮 | GM提出；按来源、模板和有界协议校验后保存 |
| AIRP奇物身份与商店台词 | 副本GM回填已冻结槽位；程序决定实例、掉落、品质、报价和交易 |
| 角色正文与表现 | 正文生成；辅助封装为阅读结构，保留原稿与诊断 |
| 好感／活动状态、有限记忆纠正与待办收束 | 独立结算提出允许范围内的变更，应用校验再入账 |
| 玩家决定与实际阅读 | 玩家操作＋正式游标／选择事实，不从模型候选推断 |

未读候选不成为已读记忆。结算不是又写一篇正文，封装也不是借机润色。原始响应、失败帧、冻结输入和已读全文保留，后续版本只作用于新帧；不把旧响应强行解释为成功。

GM最小职责与排期边界见[定稿](../plans/2026-09-24-airp-gm-demo-scope.md)，完整事件设计见[事件流合同](../plans/2026-09-23-airp-director-and-event-flow.md)。通用Agent工具、全量旧账重判和任意场景重排尚未开放。

## 4. 资料、文风与内容验收

正式Low从[low-r8-source](../../src/content/presentation/airp/low-r8-source.ts)装配全文资料与r8预设。通用资料清单见[generation-documents](../../src/content/presentation/airp/generation-documents.ts)，它直接导入角色／世界资料及两份Markdown规范；删除或改写这些文件会影响运行内容和哈希。

内容28的新角色资料由[household-documents](../../src/content/presentation/airp/household-documents.ts)单独装配，旧四人资料清单保留。两份原人设、双库指导和每个生成帧都校验摘要；修改运行指导后必须同步该清单中的SHA。GM拥有全局资料不代表NPC互相知情，正文和结算仍按实际在场与已读来源筛选。

[r8冻结样本](../baselines/airp-style-r8/README.md)仅有“文风暂定接受”的授权，因果、人物与双语协议不是已验收。context21在新帧上修补人物反刻板条款、首轮续谈计划和无计划时的篇幅锚点，原件未覆盖。实际表现待真实文本验收，见[调整证据](../audits/2026-09-25-airp-dialogue-v21.md)。

固定序幕、首晨、教学和SHOP首访使用作者审定数据，不经过在线生成。普通鉴定仍为作者身份与台词；正式AIRP启用的新奇物使用出征GM冻结的实例文案，商店不临时请求模型。不能把这一限定入口推导成全商店在线角色扮演或自由生成装备。

## 5. 连接、后台与恢复

连接只在[设置→Model](AIRP_CONNECTION_SETTINGS.md)编辑和保存。浏览器直连要求服务商支持实际页面Origin；静态站不代为代理。保存连接不会发起模型请求，Key不进入游戏存档和公开报告。

生成状态、已读游标、节点选择和结算分别落盘。页面收起后轻量后台宿主可继续保存已启动任务；切换存档身份会取消旧调用。刷新恢复已保存进度，待保存输出和真实失败保留显式恢复入口，不无条件重发付费请求。

进入正式AVG后锁定阅读，首句也持久化；刷新回到当前阅读。旧“出征安排”通知在计划开始后过期，点击前再次核验当前存档，活动远征不能借侧栏返回MAP。表现与交互详见[生成反馈与阅读恢复](AIRP_FLOW_AND_RECOVERY.md)。

存档以文本／结构池无损去重，持久化／导入上限仍8 MiB。普通27可按既有安全边界复制；正式AIRP28支持原身份备份恢复，不新增活动链跨身份副本。一次性的默认游戏库清理与读取旧格式能力分开，见[池化记录](../audits/2026-09-25-airp-save-pooling.md)。

- 旧内容10仍保留rp Session／Release协议，兼容至0.3.2；早期真实验收见[记录](../audits/2026-09-12-airp-032-acceptance.md)。不是当前正式AIRP的后端依赖，也不证明服务此刻在线。

- 原`llm/`作者工具已经退役；骰局的旧适配器默认关闭，独立RP／AVG演示不等于正式生成。
- 公网HTTPS、实际API跨域和更新回退未验收；真实文学质量、长程连续性和逐卡定稿仍在当前待办。
- 用户所报“缺少正常结束标记”仍需对应调用日志定位；滚轮监听警告和旧错误残留已修，但不能据此认定该响应错误来自同一原因。
