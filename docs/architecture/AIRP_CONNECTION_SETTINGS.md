## 使用

API 地址、Key、模型 ID、独立槽位连接和采样参数统一在「设置 → Model」填写或导入。GM（日度／副本）、正文、中文封装／结算和静态试读共用同一个 `aiConfiguration`；不在生成窗口复制表单。「前往设置」打开现有全屏设置，关闭后返回原场景，不导航刷新、不取消请求、不修改已冻结任务。

填写或修改连接后点击「保存」。未保存的编辑标为「有未保存修改」，仅本次页面有效；保存成功显示「已保存」。刷新／下次打开自动恢复，不需要口令、确认口令或锁定／解锁，也不会自动请求模型。导入文件后仍须点击保存。「保存说明」内可以明确删除本机连接，不影响游戏存档。

正式设置页左栏是公共地址与 Key，右栏是Ⅰ GM／Ⅱ 正文／Ⅲ 辅助。保存与返回共用原切角按钮、同置页脚，不随表单滚走；输入框统一透明底细线，不再放深色保存卡或空置预设说明栏。[ABYSSA 当前机制与游戏闭环总览](../GAME_SYSTEMS_AND_CONTENT_SPEC.md)。

三槽默认共用公共连接；各槽可以显式设置独立连接。切换连接不会静默替换旧任务冻结的模型／端点，试读续跑也会校验端点，不能将新连接的 Key 发给另一旧端点。

## 存储边界

- 独立 IndexedDB `abyssa-ai-connection` 保存连接地址、Key、启用的独立连接、模型 ID 和参数；不保存预设或角色卡，不混入游戏存档数据库。
- AES-256-GCM，每次保存生成随机96位 IV和浏览器管理的不可导出 CryptoKey。密钥和密文同一事务原子替换；不写明文 localStorage，不使用内置固定密钥。
- 自动恢复依赖浏览器保存的 CryptoKey；**同源脚本可以使用它解密**，不是防御 XSS、恶意扩展或被控制浏览器的保险库。不同浏览器／Origin不共享；清除站点数据会清掉连接。
- 仅在 HTTPS 或可信本机环境使用 WebCrypto。存储／加密失败明确显示未保存，不回退明文；旧记录保留。加载期间的新输入不被自动恢复覆盖，保存期间的新编辑仍标为未保存。
- 旧口令版 `localStorage/abyssa.ai-connection.v1` 无法无口令解密。检测到后只提示重新填写或导入并保存一次，不再提供口令交互，不擅自删除旧密文；新格式优先。
- 原导入文件仍是用户自己的明文文件，本次不读取、改写或上传。浏览器保存不会加密磁盘源文件。
- **游戏冻结快照仍保存非密钥模型配置（含端点）以支持重放与连接校验**；不修改旧请求哈希。完整存档／完整诊断不是保密包，分享前仍须检查；Key误填防护的修复和历史边界见本页开头。

## 验收边界

使用合成凭据验证显式保存、自动恢复、共享／独立连接、异步编辑不被覆盖、失败可重试、删除隔离、设置唯一入口。不改文学提示词，不读真实私有配置，不执行游戏模型调用，不修改玩家档案，不发布。按用户要求不录屏、不做截图视觉验收。
