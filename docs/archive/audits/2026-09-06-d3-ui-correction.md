# D3 界面接入纠偏 · 2026-09-06

用户定稿边界：**样式不改，内容必须改成庄园。** 不能另造战斗页，也不能为了恢复样式而退回旧裂隙内容或关闭庄园入口。

## 当前实现

- 原战斗 JSX 提取为 `ExpeditionBattleSurface`，旧规则与庄园共用这一份界面。角色立绘卡、饰品槽、英文铭牌、盾心条、意图线、机械倍率账本、战斗日志、骰池、外置撤回按钮和红线边框保留。
- `ExpeditionDiceTray` 复用原骰盘布局；正式骰面只输入各自的点数、阵营、铭文、动作和沉睡状态。沿用原随机掷骰时长、转动角度、归位 CSS 和战斗特效阶段，仅回执里的实际掷骰者播放转动。
- `ManorBattleBinding` 只负责内容与命令接线：候席客、执盘侍者、缝补女佣、落幕管家与迎客门厅／服务走廊使用已归位的仓库素材；最大生命、意图、目标与行动取正式规则。
- 迎宾簿、遗物整理、携带配给、走廊继续、第三层撤离、最终结算全部复用原弹层和按钮。没有新增第二套战斗 CSS。
- 地图继续使用原编队、委托侧板与地标结构；中央入口换成旧庄园图标和内容。新建档采用正式庄园三层包，默认五人、四种配给。原裂隙档仍用原版本恢复，不静默改写已有进度。
- 移除先前“D3 暂未开放”占位。失败的另版界面只保存在忽略目录中，不进入玩家构建。

## 验证与证据

已经通过实际构建，在独立随机端口完成：新建档 → 地图出发 → 三层战斗 → 两个事件 → 落幕管家 → 主动撤离 → 单次回馆结算 → 刷新 → 第二次出征。该次实测执行 85 个战斗操作、最终带回 67G、无页面运行异常；这是一条实测记录，不作为平衡结论。

代码检查已完成：core／application／app／tooling 四组类型检查通过；模块边界、18 个页面入口、产物检查和纯核心导入通过；构建测试 66 项通过。全量单元测试中 862 项通过，一条真实三层流程用例超过 30 秒。随后移除配给查询的重复命令模拟，并把整趟流程用例的测试预算调整为 60 秒；包含该流程、四种导出导入状态及事务回归的 22 项定向复测全部通过，流程实际耗时约 10.1 秒。此测试耗时不代表浏览器帧率结论。

最终浏览器回归 **40 项全部通过**：原角色档案、旧档出征结算与中断恢复、根路径和 `/abyssa/` 的新建庄园档、原组件布局与刷新后的骰面恢复。日志见 `shared-ui-smoke.log`；最新画面见 `manor-original-layout-final.png`。本记录不把前面的回滚检查数字当作本次接入验收。

## D3 总体验收边界

庄园内容已经接入原界面，并通过正常流程实机验证。D3 总计划里的完整数值矩阵、五趟人工试玩、全部故障注入与性能对照尚需独立收齐，不能据此写成整个 D3 已全量验收。D4 的完整五层、千金 Boss、首通接管，以及 D5 的回忆和玛丽埃塔亲征继续按原计划推进。
