# D5-E：成长与装备实施记录

## 1. 玩家流程

| 环节 | 本包行为 |
| --- | --- |
| 十项成长 | 洋馆原归来面板列出符合条件的片段。尤／艾／柯／诺各Lv.2、Lv.3；玛开放亲征后通过维护归来取得两级成长 |
| 资格 | 根据已结算的本人参战名单、三层撤离／五层通关推导。Lv.3需要已接管庄园，且资格旅程在本人Lv.2领取后才出发；失败和未参战不能代领 |
| 对白与奖励 | 每段6句，复用原AdvStage与阅读栏。稍后继续保留游标，刷新恢复；跳过只到末句，“完成片段”才同事务记录事件完成与成长／赠物 |
| 团队里程碑 | 第二名角色实际领Lv.3时，凯尔第4面「护卫」变金一次，并展示《这边交给我》。短片段只读，不增加领取门槛；没有额外装备／晶石 |
| 整备赠物 | 一次合法归来后，玛丽埃塔交付备用短刃、应急药囊各一件，进入未装备库存。结果提供“前往骰装”，不自动分配 |
| 装卸与转交 | 角色页原“骰装→通用槽→管理通用装备”进入原风格模态；可以装备、卸下或直接转交空槽角色。已有物品时提示先卸下，不隐式替换 |
| 装备作用 | 尤／艾／柯／诺适用；全部原生空面改为攻1／治1。点数、品质、花色、苏醒状态不变。凯尔和玛无原生空面，显示不适用 |
| 出征与归来 | 普通远征／回忆期间冻结馆内改装和领奖；参战装备预留给当前run，归来返还同一instanceId，未参战者的物品保持原归属 |
| 查询与记事 | 原角色概要／六面／铭约、地图编队及战斗读取相同配置。记事记录真实成长、赠物和团队里程碑；已完成片段回顾不写新事实 |

原五枚好感晶石、三格私约、三装备槽保留。没有引入专武／小件、Lv.4／5、商店或新的成长货币。

## 2. 实现边界

- [应用命令](../../../src/game-application/versions/d5-service.ts)接入成长／赠物故事与`equipment-moved`。最终结果继续走expectedHead、clientRequestId、CAS与幂等回执；页面回调不能直接修改进度或库存。
- [资格函数](../../../src/game-core/session/d5-progress.ts)`d5EventEligibility`由核心重放和[runtime查询](../../../src/game-runtime/d5-views.ts)共用。查询提供候选、持久游标、库存、适用角色和空闲槽目标；提交仍重新校验。
- [成长阅读](../../../src/game-client/GrowthStory.tsx)、[事件入口](../../../src/game-client/GrowthEvents.tsx)使用既有AdvStage、阅读栏、按钮和洋馆提示；脚本位于[展示内容](../../../src/content/presentation/growth-stories.ts)。没有新增CSS、改背景／立绘或套战斗框。
- [角色页](../../../src/apps/character-status/App.tsx)保留只读reader。[有限装备会话](../../../src/game-client/use-equipment-session.ts)只允许三类装备命令，不恢复敌方队列或其他故事；允许恢复自身丢失的装备回执。未确认的其他操作保留原请求，并阻止装备操作覆盖它。
- [装备面板](../../../src/game-client/EquipmentEditor.tsx)复用RpgModal，放在Stage内、角色主面板外，保持缩放与焦点循环，避免被原检查栏裁切。共享DiceLoadoutPanel只增加通用槽的可选操作入口，旧版本仍只读。
- [人物记事](../../../src/game-application/character-history.ts)以已提交事实与实际grant为来源，展示标题／正文在character-presentation映射；没有LLM或rp-style-lab依赖。

## 3. 实际可达路径与故障验证

[游玩夹具](../../../src/game-application/testing/d5-growth-fixture.ts)从公开命令创建新v4档，完整执行庄园首通、回忆失败／重试／胜利、当下兑现，再领取成长。没有修改HP、骰面、RNG或伪造结算凭证：

1. 首通与回忆兑现后，领取赠物及四位勇者Lv.2。
2. 短刃装备艾洛拉并原子转交柯萝萝，药囊交给诺玛。
3. 凯尔／尤／艾／柯／玛参加第一趟维护并从三层撤离。尤／艾／柯领Lv.3，玛领Lv.2；第二人Lv.3派生凯尔里程碑。
4. 凯尔／尤／艾／诺／玛参加第二趟维护并三层撤离。诺和玛领Lv.3。
5. 卸下两件物品，核对仍为赠物创建的原实例。

定向故障覆盖成长、赠物、团队里程碑和转交的提交前中断、提交后回执丢失、同请求重放、不同连接旧head竞争及完整记录重验。边界用例覆盖旧旅程不能充当Lv.3新旅程、重复赠物、占槽／无空面目标与活动run冻结。
