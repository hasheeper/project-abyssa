# P1-D 推进、间歇与现有事件内嵌：实施记录

日期：2026-09-07。依据：[主计划 v0.6](../snapshots/BATTLE_UI_AND_EVENT_FLOW_OPTIMIZATION_PLAN_BEFORE_CONSOLIDATION.md) §2.5、§5。用户要求先读实际规划，推进本包，并将多人骰子规则与存档单独补齐。

## 实施结果

- `ManorBattleBinding.tsx` 只保留 finished / wipe 终局弹窗。间歇、迎宾簿、遗物整理、席位记录、已提交结果、第三层出口都显示在原敌方舞台内。
- `ManorJourneyPanel.tsx` 展示房间文本与结果；`ManorJourneyActions` 复用原 ActionDock / DiceActionButton，提供 read/attempt/skip、继续前进及退出/深入。整理直接点选下方存活伙伴，支持 Enter/Space；费用、骰面和强弱结果仍来自原查询/命令。
- `ExpeditionBattleSurface.tsx` 增加独立 CG 图层；`useManorBattlePresentation.ts` 在推进命令已提交后播放 680ms 小幅上下步行，再用 280ms 抵达过渡切换事件内容；敌人仍使用原登场演出。位移峰值为设计尺寸 +3/−2px，不移动舞台本身。
- 普通进入事件房可能返回空 events，因此过渡以成功提交的 `advance-room` / `choose-exit(continue)` 为边界，不能仅监听战斗事件列表。
- 同步 queue 锁阻止双击重发；动画等待检查 current head。提交失败、旧 head 冲突、恢复重放、隐藏标签与低动效不补播走路。刷新直接显示已提交节点。
- `expedition-journey.css` 限定本包舞台内的文本/结果/选择样式；场景文字用暗渐变托底，不新增模态板。初次视觉检查发现操作按钮挤到道具菱形，已按原按钮宽度和坞内居中范围修正。
- 删除旧事件/间歇弹窗中的逐层结算算式，保持用户此前“不要把地牢收益解释得过细”的要求。终局的带回/遗失总额继续保留。

## 保留的规则和样式

没有改 `game-core`、application 结算或存档解析器。旧 v2/v3/v4 仍使用单人独立事件 RNG；强弱判定及 2G 成本/4G 成功奖励照旧。事件结算到层末时，GameSession 仍执行权威自动入袋，不能用散金清零判断为额外扣费。

角色卡保持原尺寸、骰子保持原动画、倍率仪表和日志保持右侧原布局、道具坞保持七槽；顶栏红线、雾气画布与其他皮肤框架不重画。扎营只显示禁用占位。角色卡自动折叠、多人选骰、配图占位属于 P2，没有混入本包。

## 补正：事件掷骰与判定演出（同日）

用户指出“只选了个人，没有看到 roll 和判断结算”。核查确认上轮只接通了事件输入/结果；演出队列监听战斗 `dice-rolled`，没有处理旧事件的 `event-resolved`，确实漏了中间过程。

现已补齐：

- 整理按钮明确为 **ROLL**。选人后点击，仍提交原 `choose-event(attempt)`；成功保存后，只有该伙伴原槽位的骰子使用原物理滚动样式转动，其他四颗不动。
- 原滚动时长0.85–1.30秒，落定缓冲120ms，然后停面核对620ms，最后揭晓结果并保留700ms演出收尾。结果持续展示至玩家推进，不是一闪而过。
- 从已提交结果的 actorId/faceId 找到真实面序。结果区显示强/弱/失败、行动与命数是否通过及花费/获得；只展示core已裁决的method，不在React重新判定。
- 原右栏结果台词、收益和日志延后到揭晓，避免骰子尚未停稳就泄露成功或失败。落定骰面一直保留，刷新仍读取同一结果。
- 低动效直接显示结果；隐藏、刷新与保存失败不会额外重掷、扣费或重播。没有修改旧事件规则或存档字段。

验证：5项整理专项测试通过（包括v4真实结果、仅单骰旋转、他骰不动、停面后才显示结果、刷新/隐藏/低动效、失败不演出）；54项原战斗/庄园交互回归通过。类型检查和模块边界检查通过。实际1600×900强保全与1280×720失败流程已截图并录屏，材料在 `dist/reports/battle-event-roll/`。额外光晕导致骰面发糊的问题已在视觉复核中移除。

## 补充：遇敌缩放与白闪（同日）

按用户最新反馈，遭遇镜头需要放大幅度更大、柔和回旋，而不是急促跳两下。已提交的 `advance-room` 或 `choose-exit(continue)` 若进入战斗，680ms步行后接1200ms连续缩放：1→1.42倍推近、回收至1.10倍、再推至1.62倍，配合小于1.3°的轻微反向转动；曲线在转折处自然减速。随后接240ms快速双闪（60ms亮→60ms暗→120ms亮）；回暗时保持镜头末态，第二闪覆盖后才切换新房间并挂载敌人，最后用280ms连续曲线退白。普通事件房保持原280ms抵达。时长由 `presentation/journey-motion.ts` 同时提供给队列和CSS。

只有独立CG层运动；白闪限制在敌方视口，角色、骰子、操作坞、顶栏、雾气画布不位移。镜头运动及双闪期间复用骰子演出的雾气8fps绘制策略，保持原shader、分辨率和时钟，为前景效果让出绘制时间。没有改游戏规则、RNG或存档协议。刷新/隐藏取消演出并显示已提交战斗；低动效直接抵达；保存失败不演出。控制锁保持到退白结束。

接线初版21项流程测试通过；本次手感修订重新通过6项遭遇专项（v4普通推进、第三层深入、刷新/隐藏、低动效、失败）及4项雾气测试。`typecheck:app`、`build:game`、`check:output -- game` 通过。

1600×900及1280×720真实点击录屏与逐帧几何检查通过：缩放阶段超过1.05秒，连续采样超过20种中间变换，峰值超过1.55倍，存在明确回缩与轻微反向转动；实测双闪顺序为白→暗→白，回暗时镜头保持1.62倍，第二闪结束前敌人数量为0；顶栏、五张角色卡、操作坞及雾气画布位置不变。最新材料位于 `dist/reports/battle-encounter-double-flash/`，包含 `verification.json`、两份录屏、关键帧拼图及 `encounter-preview.mp4`。
