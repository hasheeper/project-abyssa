## 3. 存档模型的实测修正

完整回忆归档测试发现，若每个战斗fact携带前后整份状态及撤回栈，第69份事实附近就会超过既有JSON复杂度上限。没有放宽全局限制。当前战斗fact改为：

```text
runRef + operation + beforeDigest + afterDigest + events + retracts
```

回忆起点由固定模板和已记录seed恢复；后续状态由前一已验证结果与命令重放得到。普通遭遇入口可携带一次严格校验的checkpoint，后续不得反复插入checkpoint跳过前史。摘要仅用于核对，不能单独授权结果。

独立回执可携带完整单次转换证明，归档内的战斗事实保持紧凑。资格投影在同一段连续战斗校验中复用，避免每步重复推导未变化的当下进度；每条战斗命令只重放一次。

这替代B阶段“一事务固定一事实”的暂定限制：普通进度／非终局战斗仍一份；历史终局事务必须有**战斗事实＋memory-ended进度证据**两份，绑定同一revision与顺序fact ID。只有完成两份的记录才能进入history-complete／failed。回执、当前snapshot和真实终局必须一致。

撤回分组从已验证命令链推导，不接受任意retraction数组，也不撤成长、赠物或篇章凭证。回忆和普通远征事实仍分别标记memory／adventure；没有新增LLM调用。
