# D4 五层庄园实施与验证记录

日期：2026-09-06。对应 [D4 实施计划](../plans/DEMO_D4_OLD_MANOR_PLAN.md)。

状态：**工程闭环与本轮自动验证完成；关键救离美术、人工试玩及完整发布验收待补。D5 未开始。**

## 实施范围

完整庄园使用 `abyssa.demo@1 / rulesVersion 3`，存档、请求、回执、归档、事实均为第三版。新建档切入完整包；原三层 `abyssa.demo.manor-segment` 与 legacy 原档继续按自己的版本读取，不做隐式迁移。

游戏闭环：初始五人出征 → 前三层逐层入袋 → 第三层撤离或深入 → 第四层三客一佣与空席核对 → 第五层千金 → 解线终局自动结算 → 五段可恢复剧情 → 回馆 → 维护委托。全灭和第三层撤离各保留原结算规则。

千金采用 HP18、18G 普通赏金，初始两客、最多三客、整场最多补六客；举杯与补席交替。补出的候席客没有赏金，当轮不行动。伤害用同一核心公式读取当前宾客，独立保留格挡和威压修正。定身保持动作游标，目标倒下不转移攻击。终击按完整动作／铭约批次收尾，余客解除退场，千金不播放通用斩杀效果。

首通奖励20G单独入账，不参与层倍率。五层房间／战胜证据、结算终局、接管凭证和奖励事实互相校验。普通收益、剩余物品归还、时间推进、接管及首次奖励进入同一持久事务。剧情游标不控制奖励；继续、跳过、刷新和回顾不改变资金与时间。

维护路线没有管家和千金，也不重复接管。首通仅开放维护并建立回忆前置；D5 回忆战、玛亲征、重排铭约、成长及装备获取未实施。

## 结构与样式

v3 复用现有 Demo 引擎、应用服务和存储事务，在版本边界使用严格字段校验；新增 `contracts/manor.ts`、`rules/v3/manor.ts`、`session/manor-progression.ts`、`versions/manor-history.ts` 与独立完整内容装配。没有复制第二套角色规则／战斗 UI，也没有接入 LLM 或 rp-style-lab。

查询中的 `version:2` 仍表示既有 Demo 展示 DTO 的格式；发命令使用 record 的真实 schema/protocol，不能拿展示 DTO 版本作为协议版本。

继续使用 `ExpeditionBattleSurface`、原骰盘、红线边框、雾效、人物卡、意图线、倍率账本及事件弹层。角色页好感晶石和布局保留。703项样式／素材／关键表现文件核对中，701项字节不变。另两项是 `EnemyMist.tsx` 的前景绘制预算和 `ExpeditionBattleSurface.tsx` 的投骰状态接线；全部CSS、素材、骰子动画及归位时序保持原值。千金的素材容器仅增加等比 contain 约束，避免横图被压窄。

## 性能与读取边界

CPU采样发现同一提交记录在查询和续步中反复完整校验。现由 registry 对外部数据校验后返回自己的深冻结副本，后续查询仅复用该副本；可变输入、调用方自行冻结的对象和新存储读取仍走严格校验。查询缓存改为使用验证后身份，避免外部对象改坏后沿用旧结果；命令分流不再先做一遍与服务相同的完整历史校验。新增回归覆盖嵌套篡改、外部对象改坏、浅冻结伪装和损坏存储拒绝。

未保留没有明确收益的 fact-ID 全局缓存。读取优化降低了校验开销，但满席重掷仍出现绘制退化；进一步的浏览器 trace 显示 GPU／图层合成繁忙。静止满席的8秒诊断约17.6ms；关闭雾绘制后，30秒满席重掷约17.4ms。降低画布分辨率未改善，因此没有采用。

最终保留原640宽上限、原shader、颜色、雾形与24Hz流动时钟；仅在3D投骰期间每三个时钟绘制一次（8fps），投骰结束恢复24fps，同一 renderer 持续使用。雾的时间仍连续推进，不因绘制降频减慢流动。现有隐藏暂停、静态降动效及无WebGL回退保留，骰子与意图线的既有动画不改。正式构建（`build-release-4.log`）的30秒对照如下，原始数据见 `focused-performance.json`／`focused-ui-4.log`。固定骰均未进入旋转状态，测试没有页面异常。

| --- | --- | --- | --- | --- | --- |
| 首层门厅 | 17.7ms | 0 | 104ms | 9.37MB | 34 |

环境：Apple M2／8GB，Chromium151，ANGLE Metal，1600×900、DPR1。初轮对照出现17.6／50ms，读取优化后出现17.6／33.2ms；单场景采样也有波动，不能把每次差值都归因于一项改动。保留所有日志、CPU profile与GPU trace，最终只按实际构建记录报告结论。
