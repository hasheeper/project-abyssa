# 庄园三类战斗、旧档续接与商店首版实施记录

> 2026-09-07。承接[闭环与商店接入审计](2026-09-07-game-loop-and-shop.md)及用户最后确认的三类战斗。本文记录实际采用的实现；完整阵容配平、美术补图与多人解谜仍分别跟踪。

## 1. 当前入口与闭环

正常新建档案使用 **schema／protocol／rules v4，contentVersion 3**。旧版 Catalog 保留；不会打开旧档就原地改变遭遇、配给或剧情。

| 模式 | 入口与门槛 | 内容与结果 |
| --- | --- | --- |
| 初战 | 地图；尚未完成第五层通关 | 五层，第三层落幕管家、第五层末席的提线千金；第三层撤离或全灭后仍为初战 |
| 回忆 | 玛丽埃塔角色页「记事」顶部；首通后可见，家宴未收束时先接续家宴 | 固定历史勇者五人对战刻仪兽；当下对白结束开放玛亲征；不领取普通金币、不推进当下时间、不消耗当下库存 |
| 维护 | 首通后地图直接进入，不要求先打回忆 | 五层，第三层可撤离、第五层刻仪兽；千金不再出现 |

记事入口支持开始、继续、失败／离开后重试、完成后重打和剧情回顾。入口复用原记事时间轴的重要条目：菱形节点、标题和行内操作置顶，与冒险经历共用织纹底和滚动区；仅回忆条目内部使用玛丽埃塔本人的战斗立绘作渐隐底图，按头部对齐放大并向条目底部渐隐；不增高条目，不覆盖下方记事背景。角色页左侧接回现有GameMenu，保留返回来处、菜单、洋馆、出征／回忆续接与档案导航。原角色页框饰和好感面板保留。标题继续游戏使用实际 `memory + attempt` 定位。玛的共用战斗立绘／色调映射已补齐。

回忆新题为**《停下来的钟声》**，场景为旧日钟廊。新增独立脚本与行ID；原《王座前的提线魔女》保留给旧内容档案回顾。升级后已取得的旧回忆资格与亲征开放继续有效，不要求补打一场才能保留成长。

## 2. 本轮采用的内容参数

以下是本次实施工作值，供后续玩家体感与完整阵容矩阵调整，并非追加世界观定稿。

| 刻仪兽 | HP | 行为 | 普通赏金 |
| --- | ---: | --- | ---: |
| 回忆 | 14 | 摆锤蓄势 → 钟鸣重击3，交替循环；单体，无护域、无侍偶 | 0 |
| 维护末层 | 16 | 同一蓄势／重击循环；单体 | 8G |

沿用仓库内 `clockwork-beast.png`，不安排额外玛丽埃塔本尊战。新回忆不复用旧本尊的邻接护域、重排敌群或收线止战台词。角色玛的重排铭约继续有效。

## 3. 商店首包

保留原杂货铺木柜、金属框、货架、数量控件、缇比和对话布局。正式页读Campaign钱包并提交真实购买命令；独立预览页仍为预览。

| 补给 | 每次出征／充能上限 | 价格 |
| --- | ---: | ---: |
| 食物 | 免费补满4 | 不出售 |
| 药水 | 免费补满2 | 不出售 |
| 护符 | 2 | 4G／次 |
| 圣水 | 2 | 3G／次 |
| 保养工具 | 1 | 6G／次 |
| 幸运符 | 1 | 8G／次 |
| 卦签 | 2 | 3G／次 |

每趟最多选四种。购买的是使用次数，库存与单趟均沿用原容量；没有另造无限囤货仓库。购买物资保留实例身份，出征预留、战斗消耗、返回余量、再次携带均使用实际剩余次数，不自动补满。0G仍能携带食物与药水出征。

常驻货架不设每日补货或随机价格。购买只用小队金币；活动旅程或故事期间不可买。请求包含商店ID、物品ID、数量、报价版本，不接受最终价格、余额或库存patch。扣款、到账、事实及回执同事务提交；重复请求只成交一次，过期head、缺钱、容量不足、报价变化不改资产。

**出售、鉴定、砍价继续后置**：当前没有可卖的正式掉落实例或未知物品鉴定链。免费配给及两件赠物均不可套现。缇比使用仓库内纸娃娃图层合成的本地立绘，不依赖外部图床。

## 4. 存档续接与二周目

标题「游戏档案」按资格显示操作：

- **复制并续接新内容**：v3或旧contentVersion 2的v4，在非活动旅程且家宴／回忆收束完成后使用。保留原档，创建新的saveId和epoch。金币、时间、首通、成长、装备位置、已开放角色均由原档证据承接。旧免费战术配给的实际余量一次转为有限库存，不补满、不补钱。
- **导入备份**：v4同版本复制，保留活动远征、回忆attempt、骰面／RNG、撤回和待兑现游标；旧回忆不会导入成新Boss。
- **新周目（仅继承回忆）**：原档完成回忆与当下兑现后开放。新档金币、成长、装备、接管全部重置，只保留可核验的章节来源；本周目仍须先通庄园，然后在记事入口选择「承接已通回忆」，进入当下对白，再开放玛亲征。

与原F提案中“全ID重定位表”的差异：实施采用**新档持有完整、不可变且重新验证的来源记录**。内部run／实例／奖励ID保留为各自存档作用域内的身份；新head、epoch、提交和事实ID独立。不会搜索替换任意字符串，也不接受只有来源摘要或章节flag的继承。源记录按自己的Catalog验证，新快照必须等于来源基线加本档事实的重放结果。

旧成长／章节与出征修订序号平移到本档revision 0之前，保留“领取Lv.2后必须重新出征”的先后关系。来源最多8层；归档仍受现有8MiB及JSON结构限制。源档不会被删除或覆盖。

## 5. 代码边界

- 内容：`src/content/gameplay/demo-v3/content.ts`；新回忆脚本：`src/content/presentation/clockwork-memory.ts`。
- Core：补给报价／预留、版本化来源、进度重放；不调用LLM。
- Application：购买、来源验证、复制／升级／周目、CAS与回执。
- Runtime：注册旧／新Catalog、默认创建、统一商店／出征／角色读取。
- 页面：记事顶部入口、原标题档案操作、原商店与地图接线。战斗／AVG／好感页面主体样式保留。

`rp-style-lab`没有加入资产、战斗、存档或解锁链。未来只能从已经提交的公开事实生成表现或对白，不能决定价格、扣款、掉落或胜负。
