## 3. 发布版本与 D4 旧档续接

### 3.1 推荐：显式第四版

本阶段新增 memory、篇章／成长凭证、装备归属和事实来源，超出 v3 的严格结构。推荐新包为 **`abyssa.demo@2 / rulesVersion:4`，schema／protocol／receipt／archive／fact 同步4**。保持1／2／3 reader、原内容、digest及行为。

此编号是规划选型；实现时集中注册，不把版本判断散落成 `不是1就是最新版`。展示 DTO 可以继续复用结构，但必须另带真实 contentRef、runRef 与 capabilities；UI不能把 DTO version 当命令协议号。

新版内容装配使用独立模块，例如 `src/content/gameplay/demo-v2/`。可复制已冻结内容数据再显式增量装配；不可改 `demo-v1/content.ts`／`manor.ts`／`manor-full.ts` 的已发布输出来给旧档加能力。公共纯函数抽取须有旧轨迹回归，不复制第二套引擎。

## 4. 玛丽埃塔铭约：D5-A机制卡摘要

### 4.1 触发条件与时机

采用“女仆长的领域／葫芦”命名，使用同一收束 hand 快照。**五个有效骰**满足3＋2、4＋1或5时触发；只有四个有效骰的四条不触发。条件独立命名为铭约匹配，现有 `fullHouse` 的严格经济含义不变。

| 冻结有效点数 | 是否触发 |
| --- | --- |
| 1,1,1,2,2 | 是 |
| 1,1,1,1,2 | 是 |
| 1,1,1,1,1 | 是 |
| 1,1,1,1（仅四骰） | 否 |
| 1,1,1,2,3 | 否 |

凯尔代点沿用已经选定的 hand.wildValue；不为玛单独重新求解。持约者资格沿D1冻结规则；沉眠不成牌，封锁与力竭继续排除资格。五个有效骰的成本必须真实保留。

采用顺序：**尤→柯→诺→艾→玛**。前四约保持不变；玛在伤害／治疗后读取实际存活敌阵，安排后续回合的邻接。已冻结的本轮 enemyOrder／cursor 不变，不追加攻击、不返还用过的骰子、不追溯本轮顺劈。

### 4.2 两阶参数与确定性选择

| 参数 | 初铭（Lv.1／2） | 现行（Lv.3） |
| --- | --- | --- |
| 可用相邻交换预算 | 最多1次 | 最多2次 |
| 目标 | 提高下一回合2＋1顺劈的清理机会 | 同目标，扩大可达排列集合 |
| 额外伤害／格挡 | 无 | 无 |
| 持续 | 当前遭遇内持续，直到死亡收拢、召唤或下一次合法重排 | 相同 |

自动策略“聚拢易斩者”：

1. 输入只含当前存活阵位、公开HP与意图。候选为预算内的相邻交换序列，包含原排列；按最短相邻交换距离去重。
2. 对每个候选计算 `K`：有向相邻对中，主目标HP≤2且邻目标HP≤1的数量，即原始2＋1顺劈能同时收掉两者的组合数。左右方向分别计入，不预测未来骰面。
3. 先最大化K；同K时最大化这些有向组合两端的公开威胁之和T，同一单位参与多对时逐对计入。威胁沿D1：未被本轮定身的攻击意图、扣格挡前的当前强度，非攻击为0。
4. 仍相同时优先更少交换、更少移动单位，再按重排前阵位序号组成的字典序稳定裁决。不用导入后可能变化的实例ID字符串作平局依据。
5. 不优于原排列则不动；只记一次触发／无改善原因，不制造位移动画。零／一个敌人直接空过。

这些是可验证的启发式指标，不称为“最优战术”。第一个版本不穷举未来伤害树；若配平证明触发后常无收益，记录频率并调整机制卡，不偷偷增加追击。

### 4.3 共同例子

`A(1)—B(5)—C(2)—D(6)`：初铭可交换B/C，得到 `A—C—B—D`，新增C主击2＋左邻A波及1的双杀机会。它不在本轮立刻造成这3点伤害。

`A(1)—B(1)—C(2)—D(2)`（公开威胁均1）：初始K=3，初铭单次交换不能提高评分，保持原位；现行两次交换得 `C—A—B—D`，K=4。第二阶候选集包含第一阶，不能因为升级反而选到更差评分。

原v0.1的 `A(1)—B(6)—C(1)—D(2)` 例子已纠正：两阶都应交换A/B一次，得 `B—A—C—D`，K=3，不能用来表示两阶差别。0／1／2敌以及全员HP≥3时，当前评分无改善便不动。完整评分表与算术核验见D5-A规格。

阵位改变后，敌人ID、HP、缠线、挣脱、定身、意图ID／目标／格挡全部随实例保留。本轮既有出手顺序不变；下轮正常生成新队列。召唤仍按D4右端入阵、下轮行动，不能为了保持一次旧排列再次偷偷移动。

### 4.4 原语与限制

共用核心操作建议为 `applyFormationOrder`：检查新旧存活实例集合相等、无重复／死者／解除单位、移动预算合法，再原子提交 `enemy-formation-changed`，载荷含before／after、source、reason、round。调用者负责策略；UI不传自由排列命令。

D5首发已存在的杂兵、管家、千金与本尊均可移动；不把“体型大”暗中当免疫。本次不实现固定锚点机制。生产最大四敌，初铭／现行最多4／9个候选，不能对通用20敌上限盲目全排列。

### 5.3 本尊的阵位机制

仅移动图卡对勇者五人缺乏意义，因此提出一项明确位置规则“侍偶护域”：本尊左右相邻的每个存活侍偶，使她承受的每次敌对伤害减少1，最多2。无侍偶则为0。减伤按每个实际命中分别结算，所有直击与铭约走同一核心入口；不误用玩家给攻击意图施加的格挡值。

玩家可清掉侍偶，或用高伤穿过减伤；死亡后立即收拢，远端侍偶可能补位，所以击倒邻居不保证护域下降。例如AMBC杀A后MBC，护域2→1；杀B后AMC，护域仍2。下一次重排可把MBC变BMC使护域恢复2。与千金“全场客数增加举杯”区分：这是**邻接防御**，没有补席循环。

## 6. memory 状态、重试与事实隔离

### 6.1 一次只运行一种战斗

B已采用单一 `snapshot.run` 判别联合，`campaign.activeRunRef`与之严格对应；回忆引用为 `{kind:"memory",id,attempt}`，普通远征为 `{kind:"expedition",id}`。验证拒绝多个run体、无体却有ref、kind／id／attempt不一致。没有可信战斗读取器时拒绝活动战斗和终局证明。

memory建议保存：runId、chapterId／内容引用、固定templateId、节点游标、attempt序号、局部战斗状态、局部RNG／补给、阶段起始检查点、历史结果与待兑现凭证。复用 `DemoBattleState` 的纯战斗计算，但由独立session适配器管理进出场；不调用普通层入袋或settle-expedition冒充memory结算。

| 状态 | 允许动作 | 当下资产／时钟 |
| --- | --- | --- |
| opening／teaching | 推进剧情、暂离 | 不变 |
| battle | 投骰、行动、道具、回合收束；合法撤回 | 只改局部状态 |
| failed | 重试或离开 | 不记ordinary wipe，不扣钱／物资 |
| history-complete | 自动记录篇章结果，进入当下收束 | 尚未凭动画回调开亲征 |
| return-pending | 继续／跳过展示，确认当下结果 | 完成凭证兑现一次，无时间成本 |
| completed | 回顾／重打，或返回洋馆 | 不再发奖励 |

建议离开未完成回忆即结束该次attempt，下次从本尊战起始节点重试；没有必要保留多个并发挂起run。已经获得的chapter完成及return-pending不因离开丢失；在兑现当下结果前禁止开始新战斗，提供明确恢复入口。

### 6.2 重试与 RNG

固定历史模板不等于固定骰面。首次使用章回局部seed；重试恢复该段起始状态与同一seed，attempt递增但不重抽一个更有利开局。刷新和失败回执重放不推进RNG。玩家可改变操作策略，不通过刷新改骰。

战斗中不读取当下Campaign装备、成长或临时锈。局部药品使用独立实例与来源类型，不复用真实库存instanceId；昂贵治疗只作用于局部资源，初始局部金币0且不向当下借款。牌型和铭约仍正常求值，但无当下金币累计／层奖励／返还。

### 6.3 完成与兑现分开

核心战斗产生可验证的历史终局；应用层一次记录 `chapter-completed` 与待兑现 `reward.marietta.memory`。当下收束通过显式命令确认／跳过时，同事务记录 `chapter-result-claimed`、开放凭证与记事，清除memory占用。没有通关证据时，传任意chapterId或调用onEnd都不能领奖。

首次历史完成与后来重打区分 `first-completion`／`replay`。失败、重试、重复胜利、重复确认不同requestId，都不能再次开放、赠物或推进时间。回执丢失后能按chapter／result身份恢复，即使active run已清空。

### 6.4 事实与未来LLM

新版fact的origin建议明确为 `adventure | memory | present | simulation`；memory事件带对应runRef、chapterId、attempt与来源引用。篇章战斗完成属于memory，回到当下的开放、成长、赠物与装卸属于present。普通远征保留adventure；升级／导入来源仍单独记录provenance，不改写原事实的语义。

- 战斗、失败与重试事实只属于历史体验；角色记事以“回忆”分组，不加入今天的受伤／击杀／失败统计。
- 当下亲征开放、成长领取、赠物／装卸属于真实当下结果，引用相应凭证；不把未选择分支写入事实。
- 纯故事回顾不产生重复事实；撤回只撤对应局部战斗facts，不撤销已完成篇章或当下领取。
- 后续LLM默认不接收memory战斗流；只有公开、已提交、未撤回的章回摘要能由显式适配器进入当下上下文。D5不建设该管线，也不让模型决定历史结果或奖励。

| claim-preparation-gift | 赠物session／最终节点、合法归来资格、容量 | 事件完成＋两个唯一实例＋已领记录，或完整失败 |

| copy-upgrade-save | v3已验证来源、目标saveId／epoch | 原档保留，生成合法v4基线与新档 |
| derive-new-game | 有效已完成源档、目标身份 | 新档初值＋有限继承证明，不带旧资金／接管 |

每个外部命令继续携带expectedHead与clientRequestId。奖励按save/epoch＋chapter/growth/reward业务键去重；不同requestId重试同一业务也不多发。非法或旧head请求不消费RNG、不先写UI成功、不留下半份装备转移。

### 9.2 动态查询与入口

统一从合法凭证推导 `availableCharacterIds`、`memoryAvailability`、`growthCandidates`、`equipmentInventory`、`allowedActions`。core出征验证、runtime名册、地图选择器与角色页读取同一规则，不再各自读静态profile假装解锁。

- 回忆主入口放在玛丽埃塔「记事」顶部，位于记录列表之前，状态由同一memory查询推导；洋馆／菜单保留合法引入与恢复，不成为唯一发现路径。地图只承接初战／维护出征；未发布chapter不显示可运行按钮。
- `battle.html`仍使用原 `ExpeditionBattleSurface`；绑定器按run kind投影，memory仅更换内容、状态说明和合法操作。可用原账本区域说明“回忆演练／不计当下收益”，不新增第二套战斗布局。
- 角色页保留概要／骰装／记事结构、五枚晶石与三格私约；只为实际可用动作增加原风格按钮。Lv.3以上保持未开放，不把五枚晶石删成三枚。
- 只读reader继续无写权限；页面需要领取／装卸时使用同一runtime的有限命令能力，不能为查看角色就自动推进enemy queue。
- AVG复用现有对话／立绘组件；先补受控游标与恢复输入，不通过onEnd直接改成长、资金或解锁。正式故事绑定放在game-client／共享叙事适配层，不能从一个app引用另一个app内部文件。
- 导航新增可辨识的memory定位参数，保留旧expedition URL；共享locator不能把memory id再次编码成普通expedition id。跨kind、跨attempt、陈旧链接显示恢复入口，不误操作别的run。

### 9.3 原样式中的重排表现

以敌人实例ID保持React key、目标绑定、意图线与读数；先提交核心before／after，再按原槽位做局部平移。相邻交换分段使用短弧线，线的起点来自玛指尖；不让敌人随重排重挂载、闪血条或重播死亡。

动画期间阻止新的目标点击；结束或降动效模式落到同一已提交阵位。离页／后台／刷新恢复最终阵位，不重发重排命令。保持雾renderer与D4投骰预算，禁止为每个单位创建独立雾画布。具体时长需实机调整，不借此改变既有投骰／归位时间。

## 10. 二周目、导入与恢复

二周目是从有效已完成源档派生全新档，继承的只有篇章完成证明及其来源。首次档不可跳过必要回忆战；新周目也要重新通庄园，之后才可选择“沿用回忆记录”，正常走当下结果兑现。来源证明不是全局localStorage布尔值，也不是普通复制升级的首通继承。旧本尊完成证据的承接必须验证原内容版本，不伪造刻仪兽击杀事实。

新档不继承资金、补给、装备、成长、凯尔里程碑、庄园接管或首通奖励。自身回忆仍可重新挑战；跳过与重打最终落同一篇章业务键。源档之后被删除，不应让已合法派生的证明凭空失效，因此派生档持有所需的有限可验证来源资料，不只存外部档案指针。

归档复制应覆盖：memory run／attempt、encounter／enemy／intent、局部道具、检查点、story/result、chapter completion、growth资格settlement、grant、装备、继承／升级来源和facts撤回引用。至少列一张显式ID映射表；不能新增状态后继续靠字符串后缀猜引用。

核心验证重点：来源证明完整性而非仅哈希相等；未知chapter／template／版本拒绝；simulation不能生成生产成长／继承；旧origin不因导入变成新的当下冒险。离线归档校验保证内部一致性，不将其描述为防用户修改存档的安全认证。
