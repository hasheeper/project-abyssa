## 3. 正式内容、存档和展示契约

### 3.1 唯一玩法来源

建议新增 `src/content/gameplay/demo-v1/`，按 characters、covenants、equipment、items、routes、enemies、events、progression 拆分，再由一个 Catalog 装配。目录名只是内容包版本，**不意味着沿用 rulesVersion 1**。

| 数据 | 权威所有者 | 展示方式 |
| --- | --- | --- |
| 面号、原生点数、命数、花色、基础动作、品质、成长表 | gameplay Catalog | core 解析后，由 client/runtime 映射为 UI DTO |
| 羁绊等级、已领成长、已解锁篇章、装备实例与归属 | Campaign | 页面只读 selector；修改走应用命令 |
| 本趟队伍、已解析配置、道具充能、胃口、临时锈、节点路径 | Expedition | 出征时冻结配置；战中不受馆内改装影响 |
| 朝上面、封锁、格挡、定身、敌人顺序和当前意图 | Encounter／Round | UI 读取已提交状态；不自行推导第二份战斗结果 |
| 姓名、人物介绍、手写台词、立绘和布局标定 | content 展示资料／assets | 用稳定 ID 关联玩法；不得以姓名或图片路径当规则 ID |

`shared` 继续保持展示契约和组件职责，不导入 core/application。统一事实源是统一**玩法数值**，不是把 UI 的字符串插槽塞进规则类型。已有静态样稿保留在明确的预览入口中。

建议每个正式面具有稳定 faceId 和面位，独立表示：原生点数或命点万能、action/effect 引用、fate、suit、基础 quality、锈的来源。禁止以 `pip=0` 表示沉眠，或以 `verb=blank` 表示不可成牌。

最终配置按“基础定义 → 已领取成长 → 合法装备 → 本趟临时状态”解析；顺序须测试。保养工具只移除临时锈覆盖，恢复后显露的仍是永久锈、可除锈或成长后的品质，不统一变素。

### 3.2 版本策略

D0 早期目标为 `abyssa.demo`、contentVersion 1、rulesVersion 2，历史边界见 [D0 版本矩阵](DEMO_D0_SCOPE_AND_CONTRACTS.md#3-新档旧档与版本契约)。D3 已单独发布 `abyssa.demo.manor-segment`／规则 2；D4 规划完整包使用 `abyssa.demo`／contentVersion 1／规则 3 及配套第三版 reader，原因与兼容策略见[D4 版本方案](../plans/DEMO_D4_OLD_MANOR_PLAN.md#3-内容发布与版本隔离)。该方案尚未实施，不改写 D3 原档。

1. `abyssa.legacy` 的内容版本、规则、旧五人、黄金轨迹和兼容 facade 保留。
2. 新记录显式选择新包；读取旧档案按其 CatalogRef 和 digest 装配旧实现，不按“当前默认包”解释。
3. 缺失 Catalog、未知 schema／规则版本、digest 不匹配时提供可解释错误与导出路径，不静默改为新包，也不回退成 legacy。
4. Campaign、Expedition、Encounter 的新增持久字段分别列 schema 变更；更新严格校验、导入导出、快照、撤回检查点和恢复逻辑。
5. 首批建议采用“新 DEMO 新档案，旧档继续原规则”。以后若允许迁移，另写角色、资产、成长映射；只在无活动远征时迁移，保留原档，不热换进行中的内容。
6. 规则／配平变更后，正在进行的远征仍使用原冻结内容。内容热更新不能改变未完成遭遇的 HP、意图或掉落。

### 3.3 持久化约束

新增命令至少覆盖事件选择、合法节点推进、道具使用、成长领取、装备装卸、篇章开始／完成；具体命令名称在 D0 契约中统一。继续使用 `expectedHead`、`clientRequestId` 和原子事务。

房间奖励、层入袋、整趟结算、篇章赠物、首通奖励是不同业务事件，各自有稳定去重键；必须联合状态迁移提交。UI 动画完成回调只推进展示，不负责发奖励或改解锁名单。

## 5. 战斗规则增量与结算时序

### 5.1 行动、成牌与铭约各自独立

建议新规则的顺序：

1. 建立玩家回合及敌方意图；应用合法的首回合共鸣。
2. 玩家掷骰、固定、重掷、行动、用道具；每条命令提交后更新合法目标和意图预览。
3. 结束回合，冻结有效朝上骰快照；命数睡眠不贡献点数／花色，已使用和固定不等于失去成牌资格。
4. 枚举牌型，锁定凯尔万能点数及最终贡献者，结算一次最高牌型收益。
5. 对同一冻结骰快照检测所有铭约图案，按明确队列执行；后续铭约的目标读取前项已生效的战局。
6. 敌方意图依确定顺序逐项执行，处理定身、封锁、修复、召唤和逐项后的死亡／联动。
7. 处理回合结束状态，判断遭遇结果；遭遇胜利再交给房间与层流程，不直接等同清层。

提前清空敌人、派生伤害双方同时力竭、终局时未用骰的最后成牌时点，应沿既有流程做正式规则测试并在 P02/P08 明定，避免同一行动得到两次回合收益。

点数牌型已有数值可作为模拟起点；同花至少四个自然同色有效面是建议接线口径。总规格中同花 `+0.6`、五骰同花顺 `+2.4` 仍是提案。P02 决定同花顺是否本次启用、牌型优先级、品相贡献及万能点数平局规则；决策前不能复用旧 evaluator 就宣称新六人经济完成。

### 5.2 顺劈

既定：按敌人横排显示顺序取左右邻位；死亡即时收拢；召唤从右端入列；波及走正常玩家伤害、赏金和意图取消链。

**建议补充原子语义**：命令通过校验时锁定主目标 ID 与当时邻位 ID，按主目标后波及结算；主目标死亡收拢不改变本次波及对象。波及对象若已被同批先行效果消灭则跳过，不向新邻居补伤。下一次行动重新读新阵位。

例如 `A-B-C`，对 B 右顺劈，锁定 B、C；B 死亡后仍打 C。对最右端顺劈只打主目标。预览与执行必须共享同一目标解析器。

### 5.3 提线、定身、缠线、挣脱

既定判定使用敌人**当前 HP**：常态门槛 `ceil(自身 maxHP × 1.5)`；敌人当前 HP 严格低于其 maxHP 一半时可用 `自身 maxHP × 2`；骰面稿还有绝对上限 6。

| 状态 | 既定效果 | 建议持久边界 |
| --- | --- | --- |
| 定身 | 取消本轮行动；保留蓄力 | round，敌回合结束清除 |
| 缠线 | 可同时留在多个敌人；绞杀命中目标时消费并 +2 伤，或目标死亡时消失 | 敌人实例／encounter；不因回合结束清空 |
| 挣脱 | 曾被定身后不可再定身，仍可挂缠线 | encounter；源文 expedition 注记与“本场”冲突，P03 裁定 |

建议上限按 `min(所适用门槛, 6)` 执行，暂不接生命小件把重伤上限变 8 的提案。重复挂线不叠层；对有挣脱的合法目标仍可提线，只产生缠线，不重新取消意图。这些补充在 P03 合并确认。

预览需显示不可选原因，例如超门槛、已死亡，而不是让玩家浪费行动后才失败。绞杀是否消费线以命中且伤害效果合法完成为准，失败命令不得先删状态。

### 5.4 敌方修复、封锁与关联意图

缝补女佣新增敌方治疗目标域，不可冒用仅面向队员的治疗载荷。建议在公布意图时选定“存活、受伤的其他友军”，优先缺失 HP 最大者，平局按阵位；目标死亡后本次修复落空，避免隐藏转向。全员满血则显示整理／空过，不暗中改为攻击；具体口径属于 P08。

管家封锁需给出目标选择、持续时间、被封骰的行动／成牌／铭约资格和圣水解除时机。D3 前必须提供完整机制卡。禁止将大范围封锁、重击和女佣治疗同时堆入首次考核而没有可读的应对窗口。

千金【举杯】保存语义公式与关联对象，显示值由核心 selector 计算：`2 + 当前有效宾客数`。建议宾客只统计本遭遇存活且标记为席位宾客的候席客，不统计背景画里的宾客、女佣、Boss 或已死亡实例。

每次死亡、召唤、相关状态变化后重新计算；锁定的是意图身份，不能锁死过期伤害数字。格挡单独保存：先求当前基础伤害及威压等修正，再扣该意图格挡，最低 0。新召唤是否本轮行动、联动是否立刻加伤都在 P08 定义。

表现按提交回执中的子事件逐步播放餐刀碎裂和数字变化；读档直接显示最终已提交状态。预览、日志、实际扣血和演出不能各用一套宾客计数。

| 落幕管家 | 第 3 层守门人；封锁＋3 伤落幕 | 建议闭门封锁→预告落幕→重夯的可读循环；HP、封锁持续与范围待模拟，不沿用旧衣橱数字 |
| 末席的提线千金 | 当下 Boss；席位／补席；举杯 2＋宾客数 | HP、初始宾客、席位上限、补席频率、目标数、行动顺序与胜利条件待 P08 定卡 |
| 刻仪兽 | 维护战与回忆战最终Boss；沿用a5四足立钟形象 | HP、意图循环、目标、是否带杂兵、终局表现、两种模式难度与奖励待机制卡；不直接继承本尊护域或千金补席 |

建议千金战初版交替补席和举杯，新增宾客从下回合行动；禁止同一轮无限补席。建议击败千金即解除本遭遇余下宾客，结束战斗，额外清除不重复发击杀赏金。这里的“击败”是解除控制，叙事与演出不用通用碎尸死亡。

每张可入库卡必须列：ID、HP、目标算法、意图序列、状态免疫（没有则明确无）、阵位／召唤上限、奖励来源、战胜条件、动效映射、事实输出、平局与异常情况。未定 HP 不得以示例数字悄悄进入正式 Catalog。

### 7.3 层、房间与遭遇生命周期

建议 Route 由有序 Layer 构成，Layer 包含有稳定 ID 的 Room；Room 引用战斗、手写事件、宝箱、休整或出口定义。先支持庄园实际用到的类型，不建设自由图编辑器。

| 边界 | 应结算／清理 | 必须保留 |
| --- | --- | --- |
| 回合结束 | 单轮格挡、定身、道具两次限额等 | 充能、胃口、临时锈、缠线、已入袋资源 |
| 遭遇结束 | 敌人实例与本场状态、首回合标记、战斗游标 | 队员残血、局内退化、装备本趟成长、未清层散金／累计牌型收益 |
| 清层 | 整层奖励入袋一次、清层效果与层作用域状态 | 本趟资源、选择、队伍及装备成长 |
| 撤离／失败／通关 | 最终结算一次，结束本趟作用域 | Campaign 资产、首通、成长和已提交记事 |
| 回忆重试 | 丢弃失败片段的战斗运行状态，按该片段规则重开 | 当下资产与既定历史不变 |

本表的具体状态归属以各定义为准：例如红线迷宫是给当前攻击意图加格挡，不是给全队一个无限期护盾。新增字段必须更新 session 字段所有权、序列化、验证与 undo。

“下一场 1 HP”与“雨夜之盟下一层 2 HP”推荐按字面分开：基础在下一场归队；雨夜之盟额外标记等到下一层兑现 2 HP，不能降低已有更高 HP。该组合仍需 P06 裁决，不能因首版一层一战就忽略多场差异。

## 8. 补给、奖励与失败

### 8.1 七件常备包（既定效果）

| 道具 | 效果 | 合法时机／限制 |
| --- | --- | --- |
| 食物 | 单人治 1 | 安全输入窗口；每人整趟最多 2 次 |
| 药水 | 单人治 2 | 安全输入窗口；受携带充能约束 |
| 护符 | 一条攻击意图 +2 格挡 | 玩家回合 |
| 圣水 | 优先解除封锁，否则净化一项负面 | 战斗内合法输入窗口；净化清单及顺序待定 |
| 保养工具 | 清一人的一面本趟锈蚀 | 可在战斗或走廊使用；不清永久锈及凯尔晶石成长锈 |
| 幸运符 | 本回合重掷次数 +1 | 玩家回合；不改已固定／已使用骰的资格 |
| 卦签 | 揭示下一层房型／敌群／变体，或事件选项的判定与代价 | 走廊、事件、出口选择前；不泄露未来骰 RNG |

不占骰、不占行动、不作用于力竭者；战斗每回合最多两件。敌方结算中“随时”应解释为等待合法输入窗口，不向执行到一半的敌方回合插命令。建议战斗外按充能与胃口限额，不虚构回合，P07 收口。

储藏室槽位 4→5→6、上限不到 7 已定。历史充能 4/2/2/2/1/1/2 是占位，不直接定稿。设施完整生产链可后续做，本次至少提供有限初始供给、真实出征预留、消耗与剩余返还、可再次补给的来源。失败后也必须有继续尝试的补给路径。

建议首次四槽默认食物／药水／护符／圣水，可在出征前更换；数量、补给成本、返还归属和防重复领取在 P07 定表。不得每次刷新免费刷物资，也不能只有首通前的一次性供给，失败后再无合法来源。

### 8.2 经济边界

新规则建议采用“基础赏金不乘层倍率；整层入袋乘一次层倍率”的方案，避免把 legacy 的重复深度放大带入新配平。还要确定牌型收益跨同层多战的累计方式、尘世 +10% 和水杯 +10G 的先后、最小货币单位及舍入时点。

建议公式：`层入袋 = round(本层净散金 × (1 + 累计牌型加成) × 层倍率 × 尘世因子) + 合法固定入袋奖励`。各项数值、赏金来源与首通额外奖励由 P10 定表；公式是推荐口径。敌人被补席无限召唤不能提供无限可刷金币，需选择召唤赏金预算或零赏金等明确规则并模拟。

| 结果 | 既定原则 | 建议具体账本范围 |
| --- | --- | --- |
| 第 3 层撤离 | 合法出口，保留获得成果 | 带回已入袋资源与合法剩余补给；无首通 |
| 第 5 层完成 | 普通远征奖励＋首通特有结果 | 常规结算按 expedition 去重，首通按 Campaign 进度去重 |
| 全员力竭 | 丢本层未入袋奖励；保留此前成果并承担金币损失 | 仅本趟已入袋金币减半；以前的洋馆存款与已入袋非货币材料不扣；P10 确认 |

战后不自动满血；本趟临时锈离场清除。普通失败不自动生成 1–3 天强制住院、永久伤残或真实重伤缺勤。道具结算只返还未消耗部分，不能因失败或刷新复原已经使用的充能。

## 9. 首通、回忆与重复挑战

### 9.1 初战、回忆战、维护战（2026-09-07用户定稿）

**初战不是“第一次出征”。只要尚未完成最终通关，后续再次出征仍是初战。初战通关后，同时开放回忆战和维护战；初战最终Boss是千金，回忆战与维护战最终Boss均为刻仪兽。回忆战入口放在角色「记事」顶部。** 用户进一步确认“由刻仪兽战替代”原玛丽埃塔本尊战。本条覆盖此前“维护无最终Boss”、地图并列三类入口的建议及“回忆→维护”的必经串行写法。

| 类型 | 开放与结束条件 | 内容与后续 |
| --- | --- | --- |
| 初战 | 未取得庄园最终通关的合法首通结果时，一直使用初战路线；三层撤离、任意层失败、末层未获胜都不结束初战阶段 | 五层庄园，三层落幕管家、末层提线千金；最终通关并结算后接管庄园，同时开放以下两类 |
| 回忆战 | 初战通关后开放，无需先完成维护战；由玛丽埃塔「记事」顶部进入 | 固定历史勇者小队，最终挑战刻仪兽，替代原本尊战；不出现千金。完成回忆和当下收束才开放玛亲征 |
| 维护战 | 初战通关后开放，无需先完成回忆战；仍由地图庄园出征面板进入 | 当下重复远征；沿用五层与三层出口，末层改为刻仪兽。回忆未完成时仍可用已开放勇者队出征，不重复千金救离 |

```text
新档：凯尔＋勇者四人，玛丽埃塔已在洋馆共同体中
  → 初战：撤离／失败 → 下一趟仍为初战
  → 初战最终通关、结算接管
      ├─ 角色·玛丽埃塔·记事顶部 → 回忆战：固定勇者小队 → 刻仪兽 → 当下收束 → 玛亲征开放
      └─ 地图·庄园 → 维护战：已开放队伍出征 → 第五层刻仪兽 → 回馆 → 可重复
```

**回忆战开放、维护战开放、玛亲征开放是三个不同条件。** 前两者来自初战通关，后者来自回忆结果在当下兑现。回忆失败、暂离或尚未游玩不撤销已开放的维护；已有活动run或待兑现结果时，仍需先完成／离开当前流程才能开启另一场。

家宴落幕的阅读游标只负责叙事衔接，不应让已通关玩家看不见回忆入口。若首通剧情尚待阅读，选择回忆时先接续或跳过家宴，再进入回忆；回忆的业务解锁来源仍是首通结果，不额外要求一次维护。

**实现现状**：默认v3仅有初战／维护；v4回忆入口当前位于洋馆归来报告，角色记事尚无入口，且开始回忆要求先完成／跳过家宴。现有回忆仍为本尊战，维护末层仍为普通敌群；刻仪兽仅有素材，尚无敌人定义。入口、遭遇与旧档续接均待实施，不能把文档定稿视为已上线。源码与复现见[闭环审计](../audits/2026-09-07-game-loop-and-shop.md)。

**入口要求**：在玛丽埃塔的「记事」内容区顶部、实际记事列表之前放回忆战入口；空记事、长列表和“显示更早记事”均不得挤掉入口。保持既有角色页组件、布局风格、好感晶石和私约区域，不另造地图三页签。其他角色只有发布了对应篇章才显示可用回忆。洋馆可继续承接引入／归来，不能成为唯一发现路径。

| 记事顶部入口状态 | 展示与行为 |
| --- | --- |
| 尚未首通 | 显示回忆战及“通关克雷格旧庄园后开放”，不启动战斗 |
| 已首通、未开始 | 可进入回忆；有未读家宴时先衔接剧情，不隐藏入口 |
| 回忆进行中／失败后暂离 | 按实际游标继续或重试，恢复对应memory与attempt |
| 已胜利、当下结果未兑现 | 继续当下收束，不生成第二趟run |
| 已完成并兑现 | 可重新挑战／只读回顾；两者区分，不重复发奖 |
| 另一活动run占用 | 显示实际占用与返回当前流程入口，不自动结束或覆盖它 |

查看记事只读；开始、重试与结果兑现必须是明确操作，使用统一会话资格和命令。标题“继续游戏”和记事“继续回忆”必须恢复同一个run kind。

验收至少覆盖：三层撤离后仍初战、千金战失败后仍初战、首通后未打回忆即可维护、回忆失败后仍可维护、维护末层刻仪兽、回忆刻仪兽且无千金／本尊战、完成回忆后玛加入维护、标题恢复正确run、记事入口全部状态，以及正常新档和既有v3档能到达该入口。

玛丽埃塔不在战斗队伍仍需参与首通救离：脚本明确她在分区解除后抵达／接手；不能在结局忽然当作一直在战场上攻击。首通后“今天没有客人”表明旧规约结束，接管不是她坐上仍有效的陷阱主位。

### 9.2 首通事务与演出

既定终局：斩断全部吊线→餐刀化灰→少女脱落沉睡→玛丽埃塔抱起合眼：“家宴结束了，小姐。您可以离席了。”→推回主位、合登记簿：“今天没有客人。”

首通提交建议同时记录：旧程序已停止、千金已救离、庄园已接管、一次性奖励领取、后续可用篇章／委托状态。演出游标独立于这些权威结果；跳过、刷新、切页不能取消既成结果或再发奖。恢复时可续播或查看剧情回顾。

首通奖励和篇章奖励使用不同 claim key。若结局有玩家选择，其选择先成为持久命令再驱动结果，不把交互藏在不可恢复的动画里。P08 还需明确同批双方全灭时按哪种终局处理。

### 9.3 回忆篇

回忆仍为玛丽埃塔的独立历史片段，参战者为固定勇者小队（凯尔、尤斯缇丝、艾洛拉、柯萝萝、诺玛）。**最终战改为刻仪兽，原“勇者对战玛丽埃塔本尊”由它替代，不前置保留、也不另增独立本尊篇章。** 千金不进入回忆。现有回忆是一场战斗，本次替换不自动扩成五层地牢。

原《王座前的提线魔女》的本尊开场、护域教学、战中台词、突破防线与收线止战结局，不再作为新版脚本。刻仪兽的机制、篇名、历史场地适配、出场缘由和战后对白需随替换稿重新编写；不能把旧台词中的人物名机械替换成刻仪兽。保留“当下引入→固定历史片段→战斗→历史收束→当下兑现”的可恢复结构。a7本尊美术保留归档，当前回忆使用a5；此项不改变玛作为可操作角色的敌方阵位重排能力。

回忆隔离当下物资、HP、临时锈和经济；失败只重试，不改既定历史、不写当下远征败绩、不领取常规掉落。完成回忆后，应用层一次性写入角色开放和当下互动结果。

建议回忆片段与重试不推进当下时钟，返回当下后的事件按独立规则计时；P15 同时收口时间和事实边界。二周目跳过需读取可验证的篇章完成记录，例如从已通关档案派生的新档继承；不以本地任意布尔值或另一个无关档案的 UI 缓存开放角色。继承范围在 P01 定义。

角色“红线重排”与葫芦铭约继续使用已实施的阵位原语，作用于敌方横排。旧本尊护域／重排循环仅作为旧内容版本的兼容规则，不自动移植给刻仪兽。两类刻仪兽可以共用基础敌人定义与美术，但回忆固定队伍和维护可成长队伍需分别配平；局部补给、奖励和完成凭证保持分开。

替换涉及遭遇、敌人、模板、脚本行ID、终局及篇章证据。必须先制定内容版本与迁移映射，再接正式入口；不原地更改冻结v4定义，不把旧本尊活动战的HP和游标直接当成刻仪兽状态。旧完成／已兑现记录不得被悄悄撤销或重复领奖，具体承接由D5-F核验与G验收。

### 9.4 维护战

**已定：初战通关即开放维护战，不以回忆完成为前置，最终Boss为刻仪兽。** 叙事为清理尚未拆除的支线残余规约，它们不再具有“补齐主人”的中央权限。沿用三舞台，不再绑回千金、不重复救离，也不撤销接管状态；刻仪兽在维护中的具体职责和收束由机制／剧情补稿说明。

初战与维护使用不同route／encounter定义，奖励分开配置。保留D4五层、第三层可撤离及三层普通敌人组合，**第五层从普通清理战改为刻仪兽终战**；末层编队、HP、行动循环、赏金及终局条件待卡片与模拟。现有代码产出为金币，新Boss奖励尚未定数；不套首通20G奖励，也不重复触发接管。

剧情回顾只重播既成片段；带奖励的当下维护委托、无当下损耗的回忆重试、纯演出回顾须在存档和文案中区分。完整 DEMO 验收必须覆盖一次正式重访。

**Abyssa 决定发生了什么，rp-style-lab 以后处理如何组织上下文和调用模型。** 不向模型开放直接改 HP、抽取掉落、赋予解锁、替玩家选事件或写 Campaign 的入口。

以下是历史候选名称的实施载荷建议，不是现有协议。注册时同步 schema、校验、版本、可见性及撤回处理。

| 候选事实 | 最小业务载荷 | 触发依据 |
| --- | --- | --- |
| `cleave_double_finish` | actorId、主／邻 targetId、同一 actionId | 同一次顺劈实际造成两次击杀 |
| `bound_heavy_attack` | actorId、targetId、被取消 intentId | 定身实际阻止该轮重击，不把举盘准备也冒称重击 |
| `thread_execution` | actorId、targetId、消费线及击杀结果 | 绞杀实际消费缠线并击杀；不用于千金救离 |
| `banquet_guests_cleared` | encounterId、清席数量、剩余数 | 实际席位宾客死亡／清席 |
| `manor_invitation_corrected`、`manor_relic_preserved` | eventId、choiceId、参与者、实际结果 | 已提交事件选择及结算 |
| `returned_from_midpoint` | routeId、exitRoomId、结算引用 | 第 3 层合法撤离完成 |
| `manor_program_stopped` | 首通引用、救离／接管状态 | 首通事务提交 |
| `manor_wipe` | expeditionId、真实结果引用 | 当下庄园全员力竭，不含回忆 |

新增回忆完成、角色开放和成长领取事实需单独定义。现有 origin 是 adventure/imported/simulation；建议增加明确的 memory 来源并升级验证／过滤，而不是把本尊战记成今天攻击家人的冒险。回到当下的赠物与开放是当下事件，和历史战斗分开。

事实携带现有 source head、来源、世界时间和可见范围，适配时补节点／篇章引用。角色记事可读取授权的历史事实；AI 当前场景投影不应为了方便而全量放开历史、隐藏意图和未选分支。撤回后失效的 facts 必须从记事和待发送上下文中排除。

首发用本地手写反馈模板完成“真实结果→回馆短句／记事”。以后接 rp-style-lab 时继续传可见事实、场景和版本引用，丢弃过期响应；超时、断网、取消或模型拒绝都不影响主循环。长上下文摘要、检索、模型路由、提示词及复杂调用管线不进入 game-core。

## 11. 素材接线与表现验收

素材路径和来源以[庄园素材清单](../../../src/assets/battle/old-manor/README.md)为准。正式路径已经本地化，不新增图床依赖。

| 资产包 | 首批接线 | 额外制作 |
| --- | --- | --- |
| 三小怪 | waiting-guest、platter-bearer、mending-maid | 身体 bounds、足点、相对高度；侍者举盘可读状态 |
| 守门人 | curtain-butler | 屏风开合或专用状态图；体量明显高于杂兵 |
| 千金 | last-seat-puppet-heiress | 餐刀排、独立吊线、断线／化灰、沉睡姿态及接住少女的演出方案 |
| 本尊 | marietta-memory-boss | 手指发线与重排演出；不复用受害者断线死亡 |
| 场景 | 三背景，分别映射对应层 | 按实际敌方视窗做等比取景；保住舞台下部和红线 |
| 地图 | old-manor 地标 | 对应真实 route、首通／维护状态和编队入口 |

当前敌人素材保留完整大画布，不能按 alpha 边框统一身高。分别保存身体边界和含细线边界，布料／餐罩／裙撑／吊线均需检查。背景约 1376×768，而现有敌方舞台约 1040×322，需先验证裁切；不直接拉伸，也不为装下原画重做整页框架。

保留已验收的黑木／旧白布／暗红色系、收敛姓名亮度、顶栏悬丝和内沿红线。固定／已用骰不旋转；回合归位保持现有 560ms 缓起缓停及原版掷骰节奏。

雾效继续在敌人后、交互前保持独立层：24fps、内部宽度上限 640、隐藏暂停、减少动态效果时静态、不逐帧 setState／布局测量。多怪、补席、餐刀碎裂和重排不能各自新增高频 React 更新。既有同机短测数据只能作比较基线，D6 需对实际最大敌群和同时动效重新测量。

低动效模式下用短淡入、清晰状态和数字完成信息传达，不靠动画才能理解伤害或首通结果。

配平按固定种子批次记录：默认勇者队、玛替换四人分别测试；Lv.1 基线与实际可达成长档；默认补给、低补给、无艾洛拉阵容；主动撤离与全灭；有无关键装备。输出清关／撤离／失败分布、每场回合、受伤与消耗、收益、铭约触发、提线成功窗口和召唤拖延收益。

模拟不能只测“最优自动策略”，还要测先攻、先保命、误用一次道具等可解释策略并人工试玩。胜率与时长目标由首轮数据提出，再冻结；本稿不凭空承诺一个未经测量的百分比。不得为通过模拟暗加固定好骰或悄悄削弱首通敌人。
