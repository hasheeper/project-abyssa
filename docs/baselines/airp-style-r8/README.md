## 冻结内容

- [完整有效预设](preset.json)：原55项全部保留，连同既有Plan和尾部规则共59项、启用34项；原三段ICOT不变。
- [冻结请求](request.json)：实际发给gemini-3.8-flash的完整请求体，含全文角色卡／世界资料，去除了对本机配置的依赖；无API地址、Key或认证头。
- [原始公开响应](response.json)：`text`字段完整保存原始可见输出，连同finish_reason及usage；没有私有推理字段。该字段的SHA与真实调用原稿一致。
- [中文审阅稿](sample-cn.md)／[中文差分核对稿](sample-expressions.md)：两处双语失败仅复制已有中文供阅读，未重译或润色，不冒称格式通过。
- [诊断记录](diagnostic-review.json)、[差分目录](expression-catalog.json)、[微调清单](prompt-edits.json)、[顾问公开原稿及用户后续接受反馈](consultation.md)。
- `context/`含实际输入的4份全文资料及缺席者简稿。请求内也是全文；仓库其他位置的资料未来变化，不影响此快照。
- `scene.json`、`performance-plan.txt`、`player-boundary.txt`、`choice-output.txt`、`expression-output.txt`保存本场景和各追加条目。只供本场回溯，换场景应重新绑定在场角色和差分目录。

模型仍为单Gemini，没有恢复Sol或新增其他规划模型。约600字／20段／50%对白是当时提示词软目标，实际491汉字、23段、32.7%对白；用户接受的是实际文风，不是宣称这些数字全部达标。

## 独立校验

在仓库根目录运行（Node 22，无需安装依赖、私有配置或联网）：

```sh
node scripts/check-airp-style-baseline.mjs
```

检查清单SHA、有效预设与冻结请求、全文资料、原始响应、已知错误仍然留档，以及验收边界。校验成功只代表快照完整，不意味着剧情、人物或双语协议通过。

JSON归档统一以换行结尾；`manifest.json`另保留真实调用时的请求SHA，并以原序列化方式验证。请求里的所有消息字符串、预设条目和响应`text`未改。全文资料若归档末尾增加换行，清单同时保留原始长度和SHA，按原始字节片段核对，不改正文。

本次Git提交只发布这个可独立校验的文风基线、校验脚本和[逻辑分析](../../audits/2026-09-23-airp-single-generation-logic.md)。它不是整个AIRP工作区或游戏版本的发布：其他尚未提交的实验运行器、UI、玩法、部署、存档和私有配置均不夹带。
