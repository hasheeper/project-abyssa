## 1. 先建立正确的项目图景

Abyssa 是“守望者之崖共同生活＋小队骰子战斗＋人物叙事”的游戏。作者定稿的开场、主题地牢和人物篇章构成骨架；受控 AI 生成把真实行动的结果、人物关系与当下场所接成可持续的日常反馈。它不是让每个人物各开一个聊天窗口，也不是让模型自由控制一个世界。

核心体验应当是：**生活中的具体牵挂让人出门，真实玩法决定发生了什么，归来让物件与关系发生可感知的变化，变化再影响下一次生活与行动。** S4 正是玩家第一次完整经历这个交接的地方。

## 2. 设定与游戏内容的关系

### 2.1 只保留影响创作的世界前提

- “秩序／混沌”是两极源力，不是善恶标签。过度秩序会结晶与僵化，过度混沌会畸变与溶解；大天平是无人格的平衡机制，不是随意赐福、复活或倒转结果的神。
- 勇者与魔王的冲突之后，人类与深渊势力在共同毁灭的威慑下维持脆弱停战。守望者之崖是偏远的隔离／共治地带；洋馆的安宁与外部灾厄相连。
- 艾比希斯是收容灾厄的关键存在，勇者的稳定共鸣与日常照料是她的安宁锚点。柴米油盐不是与主线无关的装饰，正是维系生活秩序的方式。
- 勇者小队与魔王一方**早已共同生活**。开场不是新手冒险者初识伙伴，角色不因教学才学会战斗；教程教的是玩家操作。
- 原设定中的补给压力、结界维护、政治暗流可以提供动机，但目前没有完整家计／结界耐久／势力模拟系统。不能用设定一句话生成实际消费、计时惩罚或新任务。

### 2.3 生活洋馆与旧庄园必须分清

守望者之崖洋馆是家与整备枢纽；**克雷格旧庄园是另一地点**，不是把家变成战斗场景。

旧庄园主题是“规矩比人活得久”：失控家政结界把“备好家宴”解释成“补齐宾客”，死物被迫入席，最终拼出伪女主人。白布／黑木／红线对应假皮肤、错误躯体和控制关系；普通怪被线吊住，玛丽埃塔的线从手指出去。

她不能独自取消家宴有三重理由：只有执行权而无主人取消权；坐上主位会被困成永不离席的主人；强拆主干会毁坏遗物。伙伴参与与分区拆除应在玩法／剧情中成立，而不是说她突然变弱了。千金是权限赝品，不是某位家族成员复活；终局是解线与结束家宴，不是反复处刑少女。

首通后玛接管庄园，之后完成回忆及当下收束才开放亲征；她此前已经是洋馆共同体的一员。定稿台词“家宴结束了，小姐。您可以离席了。”与“今天没有客人。”保留。**这些是作者设计背景，不应由 S4 一口气剧透。**

未来四地牢方向已记录：旧庄园／玛／规矩，破碎要塞／阿尔薇特／誓言，禁书墓穴／蕾诺尔／记录，永夜城堡／薇薇安／宴饮；共同方向是“地牢证明力量与拒绝，餐桌让人物卸下它们”。后三座并未成为正式可玩路线。

## 3. 完整流程：S4 在哪里，结束之后由什么驱动

1. **新建档→CG序幕**：四幕15张图、34段文字，逐镜阅读／恢复，之后 Logo 与首晨；不是四个可探索章节。
2. **洋馆首晨 S1／S2**：120个持久节点，四组三选一＋末尾一组二选一；默认 AVG，可切 RP 版式。早餐、书、草药和旧毛毯建立生活牵挂。
3. **诺玛报告马车遇袭→岩窟**：十人上下、带十字弩的人类强盗利用退潮动手；任务是追回草药、帝都书箱、原送工坊的包袱，不是救缇比。
4. **雾滩·退潮岩窟**：独立单层四战。双软泥教 ROLL／固定／行动；刀手＋弩手教意图／重掷／攻防；搬运队教集火与牌型／铭约；匪首＋双弩作综合运用。七个故事槽穿插其间，目前是工作占位。
5. **S3-5→S4-1→S4-2**：真实胜利后清点返程，回馆交还物件，休整并留下旧庄园钩子。读完只到 `claimable`；玩家独立领取真实结算及一次8G报酬后，推进一次相位并进入自由枢纽。
6. **枢纽→整备／商店／编队→庄园初战**：五层固定路线，第三层可撤离；没首通就仍是初战。团灭／撤离后的再次初战可有“再战”承接，不自动变维护。
7. **千金首通与落幕→维护、回忆、四型事件**：必需收尾结束后，现有卡池才有资格提供事件。维护作为后续巡守底板；回忆从玛的记事进入，完成后还要当下收束才能带玛出征。
8. **持续循环**：游戏程序筛选事件／提供选择，玩家实际行动，规则提交结果，手写或受控生成场景反馈，实际阅读产生后续可用的记忆。不是模型不断自发续写。

**现状差异：**总设计曾建议“初章后开放自由涟漪，出击另需巡守资格”；当前 `airpEligible` 却对整个卡池要求庄园接管、落幕不再待办、艾洛拉可用、教程完成／豁免、无活动占用。因而**S4 后立即出现家务／小景／牵线并非现成功能**。若要提前形成日常循环，须按型别拆准入并验存档／优先级；本文件只列为待定方案。

## 4. S4-1／S4-2 精修任务包

### 4.1 进入两场之前，玩家已经看见什么

首晨已把三类物件分别系在人物身上：艾洛拉用私房钱购入受潮特价草药，柯萝萝等待帝都来的书；艾比希斯不接受没有熟悉气息的新毯子，旧毛毯原计划送工坊修缮，新版通报中由玛明确说出包袱内容。失物使日常问题升温，玩家出门处理，玛留守。

S2 的最后 A／B 已给过出门态度及艾比希斯反应，不能在回馆假定两支都发生。岩窟 S3-4 另有 A“守住出口”、B“堵住退路”、C“先检查货物”；只记录态度，三支都接同一最终战。它们不改伤害、敌人、货物、奖励或通关结果；重试不重新选态度。

潮汐与留守结界的时限台词提供叙事压力，**没有现实时间倒计时、读对白罚时或自动毁货规则**。回馆具体伤势、用过什么补给、赚了多少不能从“打赢四战”推断；需要相应真实事实，否则不写成确定状态。

### 4.4 审查判断与建议精修方向（不是候选正文）

**S4-1 的问题不只在短，而在三次平行签收，缺少由一次出门改变屋内关系的连续动作。** 三件物各有去处是必要信息，但不宜让人物轮流“谢谢／收到”。旧毛毯承载了首晨最强牵挂，艾比希斯缺席于实际反应又削弱了回收。

建议先确定一条共同的物理交接过程，再让艾的珍惜、柯的关注、玛的处理以及艾比希斯的反应互相承接；可有短停顿、打断与没说完的话，不必全员轮番展示性格。是否加入艾比希斯、怎样处理未修完的毯子，应先定骨架再写句子。不要直接在这里承诺大段新演出。

**S4-2 的问题是“旧庄园还有事＋商店入口”像两个功能提示，没有给玩家足够具体的下一步动机。** 但它也不适合立即讲完权限锁、千金真相、首通与回忆机制。

建议把本场目标限定为“这次出门已经落地→允许喘息与整备→留下可理解而未解答的庄园问题”。具体钩子必须先确认：只留下轻钩子，还是追加独立委托交代场景？后者是制作范围与接线扩展，不能把一段新台词当作已存在的任务系统。

### 4.5 两种交付轨道，不把旧模板变成永久审美限制

- **槽内精修**：保留现有三页＋两页、说话者与所有身份，只改善句子和承接。旧任务允许情绪：艾 `smile/neutral/serious`；柯 `neutral/smile/closed`；玛 `neutral/smile/serious`；诺 `neutral/wry/smile`。这是低改动轨道，不足以补齐所有戏剧缺口。
- **结构精修提案**：可以建议增加同节点分页、重新安排回应、加入艾比希斯或独立庄园交代；交付时明确新增内容、资产需求、哪些仍是待定。实际入库必须检查演员／帧ID、版本与阅读兼容。增加同节点帧与插入持久节点不是同等改动；后者尤其不能直接挪旧游标。

`llm/context/tasks/S4-1.json` 与 `S4-2.json` 是旧离线作者任务，不是当前在线 Workflow。它们要求日文原文＋中文翻译的候选格式；现行游戏 S4 是中文占位。本文件用中文交接，后续正式起草时应明确沿用双语还是先定中文，不擅自翻译已定稿开场，也不把旧候选 JSON 要求套给文本模型。

### 4.6 玩家主控与文学空间

允许无台词的自然物理动作，例如递物、收拾、拔剑、落座；允许声音、触觉、物件质感与短促感受，不要求一切细节都来自数据库字段。群像对话优先交给伙伴，不让主角当连续捧哏或系统讲解员。

真正需要限制的是：替玩家作关键决定、长篇代言／指定心理，把接受打算写成已经执行，把一句邀请误读成前一场已确认历史，或捏造伤势、奖励、任务完成等硬结果。**“坐下”本身不是越权；“上一场已确认你坐下”若没有来源则是错误回忆。** 既有审读中对日常动作的笼统严判不应成为新禁令。

关键选择才使用具象行动，通常每场最多两次，选后至多一句短定调；现有 S4 无新增选择权限。首晨的固定主角台词是已定稿特例，不向新场景自动延伸。不能为了避免代言把文字写成没有动作的空洞对白。

## 5. 战斗、成长与经济：内容讨论必须知道的硬边界

### 5.1 骰子战斗不是模型裁判

正式战斗有玩家、尤、艾、柯、诺、玛六人的规则，最多五人同时出征且玩家必带；初期是玩家＋四位勇者伙伴，玛亲征另解锁。角色各有固定六面配置，面同时具有动作、点数、花色、醒眠与品质；成长／装备有限改变这些配置，不是每次让 AI 发明技能。

一轮依次为：公开敌方意图；ROLL；固定与至多两次重掷；每枚固定骰一次合法行动；结束回合判最佳牌型及铭约；敌队列执行。道具另有每回合两次额度。随机数、敌意图、目标、伤害、判定与奖励由游戏规则计算，刷新不重新掷。

- 已用骰不能再行动／重掷，但仍可成牌；沉眠面不成牌，不代表它必然无动作。空白、沉眠、使用、固定、封锁是不同状态。
- 封锁／力竭骰排除行动和成牌。格挡针对一条攻击意图，不是无差别角色护盾；敌人多条攻击要分别处理。
- 牌型从一对、两对、三条、小顺、同花、葫芦、四条、大顺到快艇，只取最佳一种。金／锈修正收益，**不提高／降低动作伤害**；累计到本层、清层结算，牌型加成上限+2，即×3。
- 玩家命点万能可为成牌取1–6；诺玛万能是动作选择，不是点数万能。四种花色为尘世／圣辉／深渊／界外；编队花色与掷出的同花不是同一判断。
- 铭约按宽判模式可多项同轮触发，与最终最佳牌型不必相同；执行顺序尤→柯→诺→艾→玛。拥有者须存活且未封锁，自己沉眠不必然阻止其他队友组成触发条件。

| 角色 | 战术与成长表达 |
| --- | --- |
| 玩家 | 补位、保护、唯一命点万能；走团队里程碑而非普通伙伴等级线 |
| 尤 | 稳定攻击；同花铭约打击高威胁目标 |
| 艾 | 恢复与资源取舍；三条铭约支援。越限治疗治2，只扣本层散金至多10，不动已入袋／长期钱包 |
| 柯 | 攻4／4／5的高爆发，Lv.1有三张沉眠空面；顺子铭约攻击，不是无代价法术机 |
| 诺 | 灵活攻挡治；两对＋实际空白动作面触发飞刀。名为淬毒的面并未实现中毒系统 |
| 玛 | 邻接顺劈、提线、绞杀、全体意图格挡；组合铭约有限自动重排敌阵。首次提线可阻止该敌当前行动，不可无限眩晕 |

所有现行角色最大3HP，普通新出征满血；伤势跨房保留，力竭本场不可复活，下场通常1HP归队并留下本趟临时锈。新出征清本趟状态，没有多日重伤养成。共鸣目前仅大地（清层金币×1.1）、雨夜之盟（四伙伴齐队，力竭后的格挡／下层归队增强）、天王威慑（当前玛，首轮敌攻击意图−1）。

### 5.2 两种当下副本与回忆

岩窟是独立教学 run：四战、战间故事、检查点重试；失败不发奖励、不推进时间。成功读完七槽后独立领取真实收益＋一次8G；不触发庄园首通、装备赠物、伙伴成长或玛亲征。三件追回物是叙事目标，不是可卖／可消耗库存。

庄园是五层手写固定路线，非随机房间系统：

| 层 | 初战 | 维护 |
| --- | --- | --- |
| 1 | 候席客×3＋迎宾簿 | 候席客×3 |
| 2 | 执盘侍者、缝补女佣、候席客＋遗物整理 | 同敌群，无该事件 |
| 3 | 落幕管家；可撤离 | 双执盘侍者＋缝补女佣；可撤离 |
| 4 | 三候席客＋缝补女佣＋空席核对 | 同敌群，无该事件 |
| 5 | 千金18HP＋初始两宾客 | 刻仪兽16HP |

千金“举杯”原始伤害为2＋活跃宾客数，清杂会实时降低意图；最多三宾客、总补席预算六，新召者当轮不行动、不产赏金。核心归零后解线，不要求杀光剩余宾客；首通另有一次20金币。维护不重新绑回千金或重演首通。刻仪兽现在主要还是蓄力→3伤，辨识度与压力待返工。

回忆是固定勇者五人、伙伴Lv.2、无装备的历史短战，最终刻仪兽14HP，局部药水／护符各2；不是当下五层复制，不打玛本尊，不发当前掉落，不扣当前资产，不推进普通远征时钟。完成战斗后还要当下收束才能开玛亲征。

事件目前是单人选择后独立抽一面并即时结算，不借上一战剩余骰。迎宾簿／空席核对为阅读或略过；遗物整理花本层散金2，强／弱保全成功均得4，可免费绕行。**多人“全队先掷→选1–2人→分档奖励”只有提案，尚未实现**；不能写成玩家已经操作过的机制。

### 5.3 金币、补给和成长不是日常对白的自由变量

- 资金分本层散金、本趟已入袋、小队长期金币。清层计入牌型、层深与共鸣倍率；整趟结算才入长期钱包。新档公款／金币／晶石为0；公款与晶石目前主要保留字段／展示，没有完整常规获取与消费链。
- 第三层合法撤离保留已入袋及剩余道具；团灭丢本层散金、已入袋留一半向下取整，剩余道具返回；通关正常带回。导航离开只是暂停，不是随时免费撤离。结算只发生一次。
- 七种道具、正式最多携带四类：食物4充能（单人回1，每人每趟最多两次）、药水2（回2）；战术补给是护符2（单意图挡2）、圣水2（解封锁）、保养工具1（清本趟临时锈）、幸运符1（本轮重掷＋1）、卦签2（揭示层／事件信息，不预知随机骰）。
- 食物／药水选中出发时基础补满；其余需库存，单次充能价格依次4／3／6／8／3金币，剩余返回。商店无出售、鉴定、砍价等正式闭环。追回草药不产生无限药水；原始经济设定不授权文稿自行定新价格。
- 成长由资格＋手写片段完成领取，不靠战斗经验条或连续好感值。伙伴随队参与合法第三层撤离／通关可获得Lv.2资格；已领取本人Lv.2且庄园接管后，再参加新一趟出征并合法归来才有Lv.3资格。玛须先亲征解锁再参加维护。现有五伙伴共十个成长事件，无Lv.4／5。
- Lv.2唤醒指定沉眠面、使指定面变金，Lv.3升铭约；任意两伙伴Lv.3使玩家护卫面一次变金，护卫基础强度不变。五枚羁绊晶石的外观不是隐藏0–100好感系统。
- 符合条件的普通归来有一次整备赠物：备用短刃／应急药囊各一。把原生空白动作分别改攻1／治1，保留醒眠、点数、花色和品质；仅尤／艾／柯／诺可用，每人一个实际通用槽，可装卸／转交，出征冻结。页面三格结构不等于三类装备都开放。

## 6. AVG、美术和界面：可以复用什么

固定故事走 JSON 数据→校验／编译→原 AVG／RP 舞台；作者定义节点、分页、演员、选项、分支、背景、少量静默动作及本地声音／物品键。**完整作者脚本的表达能力大于在线模型的输出权限**，两者不要混为一个格式。

在线最终正文目前是 `creationRecord` 与 `lines[{speaker, emotion, text}]`。支持旁白 `narrator`（仅 neutral）与当次白名单演员；不包含模型新造的跳转、奖励、场景程序或舞台坐标。`creationRecord` 是可见、简短的作品检查记录，不是要求披露隐藏推理，也不混进人物台词或记忆正文。当前在线上限32行、每行600字符、记录1200字符；这些是上限，非建议写满的篇幅。

14个标准情绪：`neutral smile joy sad angry surprised serious closed wry flustered displeased confident confused panicked`。单词由本地逐角色映射成表情、漫符和一次动作；不是模型直接挑图片／动画。10人基础差分与少数专属差分已有，专属别名不是通用生成协议。固定内容按自身合同可更窄，例如旧内容8／9的三情绪约束不能静默放宽。

| 资产／表现 | 已有可复用内容 | 缺口或误用风险 |
| --- | --- | --- |
| 角色 | 头像、纸娃娃／整身立绘、基础表情、角色页与队伍图、校准数据 | 角色有图不等于有战斗规则；整体立绘动画不等于独立手臂／骨骼动作 |
| AVG／RP | 原姓名与阅读栏、分镜、LOG／回看、情绪联动、席位与转场、物品小框 | 不另造聊天页面替代游戏舞台；S4 当前用 AVG，不自动获得所有首晨 RP 操作 |
| 场景 | 首晨洋馆背景、月下长廊、地图与商店图；S4 已切回洋馆图 | 场景中有厨房／工坊等视觉不等于生产设施已实现 |
| CG | 序幕15张、PNG源图／运行WebP、运镜、文字与逐镜恢复 | 音频、独立动作分层、严格16:9扩绘母版仍未完成 |
| 岩窟 | 复用洞穴背景、五类敌人 SVG 灰盒、真实控件教学画布 | 正式敌图、S2-6行军外景／地图切面、正式物件图与音频待补 |
| 庄园 | 7张敌人／Boss源图（含归档玛本尊）、3场景、地图地标、主题皮肤 | 千金断线／餐刀化灰／沉睡／抱起等拆层及姿态缺；不要把一张立绘当作这些都做完 |
| UI资源 | 既有边框、骰子、意图、日志、物品图标、品牌与工具台 | 保持现有主题、布局和校准；不以新工作台重设计替代内容工作，手机适配非当前重点 |

声音／触觉和必要观察可留短旁白；已有立绘动作能表达的内容，不再用长旁白逐句重复。战斗与重要故事通过原淡出／入场衔接；教程提示由真实控件高亮承担，不让老练同伴念按钮说明。需要新增资产先列清单，不能让模型输出外链图片、HTML／JS／CSS来补。

## 7. AI loop：三轴联动，而不是三个人格轮流说话

### 7.1 四阶与四型是不同维度

四阶是 `canon / bond / echo / ripple`：正典、羁绊、回响、涟漪。正典／关键关系节点／回忆以作者定稿为骨干；涟漪才是首版受控生成的重点。不能由一次闲聊跨越主线或关系阶段。

涟漪四型是出击 `sortie`、牵线 `liaison`、家务 `household`、小景 `vignette`，描述事件的参与方式，不是四个模型 Role。初征／再战／回响战／巡守又是准入与叙事情境，不另造四套战斗引擎。

### 7.2 三轴各自提供约束，并共同决定同一场景

| 轴 | 输入与作用 | 不能替代的事情 |
| --- | --- | --- |
| Agenda／时局 | 章节、真实结果、任务与承诺、未解决事情、错过余波、主题冷却；决定“此刻有什么可发生” | 不凭一个目标字符串自动完成任务或造奖励 |
| Bond／关系 | 关系基线、已解锁节点、真实选择、参与者有资格知道的确认记忆；决定“谁如何回应” | 不能把共享住处当作所有人知道所有秘密，不凭文风涨等级 |
| Locus／时空 | 游戏日／晨昼昏夜、地点、可达演员、已实现设施与占用；决定“谁能在哪里做什么” | 不使用现实钟自动推进，不让场景装饰变成生产系统 |

联动实例：接受药箱委托之后，维护路线指定房间完成且成功撤离／通关，Agenda 才有“带回”的依据；Bond 只携带这条分支实际确认的互动与选择；Locus 确认归来、公共休息室、可见人物及相位。模型据此写不同的归来反应，读完后的摘要才进入后续。不能把“打算去巡路”当全清，也不能凭归来猜途中无伤。

对 S4 的意义是：Agenda 收束货物任务并留庄园未决项；Bond 用物件回应人物牵挂与已选态度；Locus 从战斗切回家中、允许整备。**这是一种创作分析方法，不表示 S4 已接三轴在线生成，也不应让演员把三轴术语念出来。**

### 7.3 当前事件池与时钟的真实行为

8张手写工作稿：出击为艾的旧药箱、尤的巡路板、诺的旧帆布；牵线为艾→尤的两张整备表、柯→诺的铅笔；家务为艾的布卷、诺的绳结；小景为柯的热杯。三条出击均有真实房间与成功归来证据，第二层发现物件也要走到合法出口，不能凭空第二层撤离。

- 出击依规则绑定本趟与目标，团灭不能交付；牵线必须读完指定人的专属约谈再回委托人；家务／小景也需明确完成。普通装饰聊天和动画结束不构成完成证据。
- 完成当前只产生一次共同记忆与主题冷却，无额外金币、物品、好感或成长。三个唯一取回物不反复提供。
- 仅在存档创建、普通归来、剧情完成、事件提交等安全边界调度；查询／刷新不补卡、不写状态、不消耗战斗 RNG。必需正典／成长／回忆收尾与活动 run 占用优先处理。
- 每游戏日最多提供4张、活动最多4个、每型最多1个；型内优先历史提供次数少的定义。这是首版参数，不是体验配平结论。
- 普通远征结算一趟推进一相位，四相位一天；初章独立领奖也推进一次。回忆、普通阅读、模型等待不推进时钟；无手动跳时、实时离线模拟。公式为 `(day−1)×4＋phaseOrdinal`。
- 惰性提供期8相位，有后果4相位；接受后没有履约期限。从未曝光的惰性过期移备用，最早下一游戏日重查、新建实例；已见过期保留历史。有后果错过由确定性公共近况写明他人处理，不伪造玩家参与、不硬扣好感。
- 已解决、拒绝、已见过期、有后果错过使用主题冷却256相位／64日；不能换标题绕过。8卡很快耗尽，合成“立即完成”策略前256相位有253相位无新事件；这不是无限生活系统，也不是玩家实测时长。
- 四名首批伙伴在公共休息室四相位可约谈，是最小可达规则，不是完整 NPC 日程。既有房间时段展示不等于已形成全员动态生活模拟。

目标仍为20–30卡、两套配平巡守底板、4–6个预制特化、四型代表与多人知情差异。当前只有8张工作稿、复用维护路线及药箱两场在线；AI 不任意新增敌人、房间、目标或报酬。

### 7.4 固定模型流与上下文组装

这里的 user 是 UI 行动／用户输入／交互触发的来源，未必是主角说了一句话；AI Role 是规划、写作、格式等任务身份，未必等于一个角色。一个 Writing 可创作多人场景，最终通用文本／JSON资源再由游戏投影为逐句 AVG。

| 阶段 | 当前 scy-a 模型 | 输入与产物 |
| --- | --- | --- |
| Outline／大推理 | `claude-fable-5 [perplexity]` | 作者骨架、受控三轴、必要人物与记忆→纯文字因果与节拍，不用 JSON |
| Writing／文本 | `gemini-3.8-flash` | 大纲、人物／场景、文本专用预设→纯正文／台词／旁白，不写 JSON、变量或情绪字段 |
| Format／小推理 | `deepseek-flash` | 冻结正文、大纲辅助、演员映射→可见创作记录＋speaker／emotion／text；保留正文文字、标点、顺序，仅去行首标签／整理空白 |
| 读后 Updater／小推理 | 同一 `deepseek-flash` 槽、独立预设 | 可信已读正文＋授权 State＋政策→记忆／状态提案；**当前只授权本次 summary**，不是任意变量更新 |

格式错误回到小模型：保留同一正文／大纲，附上一轮格式化原文与具体程序错误；最多两次尝试，不重跑大纲／正文，不靠 Format 偷偷修辞。Updater 的格式修复同样有界；领域／权限拒绝不靠重试扩大权限。没有自主 Agent 循环，也不要求增加审稿 Agent 才能推进；未来审阅模型可以讨论，但不是人类逐条确认的必需门槛。

送模前依次固定 Release／规则／权限；投影合法游戏事实；读取精确分支的授权叙事状态；按三轴、知情、时间与来源筛选记忆；装入本任务骨架、资料与预设；由 rp 编译并留下实际输入证据。必需项缺失／超预算要失败，可选项可确定性省略，不能先塞全量秘密再要求模型“自觉保密”。

已有27份 Resource 草稿：20份原始世界／历史／势力／经济与骰参考／场景／人物／玩家资料，6份创作参考，1份来源索引。**入库不等于送模。** 药箱0.3.2实际使用4个来源、11个摘录、3个包内 Resource：人物＋公共场景进 Outline／Writing，专门对白规范仅进 Writing，Format／Updater不另读资料库。不硬编码本机资源 UUID，不把原文总集再重复注入。

提示词参考类酒馆预设，提取有效模块、启用顺序、宏依赖与插槽，不照搬所有脚本。基础任务／权限与文学特化分开；保留视角、口吻、节奏、正常虚构冲突和不说教的文本能力，不把所有创作检查一并删除；不做 NSFW、越过硬安全限制、防截断填充或破限模块。宏是编译占位，不是游戏变量。

当前 Pipeline 总预算16,000 tokens，Writing预留4,096输出；这是现行输入／输出上限，不是完整交互总成本。供应商／模型支持的格式和端口属于能力声明，角色任务才选择具体路由与执行参数；更换文学预设不应顺带改通用供应商配置。

## 8. “一切皆文件”、变量与记忆的准确含义

“文件”是可命名、可追溯、按定义有限编辑的资源／结果／状态视图，不要求所有东西都落成磁盘文件，也不是让 LLM 在后台修改项目代码。rp 可用原生数据库保存其版本与关系，前端用文件／代码块／差异视图表达；游戏美术与固定内容仍走仓库资源管线。

| 对象 | 权威与编辑／审计边界 |
| --- | --- |
| 人物、世界、骨架、提示词 Resource | rp 原生资源／版本；授权自有资料可编辑，包内程序与部分规则只读。保存草稿不等于发布，新 Release／Session 才采用 |
| 大纲、正文、格式结果 | rp 精确 Floor／Run／Result 留原文；人工修订是新修订，不覆盖历史。最终结果必须来自正确 Format，不取“最后成功一楼”猜来源 |
| Campaign、随机、资产、任务、冷却、成长 | Abyssa 合法命令／事务唯一写入；给 rp 有来源的只读投影。通用变量能力存在不等于模型获得这些字段的权限 |
| 接纳场景、阅读游标、选择 | Abyssa 冻结正文及来源，按规则持久提交；模型输出≠接纳，接纳≠已读，已读≠任务完成 |
| 叙事摘要／连续性 | rp 原生 State／Updater／Ledger／Checkpoint；当前小模型只填有界摘要，身份、依据、知情、状态由程序控制 |
| 派生上下文 | 按任务重新筛选的视图，保留来源与省略记录，不是新事实库 |

未采用输出也发生过模型调用，因此保留执行／用量／错误证据，未知 usage 不记零；但**不进入玩家经历、不产生采纳的状态变化或记忆**。审计是可追溯，不等于每个草稿都要人类点击批准。制作时审应用版本与样本文风，玩家运行一般由程序校验和真实阅读确认驱动，阅读确认也不是“审核变量补丁”的工作台操作。

记忆应分清：客观已发生事实、某人物的认知／猜测、未来打算、文学连续性；大纲与可见创作记录不是经历。先检查分支、来源有效性、接纳／已读、时点、知情与任务范围，再召回相关条目；共同对白首版使用共同知情切片。改稿只能在采用新稿的分支按规则失效／替代相关记忆，不能追改其他分支或已读历史。

rp 没有现成的全功能长期 Memory 产品，但现有 State Schema、权限、集合稳定ID、Updater、校验、账本与检查点足够支撑首版有界记忆，不需要另建向量库／图谱／Memory数据库。目前最多8条摘要，每次最多召回4条／4096 UTF-8字节，满额明确停止；不是无限压缩或长期记忆问题已解决。

现有应用还支持正文修订后重格式化、有限最近摘要编辑和授权资料派生；**Abyssa 玩家端尚未提供相应编辑／自动 Fork 界面**。原生分支用于替代历史与状态隔离，不自动等于 AVG 选项；一楼是一项语义动作，不是每次模型调用各造一楼，也不按角色建独立数据库。

## 9. 工程边界与恢复能力

Abyssa 仓库：`/Users/liuhang/Documents/project-abyssa`；rp 仓库：`/Users/liuhang/Documents/rp-style-lab`。

- `game-core` 负责纯玩法与验证；`game-application` 负责命令、事实、事务、回执和版本；`game-infrastructure` 接 IndexedDB／HTTP；`game-runtime` 绑定内容与查询；`game-client`／apps 呈现合法输入与提交后的演出；`content`／assets 保存具体玩法定义与作品。
- `llm/` 是 O1-W 离线作者工具，有七场任务上下文、Provider适配、候选与审稿记录，不是第二套在线后端。需要讨论 S4 不意味着必须再部署它或复制 rp Workflow。
- rp 通用层拥有 Application／Release、模型槽、上下文编译、固定流程、状态、楼层／分支／检查点、恢复和审计；`applications/airp` 拥有游戏人物、骨架、上下文语义、预设和领域校验。多人扩展先改领域合同，不重造通用平台。
- Abyssa 玩法档在浏览器 IndexedDB；rp 运行／叙事状态在后端原生记录。不是把整个 Campaign 都迁到 rp，也不是只靠浏览器黑盒生成。两者不同字段各有唯一 writer，通过精确引用衔接。
- 调用复用 `/api/v1` 下的 Session／Interaction／Timeline／Run Result 等原生接口，不从游戏直调 Provider。发送前持久化请求身份，接纳时核对存档／epoch／head、内容、任务、Release、Branch／Checkpoint及精确结果。
- 两端不是一个原子事务。生成成功后先合法冻结正文，最后一条实际阅读产生确认 ticket，再提交 required Updater；确认不明时重放同一身份，依赖记忆的下一场必须等确认，失败不回滚已完成战斗。
- 同一 Interaction 幂等重放不增调用；切档／迟到响应不能写进新场景。手写降级须明确并冻结来源，后来返回的模型稿不可替换已经展示的版本。
- 当前 Session 创建没有后端原生幂等键；同origin Web Locks＋精确身份查回解决已验的双窗口场景，不是跨设备强保证。在线档原身份恢复可用，新身份复制／新周目／自动Fork接线未完成。
- 默认旧档受内容引用／摘要与严格reader保护，升级保留原档，不热迁移活动战斗。战斗保存RNG与敌队列，规则4在掷骰／重掷等边界清撤回栈，不能看随机结果后任意反悔。
- 本地后端基线是 `127.0.0.1:8787`；公网认证、TLS、访问隔离、限流与费用控制尚待独立建设。不要向浏览器提供 Provider 密钥；客户端 hash 校验不是防作弊或可信云资产保证。

容量也是正式边界：内容9全包8 MiB、叙事4 MiB、128实例／128场景；当前内容10在线记录最多2场／512 KiB，后端摘要8条。扩到多人／四型须共同演进版本与保留／恢复策略，不能只把 UI 的数字调大。

其余页面有意保留边界：洋馆有场景、共享资产、归来／成长，但建设／修缮／生产／手动跳时为空实现；码头骰局有独立五骰博弈但资金不接 Campaign；novel／rp 是表现样例；settings 未形成完整持久设置链。热区、立绘校准、Logo、骰面工作台是作者工具，不是玩家成长系统。

## 10. 最近验收说明了什么，没有说明什么

0.3.2 已验证“侧门撤离／完成巡路”两情境各归来＋后续，四场经过真实 Outline／Writing／Format 和读后 Updater：16次完成调用、4条摘要，Format正文保真、精确重放、后续召回及原AVG展示通过。另有2次历史取消，用量未知；本批保守18／24次，已知完成用量74,193 tokens，不是费用结算，也不授权继续消耗剩余额度。

生成四场约77–128秒，读后摘要约11–20秒；是分钟级样本，非即时对话，也不是性能分位数。本轮无真实格式修复重试，修复链由隔离测试证明，不能把未发生的重试写成实测通过。

内容仍未通过：完成／撤离区别不鲜明，后续误把邀请当此前已经确认的行动，推断玩家意图，新增无来源具体维修价格，继续围着搭扣重复节拍。Format忠实封装、Updater忠实概括不能使上游错文变正确。修订重点在作者骨架与 Outline／Writing，不把 Format 改成暗中重写器，也不让 Updater 删除玩家实际看过的内容掩盖问题。

S4 是另一条**作者内容质量线**，不受这个在线单样本模型配置阻塞。可以现在讨论／精修，但不能说0.3.2已经生成或验收了 S4。初章 O2-T规则与O3-T接线完成，O1-W正式文稿、O4-T真人试教未完成；庄园压力／刻仪兽辨识度／成长与回忆剧作／缺图和声音也仍需制作。整体约40分钟是目标，不是已经测得的完整玩家时长。
