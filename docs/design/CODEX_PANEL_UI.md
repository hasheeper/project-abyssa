## 2. 页面组织

保留第二张的完整页幅。视觉先看到观察图与名称，再阅读简介与资料，最后进入记录与掉落。局部尺寸随文字和对象体型调整，不将史莱姆的长宽比例写成所有条目的固定模板。

| 区域 | 内容与组织 |
| --- | --- |
| 全局外壳 | 复用 Menu 左侧导航、标题和背景；顶部保留生物、地点、器物、世界知识四个分类。首期只激活生物，其余按用户要求保留不可切换的占位 |
| 图鉴目录 | 缩略图、名称、编号；当前条目有清楚的轻切角选中边界，普通条目减弱盒子感；固定行高，长名称可换行，列表独立滚动 |
| 观察图区 | 一张完整的观察草图，保留主体周围呼吸空间；编号作轻附注；按可见轮廓等比适配、放大，主体清楚、四角与外围渐淡 |
| 右侧资料 | 名称与少量分类信息 → 简介 → 有内容的结构化资料 → 已知掉落；统一左边界、字级和纵向节奏，长内容在此区滚动 |
| 下方记录 | 横向联系目录与观察图区，保留低对比切角边界；承载观察补充或已收录笔记，避免与简介复述；没有记录时不以虚构引言填充 |

主图承担第一张轮廓画的辨识度，底部不再重复摆放一只完整的同款生物。按用户补充参考恢复低对比轮盘：同心圆、少量刻度和四个轴向节点位于主体后方，圆环弱于主图描边；按动效阶段的最新反馈，切换时扩散、旋转、聚焦，静止时恢复轴向对齐。灰绿微光托起主体与轮盘，不给主图增加发光描边。

观察图按形体横向视觉重心定位，先裁去 AI 画布的空白，不能直接把原始画布缩进固定框。图像要撑住主图区，同时给细高或横宽对象保留不同的显示比例。主图后的光晕范围宽、边缘柔和，不能看出另一块椭圆底板。底部记录与草图之间保留清楚间隔，目录滚动不穿入记录区；无记录时不绘制空框，空间归还可用页幅。

缩略图使用同源观察图的简化版本，保留适当明暗，确保缩小时能辨识。掉落使用项目已有物品图标，按用户要求每行四格；四格采用相同边框、背景和名称基线，样页不足四格的位置以问号表示尚未记录，仅问号与文字稍淡，保持整排重量均衡。问号仅为展示占位，不代表掉落表中的“无掉落”结果，也不写入收录进度。页面只有选中条目、主图与标题承担主要对比度。

## 3. 早期程序试制：带明暗的观察草图（保留作对照）

本节记录此前的算法路线；当前成品方向以文首的 AI 单色线稿为准。

目标是保留轮廓与内部结构、压低厚实色块、以少量明暗支撑形体。主图具有足够的线条强度与体积感，暖灰线融入 Menu；“若隐若现”主要体现在次要笔触和淡彩边缘，不能把整个主体压到难以看清。

纯轮廓不足以承担主视觉：史莱姆的大面积内部会空，复杂怪物则可能碎。最终方向采用“主要墨线 + 有选择的内部结构 + 少量明暗／原色淡彩”，强弱顺序为主图结构、辅助细节、底部装饰。原有贝壳、碎石、褶皱等特征来自原画，保留到足以认出对象即可。

线色偏暖灰，正文保持暖白，界面边界继续灰绿。透明感来自分层的墨线和淡彩，避免整体透明度降低造成幽灵感。主体内部以随形体变化的暖暗底层压住走廊纹理：略亮于局部背景、明暗起伏克制，避免成为均匀的实心剪影。遮罩保持在轮廓以内，按实际显示尺度轻微向内过渡，不向外冒光晕；细小泥滴同样保留形体。没有发光描边、整体反相、纸底或人为叠加的排线；可保留源图本身的笔触。

### 离线算法路线

当前 v5 程序试制已覆盖潮礁 7 张、洋馆 7 张（含旧版回忆素材）和早期敌方素材 3 张。素材清单和生成器共同检查来源覆盖，复用同一原画的遭遇去重。依赖见 `scripts/requirements-codex-observation.txt`（Pillow、numpy、scipy）。

1. **统一分析尺度。** 按 alpha 可见范围等比适配 550×380 主图框，以两倍分辨率计算；保留全部可见部位及离散碎片。以墨线距离场估算笔画宽度，避免不同原画尺寸套同一滤波半径。
2. **整理透明边缘。** 输入是 straight alpha；只在重采样时使用线性颜色预乘，不对原图错误反预乘。透明区域用最近有效边缘颜色延展。外轮廓沿 alpha 内侧生成，宽度与明暗略随原色和方向变化。
3. **提取并分级线条。** 从局部对比及方向一致性生成墨线候选；骨架在交叉点拆段，以长度、对比和简化区域边界对齐度排序。使用局部密度限制选择线段，按固定显示线宽重新绘制，避免粗暗笔画变成整块亮斑。区域图只给原线评分，不凭空增加等高线。
4. **保留有限明暗。** 按每张素材亮度分位归一并压缩暗部，略带回原色。修补转换成浅线的区域并限制高频纹理；少量紧凑暗点独立保留。这部分混合色调仍未达到用户要求，后续优先改用 AI 单色线稿成品。
5. **统一颜色与透明度。** 浅墨线、alpha 内侧轮廓、暖暗淡染分别计算后离线合成。保留规范化来源的 alpha，不向轮廓外发光，不叠随机噪声或排线。
6. **分别导出大小图。** 主图和 82×62 缩略图独立按两倍显示尺寸抽线，缩略图减少碎线并略抬明暗。无损 WebP 记录来源 hash、参数版本、视觉重心、落地锚点和产物 hash；运行时加载成品，不运行图像算法。

线稿算法不能理解生物解剖，也不能从一张正面图生成可信的侧视、剖面或新的观察细节。若首轮结果显得像滤镜，应回到线条选择、明暗占比和必要的局部遮罩修正；不能把增加噪声或发光当成“手绘感”。只有样图通过后才固定默认算法及参数。

原画沿用现有资产身份。衍生素材通过[清单](../../src/assets/codex/observations/catalog.json)显式关联原图，不替换战斗素材，也不通过标题关键词寻找主图。入库遵循[素材命名合同](ART_ASSET_NAMING_CONTRACT.md)。

## 4. 交互与动效

图鉴采用同页选中阅读：目录始终可见，选中条目只更新主图和资料，不增加“目录页 → 详情页”的布局伸缩。目录保留滚动位置，分类恢复各自的选中项；内容不可用时区分未收录、无此资料与加载失败，不重复铺满问号。

### 当前实现与本轮范围

2026-10-02 已结合真实界面与 Opus 5.5 完成两轮动效讨论并实施。实施中用户进一步明确：“扩散，旋转，聚焦”，并要求淡入淡出服从同一关系。以下以此最新要求为准。顾问两轮原答保存在 [动效咨询原稿](codex-concept-2026-10-02/opus-motion-discussion.md)，实际切换录帧见 [动效预览](codex-concept-2026-10-02/ui-motion-expand-focus.webp)。

当前实现：目录选择即时响应，所有条目内容先归零、再一次提交新内容，保持一个主图节点和四个掉落格位。整页使用独立的 1000ms / 620ms 编排；内部切换 180ms 扩散淡出、500ms 聚焦淡入。主图、标题、资料、编号和记录同步交接，轮盘的转动与这段 680ms 过渡一起完成。

### 动作语言与固定层

保持当前页幅，内容在原位分层显现。轮盘最多扩张约 6.5%，伴随轻微失焦与减淡，再旋转、收回聚焦；每次前后切换按方向转过 90°，停稳时四个轴向装饰重新对齐。主图最多扩张约 2.5%，随旧内容散去，再由新线稿聚焦；正文只按节奏交接。线稿尺寸、B 版线宽、颜色和四角／外围遮罩在稳态完全恢复，底光持续托住观察区。

| 层 | 整页切入、切出 | 内部条目切换 |
| --- | --- | --- |
| Menu 背景、左侧全局导航与栏目大标题 | 由原 Menu 转场负责 | 保留 |
| 图鉴顶部分类、边界、固定栏标题、记录框、掉落格位 | 作为结构层淡入淡出 | 保留 |
| 左目录 | 整组显现，不逐行排队 | 选中反馈立即响应，滚动位置保留 |
| 轮盘 | 切入由散到聚并转动，切出扩散淡去 | 扩散、转动一格、聚焦停稳 |
| 底光 | 随场景淡入淡出 | 保留 |
| 观察线稿、名称、编号、族别、简介、情报、记录内容、掉落内容 | 分组显现 | 同一条目同步交接 |

大名称最多约 0.8px 模糊，主图切入最多 1.5px、内部切换最多 2.2px；正文、标签、编号与细边界仅改变透明度。新主图的模糊和扩张先归零，透明度稍后完成。没有文字位移、缩放、径向揭示或逐笔描线；轮盘仅在进入和条目切换时运动。

### 切入：约 1000ms

页幅先建立，观察台随后出现，名称与资料沿阅读顺序接上，线稿最后落稳。各组大幅重叠，名称约在开始后 400ms 已可读。

| 时间 | 内容 |
| --- | --- |
| 0–320ms | 顶部分类、边界和固定栏标题显现 |
| 80–480ms | 左目录整组显现 |
| 120–800ms | 轮盘、底光到达当前稳态；轮盘在前 680ms 转回轴向并聚焦 |
| 180–1000ms | 主图原位显形，模糊约在 760ms 归零 |
| 200–600ms | 名称、英文名、编号、族别与标签 |
| 260–680ms | 简介 |
| 320–760ms | 已知情报 |
| 380–820ms | 底部记录、四格掉落内容与 footer |

主 Agent 将顾问稿中“情报先于简介”的次序调整为页面实际的从上到下阅读顺序。初始条目只走整页入场，不再叠加一次内部条目动画。以上是图鉴自身时长；落地时要连同 Menu 的上一栏目退场核对点击后的完整节奏，避免额外等待。

### 切出：约 620ms

采用独立的两拍退场。文字先收，主图稍作停留，结构最后消失。

| 时间 | 内容 |
| --- | --- |
| 0–360ms | 目录和条目文字、记录与掉落内容近乎同时淡出，组间差不超过 30ms |
| 140–560ms | 主图轻微扩散、失焦淡出，模糊上限 2px |
| 180–600ms | 轮盘与底光淡出 |
| 220–620ms | 顶部分类、固定栏标题、边界与记录框淡出 |

各层归零后由 Menu 卸载。退场曲线尾部平缓，不能在仍然可见时直接删节点。图鉴返回主菜单时，共用底景的撤出要跟上这段时长；图鉴切到设置／记忆时，共用底景继续保留。

### 内部切换：约 680ms

一次切换属于一个完整条目。目录先回应操作；旧内容归零后一次提交新条目，再按名称、简介、情报、附注的顺序显现。

| 时间 | 内容 |
| --- | --- |
| 0ms | 更新目录选中目标，选中底色约 90–120ms 过渡 |
| 0–180ms | 旧主图扩散、失焦，所有旧条目内容同步淡出；轮盘扩张并减淡 |
| 45–680ms | 轮盘按选择方向转动 90°，后段缓缓停住 |
| 180ms | 一次提交新条目；编号、族别、目录索引计数与内容同步；资料区在不可见时回顶并完成排版 |
| 180–680ms | 新主图与轮盘收回聚焦、淡入；主图模糊约在 530ms 归零 |
| 210–510ms | 名称、英文名、标签及条目附注 |
| 260–580ms | 简介 |
| 310–630ms | 已知情报 |
| 360–680ms | 底部记录与四格掉落内容整组显现 |

底光、框线与固定栏标题全程保持。图像先退后进，避免两张复杂轮廓叠成一团。简介保留三行的基本高度，短描述不会让情报标题突然上移；文字盒子直接采用新内容的最终排版。底部图鉴记录采用整栏正文宽度与自然换行，不再为参考图中的评论句预留右侧空位，也不均衡拆成两行。掉落四个外框持续存在，仅内部图标和名称更换。顶部三个占位分类保持不可交互。

### 连续输入、接线与验收

- 目录目标与实际展示条目分开。淡出期间只覆盖最新目标，不重启动画；淡入被打断时从当前可见程度退出。所有内容归零后统一提交，方向键与 Home/End 复用同一规则，不增加连按专用模式。
- 整页退出优先于条目切换。中断时从各层当前透明度接管，不能先补满或重置为零；返回原栏目也保持连续。
- 复用现有 Menu 生命周期，并给图鉴独立时长和进退编排。源码中的 `SystemSceneMotion` 实际仅含 `clock / exiting / skip`，宿主 `useMenuView` 仍负责切页与卸载。`MenuSystemBackdrop` 已同步图鉴时长。
- 减少动态效果或页面隐藏沿用当前 `skip` 即时稳定。稳定后清掉临时滤镜和图层提示；不改变现有键盘焦点与 Escape 层级。
- 预加载不阻塞整页进入。当前 14 张主图合计约 2.26MiB，当前图先准备，其余后台解码。新图尚未解码时保留观察台，新文字按新条目展示；图像就绪后渐入，旧请求不得覆盖最新选择。
- 动效验证：全目录、键盘、快速点选、不可见时提交与回顶、中断恢复、轮盘扩散和方向、减少动态效果均有测试覆盖；Menu 20 项回归曾通过，本次接线后追加核对图鉴、记忆、设置三个正式入口。类型检查与 motion:check 通过。真实浏览器核对了史莱姆到礁蟹的切换，以及图鉴／设置之间的进退场；未声称逐张录制全目录。

目录聚焦反馈与悬停一致，底色约 120ms 淡入、160ms 恢复。物品补充信息继续采用项目已有的通透浮层；原图／草图切换、拖动旋转和自动轮播不属于首期交互。

## 5. 内容接入边界

当前 [MenuPage](../../src/apps/menu/MenuPage.tsx) 与 [useMenuView](../../src/apps/menu/useMenuView.ts) 已可承载图鉴样页，复用 Menu 容器、共用底景、标题及进退场。正式游戏的图鉴入口仍为占位；开发模式访问 `#/menu?codex-preview=slime`，首选史莱姆，可从目录切换当前 14 项。预览不写入玩家收录进度。

条目身份取自潮礁／洋馆展示表及早期内容目录；区域、行动和明确掉落表用于预览资料，观察简介依据真实原图编写。除史莱姆沿用洞口记录外，其余记录暂由区域与行动资料组合。它们尚未成为正式图鉴文案合同；旧版素材显示“旧版记录”，完整视觉覆盖不等于正式全量收录。

现有资产展示表提供原画和基名，内容数据提供遭遇定义、数值和掉落表。图鉴应按稳定的条目 ID 聚合同类资料，显式关联相关遭遇与素材；素材 ID、物种条目和单次遭遇仍是不同身份。尚未发现完整图鉴查询、收录状态和观察文案合同，须在数据阶段补齐。

参考图中的“下水道”“软体生物”“碎石掉落”“观察者笔记”等尚不能视为正典。已查到的 `table.loot.mire` 包含凝胶、贝壳及无掉落；其来源仍绑定房间槽位，不能简单将房间所有掉落算给每只敌人。“无掉落”的抽取结果不是物品，不占图标格。后续从真实数据建立明确关联；空字段直接省略，观察文案另行核对。

浏览页面只读。正式收录与旧档恢复需要可证实的游戏事实，不能因展示过开发样例便写入玩家进度。首期以生物页面完成整条链路，地点、器物和世界知识仅保留可扩展的分类设计。

### 5.1 收录规则与存档合同（2026-10-02 已接入）

用户确认展示与动效后，正式收录采用两次升级：**首次遇见收录基础观察，首次击败开放完整资料。** 重复遭遇、重复击败不再触发图鉴更新反馈，战斗自身的经历与结算照常记录。

| 状态 | 触发条件 | 当前页面展示 |
| --- | --- | --- |
| 未遇见 `unknown` | 当前存档没有有效遭遇依据 | 保留稳定编号与未收录占位，隐藏真实名称、缩略图、观察图和资料 |
| 已遇见 `seen` | 该条目对应的敌人首次实际进入已提交的遭遇，或在战斗中被召唤出来 | 名称、缩略图、观察图、外观简介、形态特征与本次遇见的地点；行动、完整出没资料、掉落与深入记录保持未解锁 |
| 已击败 `defeated` | 对应敌人首次满足有效击败条件 | 开放该条目配置的全部资料，包括行动、出没区域、可能掉落与图鉴记录 |

“展示完整”指开放已经配置并核对的内容。击败后可以看到已知的可能掉落，无须先实际获得每种物品。没有配置的资料仍使用原有空状态，不编造文案或物品；四格掉落布局继续保留，未有资料的位置使用问号，确认为无掉落的对象应明确显示无掉落。此类内容空缺与“尚未击败”的进度锁分开表达。

同一条目在当前有效存档历史中取最高状态。状态更新按物种条目去重：同场两只史莱姆只收录一次，后续换房间遇到同类也不重复更新。首次遇见与首次击败可在同一次提交中完成，此时直接进入完整状态，更新反馈合并一次。重新打开图鉴、刷新页面、读档或重放同一请求只恢复状态，首次收录的反馈仅在新的玩法提交成功后出现。

### 5.2 遭遇与击败的依据

- **遭遇：** 从已验证的遭遇状态确认实际出现的敌人定义；不能扫描整张地图、整个内容目录或未来房间。`encounter-started` 本身只有遭遇 ID、层与房间，需要结合对应的执行状态。召唤产生的新对象同样可以首次收录。
- **普通敌人：** 有效的 `enemy-defeated` 对应到实际敌人实例，再解析它的 `definitionId`。不要求整场战斗获胜或整次远征结算：先击败一只敌人、之后撤退或团灭，已经生效的该次击败仍算收录完成。
- **洋馆 Boss：** 现有规则不发普通 `enemy-defeated`，而是在核心归零后发 `enemy-released`。只有核对到 Boss 身份、HP 归零与有效核心解除时，才为 Boss 补全资料。仍活着而被一并解除的候席客等对象保持已遇见；此前已经实际击败的对象保留完整状态。
- **可结算的历史战斗：** 这是正式玩法，与菜单里的回想播放分开处理。Boss 的耐力耗尽由 `memory-endurance-depleted` 表达，并以有效 `memory-ended` 胜利终结确认补全；伴随终结退场的存活侍偶只算遇见。同步团灭按现有失败判定处理。
- **撤销：** 击败或召唤所属的操作被撤销时，查询排除该操作的收录贡献。若这是唯一击败依据，回到已遇见；若别处已有有效击败，仍为完整。遭遇开始依据未撤销时不因撤销攻击而失去基础收录。

来源以[正式应用提交](../../src/game-application/versions/d5-service.ts)、[旅程证据](../../src/game-application/versions/d5-journey-evidence.ts)、[战斗证据](../../src/game-application/versions/d5-combat-evidence.ts)与[存档验证](../../src/game-application/versions/d5-validate.ts)为准。AIRP 文字提及某生物不等于遇见或击败；正式玩法须提交上述结构化依据后才升级图鉴。

### 5.3 与存档的关系

**图鉴属于当前游戏存档，随这份存档保存与恢复。** 首期以已有的有效游戏事实为唯一进度来源，由只读查询推导收录状态；不增加一份独立的全局收集记录。遭遇／击败的玩法提交与存档已有的原子事务共用，提交失败不解锁，恢复成功的提交能恢复相同图鉴。

| 操作 | 图鉴行为 |
| --- | --- |
| 自动保存、刷新或关闭后继续 | 恢复当前存档最新已提交的收录状态 |
| 手动保存 | 保存该时点的状态，沿用现有完整存档副本流程；后续原档的击败不回写旧副本 |
| 读取较早的手动存档 | 回到该存档当时的遇见／击败状态，后来的解锁不穿越读档 |
| 导出、导入与完整恢复 | 随有效玩法证据一起恢复，保持当前已有版本与身份验证规则 |
| 切换另一份存档 | 重新查询对应存档，目录、选中项与缓存不能沿用另一档的解锁状态 |
| 新游戏 | 从未收录开始，各存档进度独立 |
| 已支持的同旅程副本／版本升级 | 查询保留有效来源历史，再叠加当前记录；不新增现有应用未支持的迁移路径 |
| 新周目 `cycle` | 首期按新旅程重新收录，来源追溯在周目边界停止 |

旧档没有图鉴字段也可以恢复：从已验证的遭遇、击败及必要的来源历史重建。缺少身份对应或可靠击败证据时，仅显示可证明的阶段；不能由通关标志、已拥有的战利品、角色总击杀数或素材存在反推所有条目已击败。

存档依据见[手动存档副本](../../src/game-client/manual-save.ts)、[存档来源继承](../../src/game-application/versions/d5-lineage.ts)与[完整恢复](../../src/game-application/versions/d5-restore.ts)。读取时沿用已有校验与来源合同；进度缓存绑定有效记录及内容版本，不仅绑定存档槽位。

### 5.4 身份与内容接入

条目采用稳定的 `entryId`。建立明确的 **敌人 `definitionId` → 图鉴 `entryId` → 展示素材** 对应关系，单次敌人实例 ID 仅用于找到该次遭遇里的对象。

例如正式潮礁的 `enemy.tide-reef.slime` 与素材 `enemy.slime.mire` 不是同一个 ID；普通刻仪兽 `enemy.old-manor.clockwork-beast` 与历史战斗的 `enemy.memory.clockwork-beast` 可以通过明确映射收录到同一刻仪兽条目。共享原画本身不表示同一对象：旧日侍偶与候席客的素材复用不能自动合并收录。名称关键词与 `artId` 均不能替代身份合同。

正式内容与当前 14 项美术预览分别核对。只有对应当前可用玩法或可读取历史的条目才进入正式收录目录；纯旧版美术不因已经做好观察图便默认开放。暂未有正式敌人定义的条目保持内容待接入，不伪造遭遇。

只读图鉴查询已返回：稳定条目 ID、当前阶段、首次有效遇见的来源与时间、首次有效击败的来源与时间，以及该阶段允许展示的资料。首次来源保留事实身份与内容版本，供恢复与去重；预览数据继续与此查询隔离。基础外观介绍与击败后的遭遇记录分开提供，锁定的名称、行动、掉落与记录直接从查询结果中排除，不靠模糊或透明度隐藏。

### 5.5 教程、回想与调试

实际游玩教程按真实遭遇与击败收录。跳过教程仍按现有规则获得教程记忆，但不补造未发生的遭遇或击败；记忆可以回看与图鉴已经补全是两种不同的进度。菜单回想、开发图鉴预览和纯展示场景都只读。

调试战斗的结果保留在它所属的调试存档，预览不得写入正在游玩的正式存档。D5 的 `origin: memory` 是可结算历史玩法的合法来源，不能把所有 memory 来源一律排除；是否收录应按真实玩法证据判断。
