# ABYSSA 非 LLM 主角行为与占位符契约

更新：2026-09-08。本文约束所有固定剧本、洋馆驻在、回忆、成长事件与地牢剧情。LLM 内容可以读取同一身份，但不能反向改变确定性游戏存档。

## 1. 三层行为模型

1. **物理动作层**：做饭、收拾、拔剑、递物、敲触手等可观察动作自动发生，不附加解释性台词。
2. **群像运转层**：对话优先交给少女角色。主角只作为环境与行动锚点，不承担吐槽、说教、机制讲解或连续捧哏。
3. **关键抉择轮**：事情无法继续时才出现选择。每场最多两次，每次提供三种具象行动，分别对应指令、拿捏和包容；选后最多显示一句极短定调台词。

## 2. 玩家身份边界

- `kael` 只作为旧存档、骰子所有权、队伍、素材与战斗规则的稳定兼容 ID，不是可写入剧本的固定玩家姓名。
- 固定内容使用 `{{user}}`。当前尚无命名流程，最终展示边界将它解析为“你”；未来接入档案名时只替换解析值。
- 活跃剧本不得自动生成 `characterId: "kael"` 的普通台词。玩家台词只能来自已经选择的关键抉择结果。
- “勇者”“队长”“勇者大人”属于情境称谓，可以由其他角色使用。

## 3. 洋馆边界

- 玩家不进入驻在角色表，不生成可点击头像、固定日程或按时段对白。
- 房间可以保留已经发生过的环境痕迹，不能借房间说明规定玩家此刻在哪里、正在做什么或每天必须做什么。
- `kaelHut` 等历史区域 ID 可为存档和地图标定继续存在，玩家可见名称必须保持中性。

## 4. 存档契约

- 关键选择记录为 `iron | seasoned | pragmatic`，同时保存故事节点位置。
- 旧档没有选择字段时按原事实重放；只有实际作出选择后才写入可选字段，避免改变旧快照的规范 JSON。
- 跳过仍可直达既有终点，不伪造某一种态度；回看优先展示已提交的选择。

## 5. 内容检查

- 六节点成长／赠物事件保持既有奖励游标，每段恰好一个三极选择。
- 活跃成长、回忆与庄园终局不得包含固定玩家姓名，不得在普通节点让兼容角色自动发言。
- 每个选择必须有三项、包含可观察动作；选择后的短台词不得承担背景解释或说教。
