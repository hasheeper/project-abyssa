## 1. 本阶段要交付什么

交付一个实际可访问、地址稳定的 HTTPS Demo：玩家打开网址，通过“新的开始 → AIRP 快速体验”建立内容18档案，自行导入 API 地址／Key，完成真实药箱委托、归来三阶段对白、读后记忆和一次后续；刷新、存读档及备份恢复不丢失已接纳结果，也不自动重新付费。

验收对象是**最终交付的 Origin 与同一份发布产物**，不是 Vite 开发服务、临时代理、localhost 或另外一套试读页。公网 HTTPS 不等于所有人的 API 都能使用：只承诺在明确记录的浏览器、网络、端点与模型组合上实测通过。

完成条件：

1. 正式 HTTPS 地址、证书、路径、资源加载及发布版本可核对；不要求玩家在本机启动项目。
2. 正常浏览器直接访问玩家提供的 HTTPS Chat Completions 端点，正式 Origin 的预检与实际响应通过；不使用 rp、新代理或关闭 CORS 的浏览器。
3. 至少一条真实委托路线在该 Origin 完成两场对白及两次记忆更新；两个既有结果分支均在该 Origin 验证档案恢复，不为部署重复生成全部 P2 文稿。
4. 已生成正文、支持段落、两项叙事标记、来源与全文输入哈希可追溯；完整作者资料与现有阶段分工不变。
5. 刷新、跨 Origin 手动迁移、同档并发保护及发布更新／回退有证据；凭据与私有档案不进入站点或公开报告。
6. 提供玩家使用说明、维护者发布／回退说明和脱敏验收记录；明确仍存在的文学瑕疵与全仓测试例外。

## 4. 托管选择与实施前决策

### 4.1 推荐路线

**独立静态站点、根路径`/`部署、平台提供的稳定HTTPS域名，首选评估Cloudflare Pages的产物直接上传方式。** 优先上传已检查的游戏产物，不为本次验收连接整个dirty工作树、推送仓库或增加CI自动发布。若用户已有Netlify／Vercel／其他合格静态站项目，优先复用其明确授权的独立测试站点。

选择标准是HTTPS、正确MIME、自定义响应头／缓存控制、可核对的部署版本、原子切换或等效完整发布、可回退以及目标玩家网络可访问。平台具体功能、套餐、配额和上传方式须在P3-A按当时官方说明与账号状态核对；本计划不承诺免费额度、可用域名或中国大陆网络质量。

本轮先不购买域名、不改已有生产站DNS、不启用付费套餐。若需要这些动作或现有项目会被覆盖，先另行确认。平台账号由用户登录，账号凭据不填进模型测试配置，也不发在聊天中。

### 4.2 发布前确认项

| 决策 | 建议 | 未确认时可以做到哪里 |
| --- | --- | --- |
| 平台／项目／账号 | 新的独立静态测试站，平台稳定域名，根路径 | 可完成本地发布检查和脚本准备；不创建资源、不上传 |
| 分享范围 | 明确“任何持链接者可访问”或“仅平台访问控制下的受邀人员” | 可出完整文件清单；不把未授权作者资料交给外部托管 |
| 最终Origin | 尽早确定一个稳定地址，测试与交付使用同一Origin | 可做本机根／子路径测试；不能声称公网CORS／存储验收通过 |

静态客户端必须把使用中的设定、角色卡、预设与美术交给访问者浏览器，打包／压缩／关闭目录列表不能保密。Key不泄漏不代表作者资料不公开；“不公开链接”或`noindex`也不是访问控制。即使用平台访问控制，已授权访问者仍能取得这些资料，内容也已上传给托管方。

若作者资料不能上传或交给受邀浏览器，本方案在该条件下不成立：停止发布并讨论范围，不悄悄删原文或另建后端绕过要求。

## 5. 发布产物与安全门禁

### 5.1 只发布经过检查的`dist/game`

1. 记录源码基线／dirty差异摘要、Node／npm版本和构建命令；所有关联改动及未跟踪源码都纳入本次可重建基线，不能只记录一个并不包含它们的Git提交号。保留用户无关改动，不自动提交或推送。
2. 用`npm run build:game`生成目标，再执行`npm run check:output -- game`及相关回归。生成逐文件路径、字节数、SHA-256与总清单哈希；发布ID同时绑定源码基线和产物，不把清单版本当成Git版本。
3. 审阅**全部**文件，包括复制自`public`的参考图、JSON和元数据；缓存清单只是其中一部分。默认不在构建后临时删文件，因为现有产物检查仍要求部分参考图／图层。需要排除不应公开的资产时，单列最小构建调整并重建、重验依赖与清单，不能上传后才决定。
4. 发布输入只能是检查过的`dist/game`快照及必要的平台配置；禁止项目根、整个`dist`、`config`、`st`源码目录、`node_modules`、源码地图、私有报告和档案作为额外上传内容。作者原文已在运行产物内的部分按第4节确认，不误称排除源码目录就没有原文。
5. 上传前在本机扫描Key、认证头、用户端点、私有文件名及意外配置；凭据只在内存参与比对，报告只写通过／失败与安全的文件定位，不打印匹配内容。检查压缩包内容和所有文本产物，不能只靠`.gitignore`。
6. 上传后核对目录中应有文件、响应状态／MIME和实际内容哈希；确认压缩传输解码后字节不变。关闭会改写JS、HTML或图片字节的托管优化／脚本注入，否则会破坏资源哈希。

私有文件没有进入上传集合是第一道门禁，路由404是第二道门禁。请求`/config/airp-test.local.json`、`/dist/reports/`、`/reports/`及已知私有档案路径应返回真正的404／拒绝访问，不能由SPA fallback返回200首页掩盖问题。

### 5.2 凭据、档案和证据的边界

- 玩家从本机文件选择器导入[测试配置](../../config/AIRP_TEST_CONFIG.md)。不把配置放网站目录、不通过URL参数传Key、不上传给静态托管方。
- Key只在当前页面内存，SPA切页保留、整页刷新清空；不进入localStorage、IndexedDB、Cache Storage、存档、日志或报告。模型请求正常发送给所配置服务商，这一点须在说明中写清。
- 浏览器站点代码能读取玩家交给它的Key；BYOK不是对恶意站点的隔离。优先使用可信站点和可撤销、有限额度的Key；不新增分析、错误上报或第三方脚本。
- 完整备份可能含作者原文、生成正文和模型端点，仍属私有文件；只由玩家本地选择导入。脱敏诊断不是完整可恢复档案，不把两者混用。
- 禁止含配置的截图、trace、HAR、video或认证头导出。截图只截已关闭配置面板的对白／记忆等安全界面，错误输出使用现有脱敏分类。
- 当前CI会上传整个`dist/reports`。**P3私有真实验收不接入这个通用上传步骤**；若以后接入CI，须先设计报告白名单和私有目录排除。此轮不为了部署直接复用该报告上传策略。

## 6. HTTPS、路径、缓存与响应头策略

### 6.1 路径与真实API跨域

- 推荐`https://<已确认站点>/`，hash路由保持`/#/mansion?...`；hash不会发送给静态服务器，不需要全路径SPA重写。兼容`.html`书签保留并检查实际跳转。
- 若只能用`/abyssa/`等子路径，先冻结完整前缀和尾斜杠规则，再检查JS／CSS、动态chunk、字体、纸娃娃、表情、洋馆图层、清单与worker scope。不把本机服务剥离前缀的行为当成平台默认能力。
- 正式验收只接受有效证书的HTTPS API端点；HTTP API在HTTPS页面下的混合内容问题不能靠站点CORS头解决。现有地址解析器允许HTTP，实施时须检查并补足正式HTTPS页面的明确提示或前置拒绝，不禁掉已有本机诊断用途。
- 检查最终`/chat/completions`地址，不猜是否要补`/v1`；现有客户端仅追加`/chat/completions`。尾斜杠、域名迁移或登录跳转导致的重定向不能冒充请求成功，客户端现在明确拒绝重定向。
- JSON＋Authorization通常触发OPTIONS。API侧须允许实际Origin、POST、`Content-Type`和`Authorization`，实际响应也须带有效CORS头；`Authorization`须明确获准，不能依赖通配请求头覆盖它。当前不发送cookie凭据，因此API的`Access-Control-Allow-Origin: *`可以适用；反射Origin时还要核对相应缓存区分。
- 给**静态站点**添加`Access-Control-Allow-Origin`不会替API放行。预检失败、证书／DNS、混合内容、CSP、重定向、401／403、429、5xx和模型截断分别归类，不把网络失败统一解释为安全审查。
- 目录查询／模型核对如有必要单独执行并记录；GET成功不证明POST、完整上下文或三个模型均可用。真实生成保留已核实模型及全文输入。

### 6.2 HTTP缓存与Service Worker协作

| 内容 | 建议策略 | 必验行为 |
| --- | --- | --- |
| `index.html`及其他HTML入口 | `Cache-Control: no-cache`，每次复用前重新验证 | 刷新能得到当前完整版本，不长时间固定旧入口 |
| `game-assets.json`、`game-cache.js` | `no-cache`或等效强制验证；worker保持当前目录scope | HTML、清单、worker版本一致；已有客户端能发现更新 |
| 文件名实际带内容哈希且不可原位变更的资源 | 可用长期`immutable` | 不把全部`assets/`或所有图片一律当作带哈希文件 |
| 未哈希的`character-art/`、`emote-art/`、`mansion-map/`等 | 本阶段优先`no-cache`／重新验证 | CDN旧字节不会导致反复的资源版本不一致 |
| 模型POST、配置和档案 | 不进入站点缓存或worker缓存 | 现有worker只处理同源GET清单文件；真实API响应不落Cache Storage |

现有worker有哈希校验、版本记录、`skipWaiting`／`clients.claim`及旧chunk处理，不据此宣称回退已经通过。云端必须完整切换发布，不能边覆盖边对外服务半套文件；不能只切HTML、漏掉清单或worker。

更新演练包含旧标签页仍打开时发布新产物、冷标签页打开新版本、旧标签页继续导航、全部关闭后重访，再恢复上一份完整产物。验证清单哈希、旧chunk和固定文件名资源都可用；失败时做最小发布兼容修复，不要求玩家清空整个站点数据。

首个部署没有历史线上版本，可在授权测试站点准备两份可识别、存档合同相同的受控发布做切换／回退。不能用“重复上传同一份文件”替代真正的版本更新测试。回退只恢复发布文件，不重置IndexedDB或退回玩家进度。

### 6.3 安全响应头

拟设置`X-Content-Type-Options: nosniff`、`Referrer-Policy: no-referrer`与防嵌入策略；HTTPS重定向、证书与HSTS沿用并核对平台能力，不对未控制的其他子域擅自扩大策略。

CSP须按现有运行资源和内联用法检查后生成，不直接贴一份会破坏页面的通用模板：

- 任意玩家自选HTTPS端点的BYOK模式需要允许对应连接；首版可选择`connect-src 'self' https:`，明确这不是端点白名单。若只允许某个服务商，必须作为产品范围变化先确认。
- 脚本、worker、字体、图片、样式默认收紧到实际来源；核对data／blob及React内联样式。旧`.html`别名使用内联跳转脚本，须提供精确hash或改为等效托管重定向，不能不验就启用`script-src 'self'`。
- 不为方便新增`unsafe-eval`、任意远端脚本或第三方遥测；不引入与Web Locks无关的跨源隔离头来冒充安全上下文要求。
- 若先使用报告模式，报告留在本机且不发送到第三方，最终记录哪些规则真正生效；不能把Report-Only声称为已强制保护。

| P3-B 发布准备与公网测试入口 | 构建、隐私扫描、头部／缓存／路径配置；独立公网Playwright配置，正式Origin可配置，不启动本机server；修正P2固定Origin与额度断言的复用问题 | 本地零付费回归通过；配置缺失默认不执行公网或付费测试；无凭据进入产物 |
| P3-C HTTPS部署与静态验收 | 在已授权目标上传白名单产物；核对证书、响应头、全资源哈希、书签、404、冷暖加载、真实缓存 | 最终HTTPS站可用，隐私和资源无阻断；尚不标记真实模型通过 |
| P3-D 新Origin存储与恢复 | 两份P2私有档案本地选择导入，读档／手动副本／刷新／导出；无Key行为、同档锁及故障恢复检查 | 不调用模型，原文／记忆和来源可恢复，无自动付费／重复提交 |
| P3-E 正式Origin真实闭环 | 新建内容18、真实委托，完整归来＋记忆＋后续＋记忆；检查直接请求、全文哈希、支持段落与用量 | 一条主路线8次正常调用闭环，或如实记录额外修复；三个模型均真实通过 |
| P3-F 更新／回退与交付 | 受控版本切换、旧标签页与回退、刷新后档案不变；脱敏报告、玩家说明、维护说明 | 有版本和回退证据、稳定URL、限制清单与真实调用账本 |

顺序为A→B→C→D→E→F。回退能力要在首次上传前设计，在C阶段先证明完整发布可切换；E之后的最终交付产物若再发生影响运行的变化，须重验受影响项。仅部署／响应头变化不自动要求重付全部模型费用；API、阶段输入或持久化语义变化则不能只复用旧证据。

拟新增独立公网配置与用例，而非直接修改P2历史验收的含义。可以复用现有helper和恢复材料；`page.goto('/')`等导航要按已确认部署前缀构造，避免配置了子路径却又跳回站点根。拟议环境参数区分站点URL、是否允许联网、是否允许付费与本机配置文件路径，不把Key放环境命令或命令行。

## 8. 验收矩阵与证据要求

### 8.1 零付费优先

“零付费”表示不请求模型；公网静态资源仍正常下载。模拟故障测试单独标注，不冒充供应商真实故障或CORS证据。

| 场景 | 观察与通过标准 |
| --- | --- |
| 新浏览器首次打开 | HTTPS安全上下文，标题与AIRP入口可用，运行资源无关键404／错误MIME／哈希不符／未处理异常；无API请求 |
| 首屏与弱网 | 分别记录首屏可交互、首次进入洋馆／战斗／AVG和后台下载；后台约129 MiB不能阻塞首屏，无网／加载失败有可恢复反馈；记录环境，不编造固定秒数SLA |
| 根路径／子路径 | 真实发布路径必验；另一本机前缀测试只作回归，不宣称另一个公网前缀已发布。旧书签和缺失资源不依赖200首页兜底 |
| 浏览器能力 | 记录`isSecureContext`、IndexedDB、Web Locks、Service Worker／缓存情况；不支持必要锁时明确阻止生成，不取消保护。SW缺失时静态资源回退按现有合同验证 |
| 两个P2档案迁移 | 从localhost本地导出／使用已有私有备份 → 公网标题档案管理 → 原身份恢复；不把文件上传服务器，不重生成；全文、记忆、来源与输入哈希一致 |
| 身份冲突与手动副本 | 空站点正常导入；已有同身份档不能无提示覆盖，沿用现有拒绝／确认行为；安全边界复制生成新身份且保留祖先，不伪造新结果 |
| 刷新与缺Key | 正文／记忆保留，Key清空；可重读；生成／整理须重新提供Key并明确操作；切页不清Key，刷新不请求模型 |
| 两标签页／中断恢复 | 同档锁＋CAS仍有效；用隔离的模拟网络验证双击、刷新中断、晚到响应与Updater失败续跑，不消耗真实调用制造故障 |
| 本地持久化 | 导出／手动存读／再导入成功；配额或浏览器禁用存储时明确失败、不声称保存成功。浏览器可能回收数据，备份仍是必要说明 |
| 缓存与更新 | 新旧标签页、固定URL资源、断网重访、更新和回退均可解释；断网只承诺已缓存内容／既有记录，不承诺新模型生成 |
| 安全 | 发布白名单／凭据扫描／私有路径404通过；配置导入和恢复没有向非预期主机传送文件；Key不持久化 |

Origin由协议、主机和端口决定。localhost、平台预览域名、正式域名及以后自定义域名的IndexedDB互不自动共享；路径不同但Origin相同也**不代表存档库隔离**。建议独立站点Origin；换域名前先备份，不能以复制localStorage或服务器搬目录代替受控档案导入。

主要浏览器以普通桌面Chromium为必验，保持真实CORS、证书检查和SW。第二浏览器（优先用户日常浏览器）做零付费打开／导入／读取／能力检查；记录版本和差异，不将其自动扩大为全浏览器、全手机支持承诺。

**缓存测试与网络拦截测试分开。** Playwright路由拦截会影响HTTP缓存，SW请求也不一定由页面路由观察；真正的缓存／更新用正常浏览器和被动观测，不用`route.fetch`、Node代发、改请求头或禁用SW来证明通过。零付费恢复可拦截非白名单请求防止意外联网，但其结果只证明恢复，不证明真实缓存行为。付费防误发门禁也不能改写供应商响应或CORS头。

### 8.2 正式Origin真实路线

默认选`extracted`（实际侧门撤离）作为新生成主路线；它同时验证“带回药箱不等于巡路全清”的事实边界。`cleared`分支复用P2真实档案做恢复／阅读检查，不声称在公网重新生成了该分支。

1. 从正常浏览器新建内容18，真实接受委托、出发、取药箱、侧门撤离和结算，不注入成功事实、不拿作者样例替代。
2. 本地导入配置及既定预设，核对三个模型；导入本身不发API请求。首个Planning完整请求就是HTTPS实测起点，不先连续发多次无意义短测。
3. 完成Planning→Writing→Formatting，进入原AVG。检查13份原文逐字及SHA、阶段输入、正文与JSON保真；小模型不承载整份作者资料。
4. 阅读中刷新，确认同一正文、节点与已读状态恢复且没有新调用；重新填Key后显式交付／整理已读记忆，确认玩法提交与叙事更新边界。
5. 完成一次后续的三阶段与阅读／记忆更新。核对输入确含完整归来正文和确认摘要，邀请不变成玩家已经行动，两个叙事标记有支持段落。
6. 完成手动保存／读取／刷新／导出，并重新检查无自动API请求。阶段结果立即留本机私有检查点，后续UI断言失败不能让已付费结果丢失或自动整条重跑。

证据保留：发布ID／Origin、浏览器与网络环境、各阶段开始结束／安全错误分类、状态码、必要的CORS头、输入和正文hash、usage、读取／记忆／任务结果及安全截图。公开或可分享报告只用端点别名，不含真实API地址、Key、请求头、完整私有档案或整份作者材料；完整复核资料只留本机。

浏览器没有暴露的网络细节写“未取得”，usage缺失写未知，不写零。API服务商收到的是完整任务与作者资料；静态站点服务商只应收到静态访问，不应收到模型POST或存档上传。

## 9. 真实调用提案与失败处理

现有累计账本是`dist/reports/airp-live/call-ledger.json`，P2结束为**46／46**。本回合不修改它。

| 项目 | 拟新增模型请求次数 |
| --- | ---: |
| 归来：Planning＋Writing＋Formatting＋已读Updater | 4 |
| 后续：Planning＋Writing＋Formatting＋已读Updater | 4 |
| 有明确原因的格式／记忆修复或失败重试余量 | 最多4 |
| 合计 | 正常8，上限12；若获确认，累计上限由46增至58 |

这是验收执行安排，**不是本回合调用授权，也不是token缩减目标**。所有实际发出的模型POST都计入，包括短连接测试、修复、失败、取消后结果未知的请求；不会把账本重置为0。进入付费测试前记录用户确认和实际剩余额度，脚本串行、禁止自动重跑整条用例；P2旧脚本的`limit === 46`断言不能原样用来跑P3。

按P2最终16次约407,699 tokens的样本，一条8次路线量级约20万tokens，仅供预估，不是上限或费用承诺。保持完整作者资料与输出容量，按服务商实际usage记账；余额不足则停在可恢复阶段，不削提示词。

失败处理顺序：先判定证书／路径／CSP／OPTIONS／CORS／认证／限流／上游，再决定是否需要新请求。完成阶段不重跑；格式与摘要按现有修复边界执行；上游结果未知明确说明可能重复计费。修复余量用尽或要重跑第二条完整路线，另记增量安排，不隐藏在“再测一次”里。
