## 1. 内容身份与四场规则

- 当前内容：`abyssa.demo / contentVersion 7 / rulesVersion 4`；Schema、应用协议保持4。
- 路线：`intro.tide-cave.first`，单层四房；房间／遭遇分别为`room.tide-cave.1…4`、`encounter.tide-cave.1…4`。
- 队伍：`kael / eustice / elora / kororo / norma`，Lv.1、无装备。`kael`仅作兼容ID，正文仍用`{{user}}`。
- 配给：原食物4次、药水2次；沿用真实物品实例、每回合道具次数与食物个人限制。
- HP、骰面、重掷、沉眠／力竭排除、铭约、治疗代价、伤势延续全部使用现有规则，没有教程专属伤害公式或假骰面。

| 遭遇 | 敌群 | 行为与工作数值 |

| T1 潮沟 | 史莱姆×2 | 每只HP3／攻1／赏金0，普通攻击 |

### 随机数

T1种子固定为 **8267**。正式创建战斗先消耗两次敌人选目标抽签，此时战斗游标为2；提交首个ROLL后五人点数为 **2／2／1／1／3**，游标为7。后续重掷继续真实抽签，不锁结果。

出征命令照常携带普通种子，保存在`continuationSeed`。真正从T1推进T2时才用它初始化普通RNG流；T2至T4连续使用该流。刷新、复制、返回标题和重试均保留种子／游标。重试不接受前端另传seed。

## 2. 状态与故事接点

Campaign的独立域为`campaign.tutorial`，不借用玛回忆的`chapterCompletion`／`chapterClaim`：

| 状态 | 持久字段与含义 |
| --- | --- |
| `pending` | 首晨后等待首次出征；尚不能进入普通远征或自由经济流程 |
| `active` | `runId`绑定本次岩窟；故事、战斗和失败都属于同一run |
| `completed` | `runId / terminalId / claimId / rewardId / cargoIds`证明成功归来与领取 |
| `exempt` | `reason: pre-tutorial-save`，旧冒险档兼容，不代表教程胜利 |

沿用普通`runRef: {kind: expedition, id}`。活动远征在原状态外增加`state.tutorial`：

| 字段 | 含义 |
| --- | --- |
| `stage` | `story / active / failed / claimable` |
| `attempt` | 从1递增，拒绝旧失败画面重复发起恢复 |
| `continuationSeed` | T2以后使用的普通种子 |
| `story` | 当前`{id, step}`，没有故事时为null |
| `choices / readStoryIds` | 已提交的剧情选择与已读段落，跨重试保留 |
| `hintsEnabled` | 提示偏好，关闭不影响规则和领奖 |
| `lessons / undoLessons` | 有效教学事件证明及与战斗UNDO对应的历史 |
| `entry` | 本章入口的完整基础远征状态 |
| `checkpoint` | 当前遭遇开场的完整基础状态及已有教学证明 |

当前每个故事槽只有`step: 0`；`S3-4`接受A／B／C，其余接受continue。页面可在槽内用现有JSON舞台播放占位文本，播完后提交一次正式读完命令。若以后需要持久化更多分页，必须随内容版本修订游标定义，不能静默更改已发布节点数。

| 时机 | 接点 | 读完后 |
| --- | --- | --- |
| 创建run，T1尚未开骰 | S3-1抵达 | 开放T1操作 |
| T1完成 | S3-2洞口 | 开放战间整备／推进T2 |
| T2完成 | S3-3背风石阶 | 开放战间整备／推进T3 |
| T3完成 | S3-4货台，A／B／C态度选择 | 开放战间整备／推进T4 |
| 四场通过且普通终局已生成 | S3-5追回→S4-1回馆→S4-2整备落点 | 进入claimable，等待领取 |

故事期间拒绝战斗、道具及推进命令；不根据某句台词或DOM是否消失推断状态。`queries.continuation`在story、failed、claimable返回null，避免自动恢复循环抢读剧情、替玩家重试或提前领奖。

## 3. 命令与查询

新增操作仍走原应用请求封套：`protocolVersion / saveId / expectedHead / clientRequestId / command`。所有命令经严格解析、既有journey证据链回放和原子存储；失败保持原档，原请求重试返回同一回执。

| 命令 | 业务参数 | 条件 |
| --- | --- | --- |
| `tutorial-read` | `runRef, storyId, step, choice` | 必须等于当前游标；有选择的节点首次必须选A／B／C |
| `tutorial-retry` | `runRef, attempt, scope: encounter或chapter` | 只接受当前attempt的真实团灭 |
| `tutorial-hints` | `runRef, enabled` | 仅修改提示偏好 |

其余继续使用`start-expedition`、`battle-command`、`undo`、`use-item`、`advance-room`、`resume-run`、`settle-expedition`。本章没有撤离房，也没有骰子事件房，不接受借用普通第三层的退出命令。

`queries.tutorial(record)`提供只读的进度、runRef、stage、attempt、故事、选择／已读、教学证明、提示偏好、遭遇序号、奖励定义与`canBegin / canRetry / canClaim`。前端据此导航，不自行拼检查点、补HP或更改Campaign。

### 教学证明

ROLL、固定、角色行动、回合结算、保留固定骰后的重掷、格挡、恢复、用道具、非散牌和铭约，分别从真实事件收集。每项保存`kind / eventId / encounterId / attempt`，去除重复。

UNDO同时撤回对应证明；本场重试只保留开场以前的证明，整章重试清空操作证明。看过提示、关闭提示和角色行动是不同事实。可选格挡／治疗／铭约没有发生时不声称学会；真实提前清场仍然通过，不强迫补点按钮。

## 4. 失败与资产恢复

普通规则先完成真实团灭，随后run停在`stage: failed`；没有普通失败终局入账，没有时间推进。`encounter`恢复本场开场，`chapter`恢复入口并重新经过S3-1。

**整章重试仍保留同一runId，通过递增attempt区分尝试。** 这比另造一次出征更便于证明配给只领取一次。此处落实并替代设计稿早期“废弃run重建”的建议措辞。

恢复包括成员HP／临时锈、配置、骰子／意图、配给实例与余量、个人食物次数、散金／入袋记录、已完成房间、全部RNG流；Boss重试不会补回前面已花掉的药水。选择、已读故事和提示偏好保留。

事件序号`run.sequence`继续单调递增，不能因资源回滚重复使用事件ID。失败尝试留在历史证据链；它们不是可领取的资产，也不是当前有效教学证明。重读S3-4可以continue沿用原选择，不能悄悄换成另一分支。

检查点由引擎在创建／推进遭遇时生成。恢复先校验完整基础状态，应用层再回放整条旅程；仅改快照HP、余量、RNG或检查点不能通过导入验证。

## 5. 返馆领取与防串写

只有四场及所有房间都有真实完成证明、普通单层终局为cleared、三个返馆槽读完，才允许`settle-expedition`。

同一事务完成：普通终局金币＋8G报酬、返还剩余补给、登记草药／书／工坊包袱三个任务事实、记入唯一领取证明、结束活动run、推进一次时段。道具越限治疗花掉的散金按原规则扣除，不承诺固定结算金币。

重复点击、同请求重试、存储写失败后重试均不会二次给钱；尚未读完回馆不能抢先领取。本章终局明确排除成长／整备赠物资格，不授予庄园接管、回忆开放、玛亲征、Lv.2或装备。三类货物不是商店可售库存。
