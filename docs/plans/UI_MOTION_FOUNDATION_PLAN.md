## 1. 目标与边界

完成后应做到：

- 页面稳定，按钮立即反馈，窗口进出完整，切换内容不闪、不跳、不重复入场。
- 同类操作使用相同预设；业务页面不再自行编写 UI keyframes、曲线、错拍和视觉等待。
- 基础动画只有淡入淡出、小幅位移、选择标记移动和简短状态反馈；默认无弹簧、无过冲、无持续装饰运动。
- 快速操作能接续当前状态或直接到达正确终态，不能排队播放一串过期动画。

本轮不改静态美术、字体、配色、布局和玩法；不制作新人物表演、复杂镜头、Lottie／Rive 素材、自定义鼠标、点击粒子或新音效。不新建动效编辑器、全局演出队列和大而全的动画框架。

**Logo 动画是独立品牌演出，明确保留，不属于本次通用 UI 清理。** 保留 `AbyssaLogo` 原有动画实现、分段时序与曲线；标题菜单不再等待或驱动 Logo 的时间表。标题外部背景装饰与菜单动效的清理不延伸到 Logo 内部。

**标题原选中／双菱形与鼠标视差也明确保留。** U1 曾误纳入清理、A1 又以清理后基线判定保留；A2 从清理前实现恢复，不再用通用 control／selection 覆盖。按后续用户要求，B1 加大背景视差并恢复 Logo 后四菜单逐项入场；键盘可跳过，减弱模式直接显示。不恢复外部法阵自动慢转。

范围以实际玩家 UI 为主：标题／菜单、洋馆工具入口、弹窗／抽屉、仓库／日志／整备、人物／商店、地图侧板、战斗界面的普通控件。AVG 人物动作、战斗回执演出、骰子结果呈现、场景天气与真实资源就绪协议不作为杂乱 UI 动效一并删除；它们可以保留专用实现。

## 2. 技术路线：一个调用入口，少量预设

**U2 使用 Motion for React（`motion` 包，`motion/react` 入口）＋统一 CSS 控件状态配方，外面只包一层 Abyssa 基础预设。** 已固定 `motion@13.3.0`，作为运行时依赖；选择它是为了复用进退场、动画接续和 React 生命周期能力，不是为了增加动画种类。[调用说明](../../src/shared/ui/motion/README.md)包含当前 API 与生命周期约束。

### 2.1 为什么用这套组合

- 本项目是 React 状态驱动的 UI。Motion 适合随 `open`、内容身份等状态变化处理窗口进退场；`AnimatePresence` 可以保留退出节点，不必再自行搭建通用退出引擎。但焦点、背景输入隔离、重开竞争仍由共享组件负责，不是装库就自动解决。
- 按钮 hover／press 只需 CSS 状态过渡，没有必要把每个按钮都改为 Motion 节点。统一的是参数、反馈语义和中断规则，不是强制所有效果使用同一种执行技术。
- 不把现有 GSAP 扩成普通 UI 的第二套实现。它适合现有 Three.js 对象与专用时间线，继续留在明确的局部场景；纯 CSS／WAAPI 虽能完成效果，但不足以省掉本项目需要的 React 退出生命周期处理。
- 首批只用基础动画、presence 与减弱偏好能力，不用拖拽、滚动联动、自动布局动画或复杂时间线；不同时安装／直接引用 `motion` 和旧 `framer-motion` 两套入口，不需要付费扩展。

官方实施参考：[React 入门与安装](https://motion.dev/docs/react-quick-start)、[AnimatePresence](https://motion.dev/docs/react-animate-presence)、[MotionConfig](https://motion.dev/docs/react-motion-config)。后者默认不会自动跟随减弱偏好，必须显式配置；它也不会替 CSS 配方调整时长。

### 2.2 共享封装和依赖边界

- 建议将预设、偏好和少量包装组件放在 `src/shared/ui/motion/`，不再新造插值器或手写通用 presence 引擎。
- `RpgModal`、按钮、页签等共享组件内部接入；现有调用者尽量不改 API。业务代码继续写 `open`、`selected`、`busy` 等状态。
- 普通页面只调用项目包装组件／预设，不直接导入 `motion/react`、GSAP 或手写 WAAPI 来制作通用 UI 动效。首版不暴露任意 `duration/ease/variants` 覆盖口，防止各页再次分叉。
- CSS 保留静态视觉，以及统一控件配方中的 hover／focus／press 等简单状态过渡；它们同属该共享库，不是页面自建的第二套体系。Motion 与 CSS 不同时写同一元素的同一动画属性。
- 地图的 Three.js 对象继续由局部 GSAP 处理，只消费公共参数／减弱策略，作为明确的非 DOM 例外；不为统一按钮而重写地图渲染器。
- 共享库不导入 gameplay、应用服务或存档。偏好属于 UI 设置，不写入玩法存档。

参数保持一份可被 TS 与 CSS 使用的定义。U2 采用 `src/shared/ui/motion/tokens.json` 保存时长、曲线、距离；TS 配方读取它并统一把毫秒换成 Motion 使用的秒，轻量生成脚本输出 `styles/motion-tokens.css`，由现有样式入口引入。生成文件不手改，并增加一致性检查；不建设通用设计令牌平台。CSS 默认值不依赖每页挂载 Provider，独立组件预览也必须可用。新 UI 参数先取现有曲线的值，不全局改写 Logo 等专用演出正在使用的旧参数。

项目同时构建游戏和 `@abyssa/ui` 包。依赖策略定为：`motion` 放在运行时 `dependencies`，React／ReactDOM 保持 peer；UI 构建将 `motion` 及其子入口 external，游戏构建正常打包。同步修改 `package.json`、锁文件、`config/vite/create-config.mjs` 与发布校验，不把依赖只放进 devDependencies，也不把库本体复制进每个 UI 入口。实施时核对所选版本与项目 React 19、UI 包声明的 React 18.2 支持范围；在独立消费环境验证，不只依赖本仓库 node_modules。

公共组件签名只使用项目自己的语义类型，不转导出 Motion 的 `Variants` 或引擎对象。新增公共组件沿用 `src/index.ts`／`src/primitives.ts` 入口，并同步发布校验中的导出清单；首版不新设 `@abyssa/ui/motion` 子包。

### 2.3 统一配方目录：首批只实现前三类

下表前三项已作为 U2 首批参数接入并定向验收；如需调整，只改共享定义。U2 只实现 control／surface／content；selection／page／status 仍是候选，留待 U3 真实使用时补充，不先制作空组件。

| 配方 | 基础表现 | 起始值与限制 |
| --- | --- | --- |
| control：按钮／可交互项 | hover／focus 提亮边缘，按下轻微下压 | hover 120ms，press 80ms、1 个 Stage 设计像素；命中区不跟着移动；禁用不播按下 |
| surface：弹窗／抽屉／浮层 | 淡入＋小位移，退出更短 | 进入 220ms、退出 160ms，位移最多 8 个设计像素；正文不缩放 |
| content：页签／详情内容 | 新内容整组短淡显 | 120ms；初次挂载不播，只在真实内容身份改变时触发；直接呈现最新内容，不等旧内容退出；不逐字逐行入场 |
| selection：选择标记 | 同一个标记到新位置，持续选中态立即更新 | 160ms，无回弹；每组独立身份，快速切换不追播旧目标 |
| page：页面基础出现 | 主要区域整组淡入 | 220ms，默认无错拍；已由黑幕揭示的页面不叠第二次整页入场 |
| status：忙碌／结果 | 保留明确忙碌状态，结果对象短暂强调 | 结果反馈约 160ms；结果由回执触发；busy 若需循环，只保留库内最小指示，不把装饰闪烁当进度 |

默认缓动先沿用现有 `--abyssa-ease` 的无过冲曲线 `(0.2, 0.7, 0.2, 1)`。首版不提供弹性菜单；背景和文字无需为了“丝滑”而同时运动。

### 2.4 如何调用，如何形成基础联动

- **按钮**：继续使用 `RpgNotchedPillButton`、`IconButton`、`RibbonButton` 的原有 API；组件内部使用 control 配方。外层按钮／链接的命中区不动，下压只作用于内部美术层；保留原生鼠标、触摸、Enter／Space、禁用与忙碌语义，不为播放反馈延迟 `onClick`。焦点轮廓、选中事实立即更新，只让装饰提亮平滑过渡。
- **窗口**：继续传 `RpgModal open / onClose`，内部使用 surface；遮罩和整块面板同时起止，不对子标题、名牌、正文分别错拍。面板动画层与静态定位层分开，不能覆盖原有居中／Stage 布局 transform。
- **内容**：提供一个薄包装 `UiContentTransition`，业务只传 `contentKey` 与内容，不传时长／曲线。首次随窗口出现时不再叠一层动画；选择改变后只更新阅读／详情区，不重新挂载整窗。U2 不做旧／新两份可交互内容共存的交叉淡变，不引入 `mode="wait"` 串行等待。
- **快速操作**：始终追随最新状态。按下时不用等 hover 完成；窗口进入中可正常操作；关闭中重开接续当前视觉状态；连续切换 A→B→C 不排队播完 B。重复渲染不触发动画，不能为了重播而给整窗添加变化的 `key`。

这就是首批联动：入口立即反馈，窗口同步出现，后续内容局部切换，退出结束后归还焦点。各组件共享节奏但没有全局导演、事件总线或演出队列。鼠标继续使用原生指针，不加拖尾、全局点击波纹或粒子；点击质感先由控件自身的 press 反馈建立。

## 4. 实施阶段

### U1：清理旧效果，建立稳定基线

首批已于 09-16 收口：标题／菜单、共享窗口重复入场、地图回弹和无引用旧控制已清理；32 个测试文件、256 个用例及 4 组浏览器流程通过。Logo 独立演出保留。以下为本阶段执行纪律；全项目其余迁移与场景时钟仍按 U2～U4 推进。

先列出实际入口与组件使用关系，留存代表流程的前后对照；再按上表清理页面装饰、重复入场、长回弹和仅服务于这些效果的计时。

每组清理必须同时处理：初始 `opacity: 0`／偏移／scale、`fill-mode` 留下的终态、animation 事件监听、RAF、定时器、文本显示门禁与输入解锁。布局用的 transform、静态旋转菱形等不能一起抹掉。保留基础状态反馈和已有加载提示。

不用全局 `animation: none !important` 或 `transition: none` 蒙住问题；不把旧代码注释掉后再叠一层新效果。混合样式文件只移除对应规则；独立文件无引用后才删除。

退出条件：标题、菜单、地图及共享窗口可以稳定显示、选择、打开和关闭；无不可见内容、残留输入锁、错误点击区；现有剧情与战斗演出未受波及。该阶段是开发中的清理基线，不作为最终“无动效版本”交付。

### U2：接统一库，优先打通按钮和弹窗

状态：U2-A～C 首批已实施；以下保留执行约束。已迁移三个共享按钮、RpgModal、JournalBrowser 和 ResourceInventoryDialog；标题／洋馆同步真实退出生命周期。具体实现、测试和剩余限制见 [U2 记录](../audits/2026-09-16-ui-motion-u2.md)，不代表全项目迁移完成。

#### U2-A：最小基础与偏好

1. 按第 2 节接依赖、参数、生成样式与公共类型；先用现有 Storybook／组件测试验证普通、减弱和无 Provider 的默认行为，不新建动效展示应用。
2. 复用 `AbyssaProvider` 接收可选 `motionPreference: "system" | "reduced"`。未传值的嵌套 Provider 继承外层，最外层默认跟随系统，不能让现有内层 Provider 把用户偏好重置。共享 hook 给 Motion 和 CSS 状态提供同一有效值；不依赖 `MotionConfig` 默认配置。
3. 接入前 `SettingsPage.reducedMotion` 只是本页 reducer 状态，没有跨页持久化；U2 已将原入口改为“界面动效：跟随系统／减弱”，接入轻量 UI 偏好存储，没有复制开关或把其他演出设置全局化。
4. 偏好存储位于产品侧的轻量共享模块，由游戏入口与独立入口复用；UI 包只接受受控偏好，不自行读写应用 localStorage。仅持久化 `system / reduced`，默认 `system`；坏值／存储不可用回退到跟随系统，写入失败保留本次会话选择并如实提示未保存。不写 `GameRecord`，不迁移玩法存档。
5. 游戏入口、设置页和首批独立入口接同一来源；系统偏好变化、返回页面和刷新后都应正确生效。设置 UI 明确“跟随系统／减弱”，恢复默认也恢复为 `system`，不提供覆盖系统的“强制完整动画”。

已采用的减弱规则：control／content 直接到终态；surface 去掉位移，仅保留约 80ms 淡变，仍走完整退出与焦点清理。关闭中改变偏好也必须收敛，不能等待旧时长计时器。新 CSS 配方使用定向规则响应偏好，处理其与 `tokens.css`／`settings.css` 既有 0.01ms 兜底的优先级；不新增全局归零，也不移除尚未迁移部分的减弱保护。Logo 与剧情／战斗／天气仍沿用原有专用策略，本批不扩大手动开关去改写它们。

#### U2-B：control 与 surface

先接 `RpgNotchedPillButton`、`IconButton`、`RibbonButton` 和 `RpgModal`；保留材质、SVG、文本、布局与调用语义。核查 `components-controls.css`、`items.css` 及首批消费者的覆盖样式，保证同一属性只有一个动画所有者。其他按钮类型留待 U3 按使用点迁移，不声称这三个覆盖全库。

弹窗的硬约束：

- 区分业务 `open` 与“仍在呈现”的生命周期：打开／进入中即可操作；业务关闭立即生效，退出节点保留到动画完成，但关闭中的业务控件不再触发操作，背景鼠标与键盘也不能提前穿透。
- 焦点与遮挡跟随实际呈现生命周期，退出期间将焦点安全留在非业务对话框容器，最终移除后归还来源；不能把含当前焦点的整个弹窗简单设为 inert。来源已卸载时有宿主安全落点；原先按 `open` 切换的背景 inert／快捷键门禁同步到实际呈现状态，必要时只增加最小的呈现状态通知，不让页面自行写退出定时器。
- 若父组件也条件卸载弹窗，必须把 presence 边界放到能存活的位置，不能只改 `RpgModal` 内部便宣称所有退出有效。
- 关闭中重开复用身份、不覆盖原始来源焦点，并使旧关闭完成回调失效；路由离开则立即清理视觉资源，不向已卸载的旧入口抢焦点，不等一个不会再发生的结束事件。
- 不 portal 到 `document.body`，不破坏 1600×900 Stage，不增加 body 滚动锁。

#### U2-C：content 与一条完整流程

- 在 `JournalBrowser` 阅读区和 `ResourceInventoryDialog` 详情区接 `UiContentTransition`；内容身份使用记录／物品的稳定 ID，不把 render 次数或动画时钟当 key。同一内容更新不重播，不因动画额外重置表单／滚动／选择状态。
- 仓库详情的几何测量与 ready 后显示是布局需要，不是旧装饰；保留它，避免测量未完成先动画。布局容器不做高度弹簧，文字不缩放。
- 用“洋馆工具入口 → 日志／仓库 → 连续切换内容 → 关闭恢复入口焦点”验收；标题起点弹窗验证同一 surface 的复用，原业务 busy 和资源门禁不变，Logo 不与窗口联动。
- 先完成一个标准窗口的质感调校，再复验其余使用点；只改公共参数，不为标题／洋馆各设一套速度。

#### U2 验收与收口

- 组件：参数及生成样式一致；按钮鼠标／键盘与禁用正常；窗口确实退出后再卸载、无透点、焦点正确、条件父卸载边界有效、退出中重开只保留一个有效实例；内容初次不播、普通重渲染不播、快速切换只显示最新项。
- 偏好：系统开／关、手动减弱、恢复默认、嵌套 Provider、无 Provider、跨路由与刷新、存储失败、动画中切换偏好；减弱下没有空间运动，清理不依赖固定等待。
- 浏览器：沿用 U1 的普通／减弱 × 1600×900／1280×900 四组流程，增加退出过程中点击／按键、快速重开、内容连切和路由离开。延续 Logo 保留断言；将 U1 的局部“没有入场动画”断言更新为“没有页面私有动画／重复入场”，不能让旧静态基线禁止新的共享配方。
- 工程：相关组件与消费者测试、app／tooling typecheck、边界检查、游戏 build／output、UI release check。UI 包额外在独立临时消费工程验证声明依赖、样式、类型和组件渲染（项目 React 19 与声明支持的 18.2），不能把当前仓库内动态 import 当作完整发布验证。
- 质感与开销：在同一浏览器／视口记录首批流程，核查文字清晰、布局不跳、命中区不漂移，以及连续交互的布局／绘制开销；记录接库前后游戏 JS 增量，不用“CSS 或 Motion 天然更快”代替测量。全项目性能验收仍属 U4。

退出条件：三类预设在上述垂直流程真正复用，普通与减弱模式通过，单一窗口进退场与焦点生命周期可靠，游戏和独立 UI 包消费均通过。记录本批迁移组件、保留例外与实际验证结果；不把 U2 样本完成记成 U3 全项目迁移完成。

### U3：迁移普通 UI，收口基础联动

状态：**A～F 已实施，最终验证中**。见 [C～F 收口记录](../audits/2026-09-16-ui-motion-u3-closeout.md)。调用点、风险、退出条件见 [U3 分批计划](UI_MOTION_U3_ROLLOUT_PLAN.md)，证据见 [A2](../audits/2026-09-16-ui-motion-u3-a2.md)、[B1](../audits/2026-09-16-ui-motion-u3-b1.md)、[B2](../audits/2026-09-16-ui-motion-u3-b2.md)。以游戏壳实际注册的 10 个玩家路由为覆盖范围，不用 catalog／lab 代替玩家入口验收。

- **A：控件收口。** A1/A2 已接日志按钮／链接、洋馆返回与功能入口、Hex／Notch／Back／Shape／SquarePanel 和复杂命令盘；Circle／DiceActionButton／ArrowButton 继承预设。标题已恢复专属动态，避免普通 control 叠加。
- **B：窗口与普通抽屉。** 补齐手册、装备和剧情菜单的退出门禁；房间抽屉、常驻图标栏按非模态范围接入，不套全局背景锁。
- **C：信息页切换。** 设置、角色、商店、仓库／日志／整备按稳定内容身份接 content，同一内容刷新不重播，不为切页签重播整窗。标题双菱形保留专属实现，不再改成统一 selection。
- **D：地图 DOM 与编队。** 清理几何长过渡和逐队员错拍，保留最终布局、空槽与命中。Three／GSAP 保留专用边界，U1 已清理的地标回弹不重做。
- **E：战斗、骰局与剧情操作层。** 迁移普通菜单、道具栏和回看窗口；剧情表演、掷骰、命中与结算不接管，业务阈值不换成 UI 时长。
- **F：最后统一整页交接。** 游戏壳、独立 `TransitionProvider` 与洋馆加载牌共同收口视觉完成信号；保留真实 ready、取消、存档及安全遮挡协议。已有黑幕揭示不再叠 page，status 有真实消费者才补。

基础联动只要求：入口即时响应 → 窗口整体出现 → 内容短切换 → 关闭恢复焦点。首版不加入复杂背景压暗编排、逐项错拍、角色镜头或声音联动。

每批同步删除被替代的旧规则、做普通／减弱动态验收、记录性能与防回退范围，不把清理和性能问题全部留到 U4。退出条件：所有正式玩家入口的普通 UI 都已归类迁移，例外有明确记录；页面不再自行定义动效时间表。不能因日志样本完成，就标记全项目 UI 完成。

### U4：删除残留，增加轻量防回退检查

- 删除已无引用的 keyframe、旧动画状态、监听与计时，不保留双轨切换开关。
- 增加一条范围明确的检查：普通 UI 不直接导入动画引擎，不新增本地 keyframes／原始视觉时长；共享动效目录与明确的专用演出例外可用。检查需有文件／规则级例外说明，不能将正常业务计时误当作动效。
- 在现有 Storybook／组件目录补充控件、窗口、内容切换、快速重开、减弱模式用例，不另建工作台。
- 对代表真实流程进行动态验收，比较构建体积与浏览器录制中的布局／绘制及掉帧；不以“装了库”代替性能验证。

退出条件：旧普通 UI 动效已移除，统一入口生效，检查能阻止页面再次添加同类私有实现；功能与动态验收通过。

## 5. 验收与变更纪律

功能验收至少包含：连续快速选择、快速开关与关闭中重开、鼠标／键盘操作、文本输入与滚动、Stage 缩放、慢资源、请求失败、前后台切换、路由离开、减弱动效，以及剧情／战斗回执不重播。

基本观感标准：无默认回弹、无重复入场、无非必要等待、文字不整体缩放、焦点和选中保持清楚、控件命中区稳定。普通装饰动画未结束不能单独阻挡新的有效输入；资源加载与真实业务 busy 不伪装成可操作。

按批次运行相关组件测试、`npm run typecheck:app`、`npm run boundaries:check`；依赖和公共组件改动验证 `npm run release:check:ui`，正式页面迁移验证 `npm run build:game`、`npm run check:output -- game` 与相应 Playwright smoke。当前存在大量其他工作区改动，先记录基线；发现失败要区分本批引入与既有失败，不为使检查通过而修改无关代码。

每批记录“已移除、已迁移、保留例外、验证结果”。不通过全局重置回滚用户修改；需要回退时只撤回本批已确认的差异。
