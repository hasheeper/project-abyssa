# U3：剩余玩家 UI 动效分批迁移计划

日期：2026-09-16。当前状态：**U3 A～F 的普通 UI 迁移已定向回退，U4 未验收，后续迁移暂停。** 标题专属修复和增强保留。当前范围与验证见[定向回退记录](../audits/2026-09-16-ui-motion-rollback.md)；下文“已实施”等表述只记录回退前历史，不作为当前代码状态。

以下为历史批次，不是待继续执行的清单。当前逐页修复与共享机制收口见 [2026-09-17 合并管理计划](2026-09-17-ui-motion-consolidation.md)、[预设调用说明](../../src/shared/ui/motion/README.md)；原[统一动效计划](UI_MOTION_FOUNDATION_PLAN.md)和 [U2 验收记录](../audits/2026-09-16-ui-motion-u2.md)保留历史依据。继续使用 `motion/react`＋共享 CSS，不重新选库。

## 1. 先确定“怎么动”

方向是**反馈及时、主体稳定、变化有交接**。不是每个地方都加动画，也不是让所有控件做同一种位移。

| 操作 | 目标表现 | 节奏／限制 |
| --- | --- | --- |
| 悬停、键盘聚焦、按下 | 原材质轻微提亮；实体按钮的内部美术下压，外层热区不动 | 沿用 control：120ms／80ms、1 个设计像素。持续选中、焦点、禁用等事实立即更新。 |
| 切页签、选角色、选物品 | 选中目标立即更新，主要阅读／详情区短淡显 | 沿用 content：120ms；首次不播，同一 ID 数据刷新不播；不让列表、标题、正文逐项入场。 |
| 打开普通窗口 | 遮罩与面板一起出现，关闭稍快 | 沿用 surface：进入 220ms、退出 160ms、最多 8px。不缩放正文，不单独动画名牌与关闭键。 |
| 打开非模态抽屉／侧板 | 局部整体淡显＋最多 8px 微移 | 共用 surface 参数，但不因此增加全屏遮罩或背景焦点锁；保留原定位与交互范围。 |
| 移动已有选择指示器 | 只有指示器短移，目标按钮与文字不移动 | 新增最小 selection 配方，候选 160ms、同一缓动、无回弹。没有原有移动标记的列表，不强加“飞行高亮框”。 |
| 完整页面切换 | 一层黑幕完成交接，目标页面稳定就位 | 已有黑幕揭示就不再叠 page 入场。最后一批才改执行时序，真实资源等待保留。 |
| 忙碌／成功／失败 | 忙碌立即可见；必要的小提示仅在真实结果到达时短强调一次 | 先复用现有静态状态。确有消费者再补 status；不加数字滚动、奖励重播或假进度。 |

默认不加弹簧、过冲、呼吸、扫光、鼠标拖尾和全局点击波纹。**Logo 独立品牌动画不改**；剧情镜头、字幕逐字、立绘／漫符、战斗命中、掷骰、结算与天气不归入普通 UI 清理。

标题为用户明确要求的例外：保留原选中扫光、微展和双菱形错拍／浮动，以及分层鼠标视差；按最新要求恢复 Logo 后四菜单 460ms／80ms 错开的逐项入场，键盘可立即跳过，减弱模式直接显示。Logo 自身不改，不恢复法阵自动慢转；不推广成所有控件默认效果。

减弱模式沿用现有产品偏好：控件、内容、选择标记直达终态；窗口无位移、约 80ms 淡变。以后新迁移的普通 UI 都消费同一有效偏好，不再只写页面私有媒体查询。系统变化与手动切换均须在动画进行中生效。

## 2. 源码勘探结论与覆盖范围

当前游戏壳注册 10 个玩家路由：title、prologue、menu、mansion、shop、dice、battle、map、character-status、settings。按这些实际入口验收；catalog／Storybook 用于共享组件回归，lab／tools 不作为“玩家页面已迁移”的依据。共享组件改动仍不能破坏它们的既有调用。

| 调用点 | 迁移前状态／缺口（历史基线） | 迁移归属 |
| --- | --- | --- |
| `TitleCommandMenu` | A2 恢复 U1 前横向微展、扫光、菱形错拍／浮动／按压和鼠标视差，撤去 A1 普通 control | 标题专属例外；共享减弱偏好，C 不再覆盖；Logo 时序独立 |
| `JournalButton`／`JournalActionLink`、`MansionTimeLoading` 的返回链接 | A1 已补共享动效类与有效偏好；HTML／SVG 文字和对应边框同步下压 | button／a 原生语义保持 |
| `RpgHexButton`、`RpgNotchButton`、`RpgBackButton`、`RpgShapeButton`、`RpgSquarePanel` | A1/A2 已接共享 control；Circle／DiceActionButton 继承 Shape | 原美术、语义与点击区保持，内部美术／文字同步下压 |
| `MenuCommandDial`／`RpgDirectionPad` | A2 已接组内对应美术反馈，120ms 提亮／80ms 轻压暗，禁用无反馈 | 保留 SVG 旋转、HTML 定位与固定热区；不添加坐标位移 |
| `HandbookModal`、`EquipmentEditor`、`MemoryStory` 的规则／菜单 | 已使用 RpgModal，视觉预设自动生效；宿主门禁、教程暂停或内容身份变化仍需核对 | B 补呈现生命周期，不能再包第二层窗口动画 |
| `MansionRoomDrawer` | `aria-modal=false`，父级按选中房间条件挂载，仍有 300ms 私有入场 | B 非模态 surface；切房间是 content，不是重新打开窗口 |
| `GameMenu` | 图标栏常驻，宽度过渡 280ms，文字有额外延迟 | B 收口展开表现；不能把收起状态的可用图标一起隐藏或锁住 |
| 设置、角色档案、商店、整备／日志条目 | 有手写列表、页签／开关和详情切换；U2 只覆盖日志阅读及仓库详情正文 | C 按内容身份接入，清理重复反馈与覆盖样式 |
| `sortie.css`／地图 DOM | 仍有 400／780ms 几何过渡、650ms 队员错拍、320ms 抽屉及独立任务侧板入场 | D 单独迁移 DOM 层；U1 已清理的 Three 地标回弹不重做 |
| `ItemDock`／普通战斗菜单、序幕回看 | UI 模式切换仍有 22px 位移、多段延迟；回看侧窗条件挂载并私有入场 | E 只迁移操作／查阅层，不接管演出状态机 |
| `GameShell`、独立 `TransitionProvider`、洋馆换相位 | 路由仍有 560／620／1850ms 视觉等待；洋馆时钟牌有多部件动画 | F 最后处理，一起对齐视觉完成与真实 ready |

关键风险不是“页面有没有 keyframes”这么简单：

- **同一共享按钮的页面 CSS 可能覆盖统一配方**，必须沿消费者查最终样式。
- **用了 RpgModal 不等于宿主已适配退出生命周期**。例如 `ManorBattleView` 的 inert、可操作条件及教程暂停仍围绕 `handbookOpen`；`MemoryStory` 围绕 `menu || rules`。
- **不能只在条件挂载的组件内部加 AnimatePresence**。`MansionRoomDrawer`、序幕回看等必须让共享 presence 边界在关闭期间存活。
- **有意的业务重置不能当作动效残留删除**。例如 `DiceLoadoutContent` 按角色 ID 重挂载有选择重置含义；`EquipmentEditor` 的角色身份还关系到操作目标。

## 3. 库只补必要能力

不新增动效编辑器、全局导演、事件总线、通用自动布局系统或第二套 UI 退出引擎。

1. **control 适配**：能沿用现有组件就沿用；手工复用美术的 button／a 通过共享类与有效偏好接入。复杂图形允许共享配方使用语义状态去点亮对应美术层，但页面不得指定时长、缓动、延迟。只读状态节点不因迁移而新增点击反馈。
2. **surface 呈现与模态行为分离**：从现有实现复用 Motion presence／动画逻辑。RpgModal 继续拥有模态输入与焦点管理；非模态呈现包装不调用其全局输入锁。默认 8px 微移；如贴边侧窗确需方向，只接受贴边语义，不开放任意距离／曲线。具体组件命名留在实施时确定，不预先创建空 API。
3. **selection 最小化**：有真实普通选择器需求再补，不再以标题双菱形作首个消费者。标题按用户要求保留专属错拍与浮动，不用统一无回弹配方覆盖。普通选择器位置由业务布局提供、参数由共享库拥有，不为此引入全局 `layoutId`。
4. **page／status 按需**：有黑幕的页面不再挂 UiPageEnter。状态提示有真实结果身份才考虑统一短强调；没有可靠触发依据就保留静态状态，不为动画补造业务事件。

所有参数仍进入现有 `tokens.json`，TS／CSS 同源生成。Motion／CSS 不同时写同一元素的同一动画属性；定位、镜像、Stage 缩放与动画层分开。不改旧全局 `--abyssa-ease` 去牵动 Logo 或专用演出。

## 4. 迁移批次与退出条件

每个子批均先留存基线，再改对应调用链、删除该范围已被取代的旧规则、验收、记账；不等所有页面做完才清旧实现。

### U3-A：补齐基础控件与绕过共享组件的入口

**A1，已实施并完成定向验收：**

以下是 A1 历史范围。A1 的“保留原样”仅相对 U1 后静态版本成立；A2 已修正标题基线并恢复 U1 前专属动态。

- 标题 `TitleCommandMenu`、`JournalButton/JournalActionLink`、`MansionTimeLoading` 返回链接接 control；标题材质渐变复用共享参数，保留原选中样式和小菱形。本批不改变标记的定位方式、不改加载牌时序。
- 接 `RpgHexButton`、`RpgNotchButton`、`RpgBackButton`。它们继续使用原 SVG、字号、静态选中态，只让内部美术与文字同步下压。
- 已删除上述调用者重复的 hover／active transform／transition。核实源码内 Ribbon／NotchedPill 手工消费者均已适配后，移除 U2 的对应临时兼容反馈；尚未迁移的 Shape／页签／状态节点规则继续保留。
- 暂不迁移地图、路由、战斗栏切换，也不顺带实现尚未开放的按钮功能。

**A2，已实施：**

- 接 `RpgShapeButton`／`RpgSquarePanel` 等剩余实体控件，覆盖 `DiceActionButton` 的间接使用。
- 接 `MenuCommandDial`、`RpgDirectionPad` 和洋馆普通图标入口：保留美术／透明热区解耦，只作用于当前命令的图形。SVG 坐标单位不一定等于 Stage 设计像素，不能直接把 viewBox 的 1 单位当 1px；若无法稳定只移动当前美术，采用同节奏提亮、不强做位移。
- `ArrowButton` 已经继承 IconButton 的 control，只核对箭头静态旋转与下压组合，不重复包装。

A2 实际实现：Shape 四种几何、Circle、SquarePanel、DiceActionButton 继承共享实体 control；命令盘／方向盘按组内 1～4 槽映射 SVG／HTML，复用统一材质节奏；洋馆功能栏的印章、图标与角标同步下压，外部文字不动。移除对应私有反馈；命令盘去掉双击重复激活。洋馆相位栏不在本子批内。

退出条件：鼠标、触摸、Enter／Space、禁用与真实 busy 正常；原生链接行为保留；按钮热区不漂移，文本与边框不分离；标题菜单、整备／日志入口、设置动作与间接战斗按钮没有重复触发。

### U3-B：补齐窗口生命周期，迁移普通抽屉

已实施：B1 覆盖洋馆抽屉／常驻菜单；B2 覆盖战斗手册、角色装备窗口和 Memory 两窗口。均落在实际游戏页面，未增加第二层整窗动画。

- `HandbookModal`、`EquipmentEditor`、`MemoryStory` 的模态窗口核对 `open || presented` 门禁、returnFocusRef、教程暂停及同层／叠层关闭顺序。窗口已接 surface，不能再动画一次整窗。
- `EquipmentEditor` 在当前角色失效、外部数据变化或路由离开时安全卸载；禁止退出快照还能向新角色派发装备操作。关闭中保留的内容仅用于显示。
- `MansionRoomDrawer` 接非模态 surface，父级保留有效 presence 边界。开／关才播放 surface，房间 A→B 只换内容；左右布局保持当前最终几何，不让两份房间控件同时可操作。
- `GameMenu` 的图标栏常驻；展开宽度先到最终布局，标签短淡显，删除文字的额外 100ms 等待，不把整栏做缩放。不新增模态锁，不因收起动画推迟条目导航或已授权的命令。

退出条件：关闭中不能执行旧窗口动作；模态背景保持隔离到真实移除；非模态不新增全局锁。Escape 优先关闭最上层，快速重开不丢焦点／重置表单，路由卸载不残留监听，教程不会在仍被模态遮挡时恢复引导。

### U3-C：统一信息页的选择与内容切换

- **标题选择标记不再迁移**：A2 已恢复用户认可的专属动态并接统一减弱，C 只做回归，不用普通 selection 重写。
- **设置**：`RpgTab`、`Toggle`、复选／单选、滑块的普通反馈归入共享控件配方。tab ID 变化只淡显活动设置区；输入值立刻更新，不淡出整个设置窗口，不改动效以外的设置持久化范围。
- **角色档案**：按角色 ID＋tab ID 标识主要内容，骰面／饰品详情按其稳定 ID 标识；同一角色数值刷新不重播。选项、主阅读区与局部详情避免同次操作嵌套叠播。保留既有角色切换选择重置和装备命令契约。
- **角色档案的骰子展示**：16 秒循环自转属于静态信息页的装饰，计划默认静止，保留检视操作和三维面结构；不延伸到战斗／骰局的真实掷骰。
- **商店**：列表选中立即更新，详情按模式＋商品 ID 短切换；数量／库存／小计更新不重新入场，购买成功后不重挂商品列表。购买 busy／失败、资金与库存规则不变，出售／鉴定等未开放功能保持未开放。
- **仓库／日志／整备**：保留 U2 正文包装，不加第二层淡显；补 `ItemSlot`、列表项、分页与整备详情的 control／content。同一物品数量改变不重播，详情定位与 roving focus 保留。

退出条件：A→B→C 连续选择只呈现 C，没有过期动画队列；不会为动画额外丢失输入、选择或滚动。布局不跟内容高度弹跳；焦点／选中事实与可见详情一致。购买与装备不重复提交。

### U3-D：地图 DOM 面板与编队 UI

- 将地图 `map/team/pop` 模式中的成员列表／任务面板按现有交互范围接 surface／content，命中与选择反馈接 control。
- 删除 650ms 逐队员入场／错拍及 780ms 侧板私有时间表；队形、地面与面板不再依次等待。保留每个模式当前最终位置、尺寸、镜像与空槽规则。
- 不以 Motion layout 弹簧替换现有 left／width／height 动画。优先让布局直接就位，再对本次主要面板做一层短淡显；不同时动画整个队伍、任务正文和所有格子。
- 已条件挂载的面板先修 presence 边界，常驻的选择层不要仅为重播而改 key。地标选择、侧板、编队内容与可出发状态追随最新合法选择。
- Three／GSAP 相机与命中检测保持明确的专用边界，U1 已删除的地标回弹不重做。若仍需调整 UI 导航相机的减弱适配，只接同一偏好来源，不把 Motion 用到 Three 对象，也不改变相机最终定位。

退出条件：快速 map→team→pop→map 无残留遮罩／双面板，选人／移除／满队／空槽正常，1600／1280 两种 Stage 下命中位置正确，出发命令及读取旧编队规则不变。

### U3-E：战斗、骰局与剧情页面的普通操作层

- 战斗的普通菜单、道具栏主／备选模式、目标选择小面板使用共享 control／surface／content；取消普通 UI 的 22px 位移与多段延迟，最新模式只有一个可操作区域。
- 战斗手册在 B 批完成窗口生命周期后，本批只验证其与战斗输入、教程和道具面板共同工作，不重复迁移。
- 序幕的自动／回看／隐字／下一段按钮接 control；回看侧窗复用共享模态呈现与焦点逻辑，保留原侧边阅读外观及阅读暂停规则，不硬套另一种美术框架。
- 剧情里的普通规则／菜单／日志入口同样处理；**不把对话气泡、字幕、人物动作和故事道具揭示统一套 content**。
- 骰局只迁移普通按钮／静态选项；战斗掷骰、骰局滚动／锁定／亮点、命中、结算及结果保留专用实现，不因组件重开而重播奖励。
- 长按跳过的 950ms 阈值、自动推进、掷骰结果停留、敌方回合等是业务／演出时间，不换成 UI token。教程对阻挡层的检测持续有效。

退出条件：取消／确认／重新打开查阅窗口不会额外消耗道具或推进回合；回看退出后焦点和原先暂停状态正确；刷新、失败、后台恢复不重复回执／奖励。原有 6 项非动效断言偏差单独记录，不能通过放宽业务断言来“验收动效”。

### U3-F：最后统一整页交接、加载与必要状态提示

- 改 `GameShell` 与 standalone `TransitionProvider` 的**视觉执行**，保留已有路由、取消、同源 handoff、数据持有／释放协议。
- 普通交接目标为一层淡黑→真实加载→揭示；移除固定 1850ms 面板装入和区域名逐段等待。候选视觉参数取现有退出 160ms／进入 220ms、减弱 80ms，在真实流程中验证后再定稿，不承诺导航总耗时等于这几个数字。
- 完全遮挡的完成信号到达后才切内容；数据／字体／图像按原协议就绪后才揭示。以共享动画真实完成／取消信号衔接视觉阶段，不让页面或两个 Provider 各留一份视觉定时器。
- 6 秒图像等待保险、15 秒 handoff TTL、真实请求超时及加载提示防闪策略与动画时长分开，不能当杂乱动效一并删除。业务存档就绪仍不可被视觉超时跳过。
- 洋馆换相位只简化加载牌／指针／符号的多部件装饰，保留盖黑后换景、图片解码、失败重试与原天气渲染。加载用的小型 busy 指示仅在真实等待时活动，减弱时静止；保留已有三维加载图形的结构约束。
- 若真实操作确需结果短强调，以可识别回执为触发，单次约 160ms；提示停留／关闭遵循原产品语义，不由动画替业务决定。没有需求不先建 status 空组件。

退出条件：直达 URL、前进／后退、快速重复导航、关闭模态后跳转、慢资源、失败／重试、后台返回、取消和减弱模式均无白闪、永久黑幕或提前可点击；每次换页只揭示一次。实现时同步更新 `shared/transition/README.md` 与 loading 实验预览，不在本次规划中把未来行为冒充现状。

## 5. 每批如何验收与防回退

1. **基线**：记录本批调用点、旧属性所有者、原生热区、稳定内容 ID、关闭／返回来源和真实 busy 条件。工作区已有大量其他修改，不按整文件回滚或顺带整理。
2. **测试**：控件／宿主定向测试；普通／减弱 × 1600／1280 浏览器流程；键盘、连续切换、进入中操作、退出中重开、背景输入、路由卸载、偏好实时改变。窗口额外验焦点和教程；业务操作额外验提交次数。
3. **工程**：每批 typecheck／边界检查；样式或共享组件改动跑 UI release 和对应 Storybook；产品页跑 game build／output 与对应 smoke。公开 API 变化再复验 React 18／19 的独立包消费，不仅测仓库内引用。
4. **性能从每批开始看**：比较生产构建的真实调用流程、布局／绘制和连续操作，不等 U4 才发现整页重绘。U2 压力样本有 33.4ms 较长帧，不能据“用了库”保证 60fps；使用同环境前后对照，异常先定位，不加全局 will-change 或 transform 来掩盖。
5. **防回退随批登记**：为已经迁移的文件／规则建立轻量清单，阻止页面重新直引动效引擎或新增同义私有 keyframe／视觉时长。Logo、剧情、战斗、天气与 WebGL 的例外精确到用途，不能豁免整个目录；不把合法请求计时、长按阈值或演出时间当错误。
6. **收口记录**：每批写“已迁移、已移除、保留例外、验证结果、剩余项”。全量 app 回归当前已知的 4 文件／6 用例失败见 U2 记录；实施时重新确认基线，不伪装成全绿，也不能用它们解释新出现的动效回归。

U3 完成标准：10 个玩家路由的普通操作层均有迁移或具体保留理由；同类操作消费共享预设，不遗留两套覆盖规则；资源／存档／演出契约保持。U4 再做跨路由总验收、性能收口与全量防回退清理。
