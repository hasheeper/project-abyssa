# AIRP DEMO：GM最小职责定稿

更新：2026-09-25。全局上下文、场景收束和有限记忆纠正已接入；实际调用与内容质量分开判断。当前实现见[运行链](../architecture/LLM_AND_AIRP.md)，重复接单修正见[context20证据](../audits/2026-09-25-airp-gm-boundary-fix.md)，后续角色条款见[context21](../audits/2026-09-25-airp-dialogue-v21.md)。

## 1. 核心分工

**GM决定接下来发生什么；正文负责人物怎么演；结算记录实际发生了什么；程序执行游戏规则。**

| 角色／模式 | 当前职责 | 不扩大到 |
| --- | --- | --- |
| 日度GM | 延续旧事项，决定当天重点、暂缓和是否新增事件 | 不逐场排台词，不每天重审历史结算 |
| 副本GM | 本趟任务联动、叙事重点、条件节点和结果承接 | 不代替探索、战斗或预定玩家必然成功 |
| 场景GM | 判断当前交流结束或继续；继续时说明尚需回应什么、软篇幅与无需重讲的事项；识别已满足的冗余叙事环节 | 不每场重排世界，不审文风，不接管日常变量结算 |
| Gemini正文 | 当前互动、人物演绎、原预设内部创作流程 | 不直接完成任务、发奖或替玩家决定 |
| 小模型封装 | 中文提取、AVG结构与合法字段规范化 | 不自行改剧情，不重新取得阶段结束权 |
| 小模型结算 | 实际好感、人物位置／状态、授权物品相关结果与记忆／待办的常规更新 | 不规划下一场，不复审GM已确定的有限流程／记忆更正 |
| 程序 | 真实操作、步骤、库存、战果、存储与去重 | 不把模型文案当成玩家选择或真实行动 |

GM不设“全面审核世界”的第四种常态业务。看到明显错误可以有限纠偏，但不要求每次检查点扫描、判定和修改所有数据。

## 2. 本阶段只新增三项必需能力

### A. GM看得到真实全局

从同一存档提供当前任务与完整步骤、玩家实际活动／选择、人物位置／状态／关系、有效记忆与待办、已采纳日度／关联副本计划、占用、日额度和主题黑名单。各模式再追加当前场景或本趟路线／队伍材料。

- 共享的是事实来源，不是假设同型号模型记得其他调用，也不建立第二份GM世界。
- 场景GM不能按在场NPC的knownBy裁掉全局事项；GM所见不等于NPC知情。
- DEMO四位常驻人物原卡、基础世界资料、触发世界书原条目及相关已读正文保留全文，不为缩范围削减原卡书或增加摘要模型。
- 待展示稿、未来计划、未选候选与已读／已发生内容分开；任务日志可查、结束后展示、实际已读不混同。
- 完整输入不意味着每轮必须检查全部内容。只判断本次节点真正涉及的事情。

### B. GM能结束无意义续写，取消重复叙事环节

先判断人物是否回应了真实玩家输入、当前交流是否完成其作用。已经说明和回应的内容继续有效，不因进入接单等新阶段再念一遍。

- 没有新的交流需要就结束；确需继续，只指出尚未回应的问题和下一轮范围，不写台词或逐段演出。
- 本事件中已经满足、可以省去的重复说明／告别等叙事环节，可以标记满足或不再触发；只改必要的当前推进信息，不借此开放通用计划编辑。
- 不能跳过真实玩家选择、探索、取物、交付、作者硬性节点或仍有实际作用的反馈。
- 首次请求应使玩家理解事情及参与意义；具体操作由已有任务指引承接，不按四项任务字段逐轮考核台词。
- 重要目标写错仍是错误，不能虚构异名或靠无限续写纠回。用已有正确事实与明确指引承接相关行动，不拿“日志可查”冒充玩家已经看到纠错。

结束当前交流与整件事件完成分开。玩家还要执行行动，不是要求再写一场对白的理由；玩家尚未得到实际回应，也不能只为少调用直接跳过。

context20落点：场景GM同一次评估可附`coveredAcceptance`，只对本事件紧邻接单对白作条件性满足判断；实际读完并选择对应程序选项后才省略。无有效标记正常回应，标记错误不阻断正文。原S2仅省掉接单后的出发开场，未覆盖这一点，历史“已完成”结论已更正。必要结果反馈不因该标记被取消。

### C. 错误信息不继续传给下一场

保留对明显错误摘要、重复记忆、已解决待办的有限修正／关闭能力，以免下一轮和下一日继续沿用错误信息。

- 常规新增仍由原结算流程完成；GM不每次重新整理全部记忆。
- 在现有检查点看到影响后续的明确问题时，GM可引用原记录与实际依据给出更正／关闭决定，由程序直接保存，不另调小模型审批。
- 后续读取使用有效更正版本，旧稿和原来源保留；不是追加一句相反记忆，让模型自己猜哪条为准。
- 修正摘要不等于修改对应战果或数值。例如实际只带回药箱，就不能把“已交付”的错误摘要变成真实交付。
- 待办尽量复用任务进度，不为同一件事另建副本；普通疑问、格式瑕疵与内部诊断不生成玩家任务。
- 本阶段不把这项能力扩成通用历史账目审计、好感重判或资产修正系统。

## 3. 正常结算保持，不因收束而砍掉基础设施

好感、物品／鉴定相关结果、人物位置／活动／持续状态仍按现有程序与小模型分工更新。人物实际位置可以偏离计划，后续以已落账的实际状态为准，不强行送回原计划地点。

“GM不常态重判变量”不等于“变量不用更新”。既有资产授权和真实操作边界保持；本稿不增加模型动态奖励，也不撤掉现有常规结算。

若以后反复出现小模型无法处理、且必须由GM重判的具体案例，再单独评估该能力。不能仅凭“GM理论上更强”将旧账复核列成本阶段前置。

## 4. 调用和保存只保留必要约束

当前洋馆场景链保持：Gemini正文 → DeepSeek中文封装 → 一次GM。下一轮承接上轮指导和玩家真实选择，不增加写前GM、正文审计或读后第二次GM。

日度、副本及原行动／事件结算依既有时点另行计数；三次不是全流程总成本。本阶段不把每个副本房间追加GM调用作为前提。

- 依赖本轮正文的步骤满足、入口撤回或记忆／待办修正，实际读完后再生效；只依赖既有事实的修正无需等待新稿。
- 相关修改通过已有存储入口一致保存；重试不重复推进、记忆修正不重复加分或发奖。既有回执、存档导出与重放保留。
- 失败保留原正文、响应及待处理状态，恢复对应调用／保存；不静默完成任务。非关键诊断不阻断无关合法操作。
- GM自己的修改和保存不再次触发GM。不新建自主查询、反思或审批循环，也不新增常驻后台。
- 本稿不引入“无GM自动放行”或新降级交互；保留现有恢复行为，若要改变另列产品需求。

工具名、通用动作DSL、跨域事务框架不是验收对象。复用现有接口实现上述最小业务能力即可，不要求先落地旧稿六类工具。

## 5. 明确后置

下列能力不进入当前施工清单，也不是完成三项必需能力的前置：

- GM常态重判历史好感、奖励与资产；通用旧账调整。
- 场景内跨事件大范围重排、任意修改目标／参与人／事件字段。
- 自主多轮查资料、长期聊天记忆、向量库、通用世界数据库。
- 完整Agent工具体系、通用回滚框架、自我审核及无限修复循环。
- 恢复逐场大纲控制、文风审计或正文自动改稿。

日度／出发前已有的规划职责不因“场景内重排后置”而取消。少量场景推进修正不等于开放所有未来计划编辑。

固定／自由两库、低密度安排、黑名单与唯一事件规则继续生效；原r8、全文作者资料、玩家自主权及正式剧情逐卡审定不变。

## 6. 以真实问题验收，而非证明Agent能力

当前已记录的问题是药箱连续场景重复交代／告别、目标层数错写、错误记忆与残留待办，以及场景GM输入缺口。“广场替代温室”仅是先前权限讨论的假设，不作为本阶段必须构建整套通用修改能力的依据。

| 验收问题 | 应看到的结果 |
| --- | --- |
| GM是否看全了 | 原任务、计划、全局占用和有效记忆进入输入；NPC不因此获知秘密 |
| 已经回应为什么还要再写 | 对同一实际流程，不再仅为补旧清单而重开说明／告别；真正待回应内容仍能继续 |
| 当前结束后玩家做什么 | 明确进入已有选择／行动出口；任务目标正确，不把结束对白当成任务结案 |
| 错记忆会不会再污染后续 | 更正／关闭后，下一场和下一日读取有效内容；不再复活已解决待办 |
| 保存恢复会不会重复处理 | 读前不提前推进，读后一次生效；刷新／恢复不重做，原文与回执可重放 |
| 正常结算是否保留 | 好感、人物状态和既有授权物品结果仍正常更新，GM不额外复审一遍 |

实施顺序定为：核对同一真实案例及输入 → 补全局上下文 → 调整收束与最小叙事推进 → 修正有效记忆／待办 → 存档恢复与真实流程复验。先验证这三项能否消除当前问题，再讨论新增能力。

上述职责已接入，恢复与回放证据见[存档池化验收](../audits/2026-09-25-airp-save-pooling.md)，接单去重与输入边界见[GM边界修复](../audits/2026-09-25-airp-gm-boundary-fix.md)。技术闭环通过，文本质量仍待验收；本稿不重复累计调用账本或阶段施工日志。
