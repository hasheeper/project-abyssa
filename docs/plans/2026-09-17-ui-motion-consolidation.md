# UI 动效合并管理与瘦身计划

日期：2026-09-17。状态：**M0–M4 已完成，合并管理范围收口**。见 [M1 清理记录](../audits/2026-09-17-ui-motion-m1.md)、[M2 共享预设验收](../audits/2026-09-17-ui-motion-m2.md)、[M3 生命周期验收](../audits/2026-09-17-ui-motion-m3.md)、[M4 校验与性能限制](../audits/2026-09-17-ui-motion-m4.md)。洋馆首次开窗长帧仍待单点调查，不将管理收口解释为全项目卡顿已解决。

目标：保留最近逐页调整的实际效果，收拢重复预设与生命周期代码，清除失效残留，让组件库展示与真实页面使用同一份实现。不是恢复已回退的 U3 批量迁移，也不是重新设计全项目动画。

## 1. 勘探结论

现状是「共享基础已经存在，页面编排与参数仍分散，少量旧规则靠覆盖失效」。不能概括为没有动画库，也不能把所有页面专属演出都当成冗余。

M0 读取源码、CSS 导入顺序、页面调用链、测试和既有验收记录；未逐页进行新一轮浏览器覆盖率采样。M1 另对洋馆抽屉和出征面板进行实际入口复验，不代表全项目动画已完成运行审计。

M0 清理前的静态扫描范围为 `src` 内 CSS／TS／TSX／JS／JSX，排除测试、Storybook、testing 与 tools：136 个 CSS 文件中，56 个含动画声明或关键帧，共 241 处关键帧定义、237 个名称。这个数字包含 Logo、对白、战斗及天气，不等于 241 个同时运行的动画，也不证明包体或帧率问题。

### 已有的共享基础

| --- | --- | --- |

| 模态窗口 | `RpgModal → UiModal`；默认 surface、洋馆显式 manor | M2 已收拢参数来源，保持默认与 opt-in 边界 |

### 分散与重复的具体证据

1. **角色、出征、商店的主板入场完全相同**：M0 时三份 CSS 各定义从上方 34px 到原位、820ms、曲线 `(.32,0,.18,1)`，配合 240ms、`(.3,0,.5,1)` 淡入。M2 已原样提取到 `shared/ui/motion/page-board.css`，三页直接调用并删除旧定义。
2. **四份近似的入场生命周期**：M0 时 `useCharacterIntro`、`useMapIntro`、`useShopIntro`、`useMansionIntro` 都实现 waiting／playing／ready、一次启动、后台收束、减弱动态、提前输入及清理。M3 已收为 `shared/transition/usePageUiIntro`＋四页薄适配；地图场景等待和 1520ms 收尾、洋馆图景等待／剧情暂停及焦点／按键差异均保留。
3. **参数来源**：M2 已将共享主板与 manor 主框／正文参数归入原 `tokens.json`，扩展 `motion:check` 校验三份生成 CSS。各页专属动作和 hook 收尾仍留在页面；测试保护共享主板不被收尾时钟提前截断。M3 仅合并生命周期机制，未改变这些参数。
4. **组件库展示**：M2 已为 `Foundation/UI Motion` 加入直接消费真实实现的 page-board／manor 普通与减弱预览，不再另写演示动作。
5. **维护文档落后**：M0 时交接 README 把 shop 写成 panel-drop、正式游戏写成独立 HTML 接力。M3 已针对性修正交接说明与四页调用表；M4 再做整体维护检查。历史回退记录不抹除，也不当成恢复迁移的指令。

M1 已删除洋馆 2 项、地图 3 项命名关键帧及配套失效声明；不设「必须砍掉多少动画」的比例指标。

### 明确不能按重复误删

- RP 的四个重名关键帧是 `prefers-reduced-motion` 下的有意替代，不能依据重名统计删除。
- `CharacterContentSwap` 不等价于 `UiContentTransition`：前者要等待图片解码、保留旧内容并在新内容提交后进入；`useCharacterChange` 还同步立绘、名字、TAB 与资料。这些不是多余的淡入。
- `mansion-ready` 用于当前保留的产出／升级标记演出；设施功能暂未开放，不等于可以删除未来状态契约。`mansion-toast-in` 也被同伴通知实际使用。
- `mansion-world-art` 由 `mansion-assets.ts` 动态创建，不是因为 JSX 搜不到就能删。
- 战斗 `animation:none`、`.001` 初始透明度、暂停标记和 `will-change` 收束，包含防二次播放／预绘制保护；不做全局清洗。
- Logo、标题选中菱形与菜单顺序、menu 背景／立绘视差、地图纸片弹簧、骰子落地回弹、攻击与敌人演出、对白情绪、时间切换与天气保留独立实现。
- GSAP 目前实际用于地图相机插值，与 HTML 面板共享 780ms focus 参数。本轮不为了只剩一个依赖而替换相机，WAAPI 的角色／战斗用途同理。

## 3. 收拢后的管理边界

| 所在位置 | 管理内容 | 不应承担 |
| --- | --- | --- |
| `shared/ui/motion` | 控件、窗口、普通内容替换、通用木板动作；参数、CSS 和真实预览 | 读档、导航、敌人出现、角色图片准备 |
| `shared/transition` | 可复用的页面 UI 入场生命周期；接受明确 readiness／暂停信号，处理输入快进和清理 | 游戏规则、资源成功的伪判定、全项目每帧状态调度 |
| `apps/*` | 页面层次顺序、分组、就绪条件和专属联动 | 再复制共享关键帧、用一串覆盖规则关闭旧实现 |
| 专用演出模块 | Logo、视差、地图、战斗、AVG、天气 | 自动继承普通面板的速度／幅度 |

维持现有 `RpgModal`／`UiContentTransition` API。木板预设优先附着现有容器，避免为统一而增加 DOM wrapper，改变 fixed 定位、裁切、TAB 附着或 transform 层级。依赖路由的 hook 不塞进公开 UI 包。

共享的是动作和明确的参数源，不是强制所有面板同速：角色／出征／商店的 820ms 主板可以共用；战斗目前 960ms、洋馆窗 760ms 保留各自曲线、距离、淡入和就绪条件。子内容错峰仍由页面配置，不逐条物品启动动画。

只建立必要的已有预设，不新增通用时间线 DSL、全局动画状态仓库、每元素观察器或全页面常驻 RAF。CSS 按实际消费者引入，不建立一次加载所有演出的总样式包。

## 4. 批次安排

### M0 — 勘探和规划（已完成）

已完成代码／调用／导入顺序盘点、候选分类和本计划；补正当前文档入口。没有修改运行代码或视觉参数，没有执行删除。

### M1 — 失效残留清理（已完成）

范围限洋馆旧 loading／房间抽屉、地图旧面板入场及其专门的覆盖补丁。

1. 在独立 QA 档记录清理前实际 animationName、duration、delay、opacity、translate 与最终几何；核对主路由及独立入口。
2. 删除已确认失效的旧定义、调用和死选择器，避免只删除 `animation:none` 反而复活旧效果。
3. 正常／减弱模式、打开／关闭／重开、左右面板复验。视觉轨迹与最终布局保持不变。

退出条件：每项删除有调用链和前后对照；没有更换引擎、时长、材质、字体或当前效果。改动只涉及已列明小范围。

完成情况：4 个生产 CSS 文件仅删除失效规则；新增针对残留、现行动画拥有者和减弱动态的回归测试。浏览器记录洋馆左右抽屉、编队及右委托的前后几何完全一致，另复验左委托关闭／重开。减弱动态由组件参数与实际 CSS 守卫测试覆盖，未改用户系统偏好。详见[验收与限制](../audits/2026-09-17-ui-motion-m1.md)。

### M2 — 合并相同预设，接进组件库（已完成）

- 将角色／出征／商店共同的主板 settle＋appear 提取为单一预设，先迁移角色，再迁移商店，最后出征；每迁移一个就删除对应旧定义。
- 将 manor 框体／正文的现有参数纳入同一可校验来源。扩展现有 token 生成与检查，避免 TS 秒数、CSS 毫秒数、收尾时间各写一份。
- 在现有 `Foundation/UI Motion` 中加入真实的 page-board 和 manor 预览，直接消费同一配置与 CSS；不复制演示专用版本，不新建预览系统。
- 现有默认窗口、三个基础按钮和普通内容替换不换风格；战斗主板本批只登记，不改其调度。

退出条件：三页实际调用共用动作；manor 真实窗口与预览一致；共享关键帧不再在三页重复定义；无新增独立维护的第二套 token。

完成情况：三页按角色→商店→出征顺序迁移，6 份旧关键帧收成 2 个共享定义；游戏产物为一份独立 page-board CSS，UI 包中也只定义一次。manor 的框体／正文统一参数源；组件库 4 个新预览已实测。105 项 app 测试、9 项样式／构建回归、类型／边界／参数检查、UI／游戏／Storybook 构建通过。三页实际入场时长与曲线、终态布局不变；四份 intro hook 与 M2 前逐字相同。详见 [M2 记录](../audits/2026-09-17-ui-motion-m2.md)。

### M3 — 收拢重复生命周期（已完成）

- 从角色／商店共同部分提取页面 UI 入场 hook，验证后接地图、洋馆。保留页面薄适配层，明确各页的 readiness、结束时点、暂停和提前输入策略。
- menu 保留 opening 阶段起播、1100ms 对白就绪等专用时序；战斗保留 SceneSequence；不为共用一个 hook 改掉当前起播时机。
- 合并后台／偏好改变／卸载的监听和清理代码，但不引入全局轮询。允许页面对独立演出继续使用原实现。

退出条件：四页不再复制同一组状态机 effect；地图不提前播放、洋馆剧情恢复不重播、键盘与点击不被吞掉；一次挂载只进场一次，内容刷新不重启。

完成情况：角色／商店先迁移验证，再接地图／洋馆。四页 221 行机制收成 55 行薄适配＋77 行共享 hook，净减 89 行；保留各页时钟、焦点／按键、图景和剧情策略。156 项相关 app 测试、9 项参数／样式检查、类型／边界／token 检查及游戏构建／产物检查通过；四页实际中间状态已采样，三页主板终态与 M2 一致。未修改动画 CSS、token、menu、黑幕或战斗。详见 [M3 记录](../audits/2026-09-17-ui-motion-m3.md)，不将代码减少解释为帧率提升。

### M4 — 校验与维护收口（已完成）

- 更新 UI motion／transition README 和消费者清单；旧 U3 计划保持历史，不再并列成当前指令。
- 利用已有测试和构建流程，加必要的未引用／重复候选检查，输出候选而非自动 purge；显式允许 reduced-motion 重名与动态类名。
- 保留页面视觉与行为测试，不将它们替换成「class 已加上」的浅断言。
- 对比源码重复、最终按路由加载的压缩 JS／CSS、活跃动画和监听、长帧。文件数量或总代码行数下降不自动等于性能改善。

完成情况：补齐消费者与维护入口，新增只读候选／静态路由产物检查及独立 QA 采样工具。扫描为 232 个定义、228 个名称；未引用字面候选和未允许重名均为 0，保留 4 组 RP reduced 替代及 5 组同内容候选，不自动删除。实测修复黑幕 idle 后 3 个隐藏活动点仍运行的问题，活动阶段效果原样保留；除此之外生产源码与 M4 前一致。178 项相关 app 测试、85 项构建测试（含 17 项动效相关）、类型／边界／参数检查及游戏构建／产物检查通过。五页完成前后入场与活跃动画对照；监听清理由原有 StrictMode 测试验证，未做全浏览器监听计数。详见 [M4 记录与数据](../audits/2026-09-17-ui-motion-m4.md)。

收口边界：本批共享 CSS gzip 增加 15B，用于停止隐藏动画，不宣称缩包或 FPS 改善。洋馆整备首次打开单次测到 181.6ms 长帧，其中 onclick 强制样式／布局为 154.7ms；仓库、日志也有首次长帧。作为后续单入口性能调查保留，不在本计划内继续扩大重构或调整曲线。

后续调查补记（同日）：已移除日志阅读区首次挂载时无效的 scrollTop 重置；整备分帧预绘制候选未证明整体更顺，已全部撤销，现有窗口动画与焦点管线保留。整备长帧仍未解决，见[后续调查与试验回退记录](../audits/2026-09-17-mansion-window-performance-followup.md)。

## 5. 各批验证门槛

- 不改同一版本下的终态坐标、尺寸、TAB 与面板接缝、美术和点击范围。
- 不出现只有首尾两帧、在黑幕后提前播完、退出后重播、背景穿透或永久 `will-change`。
- 保留 reduced、后台切换、快速输入、关闭中重开、图片准备失败、卸载取消和焦点归还。
- 组件／hook 测试覆盖相应批次；在游戏页观察中间状态，不只看静态截图。
- 运行 `typecheck:app`、`boundaries:check`、`motion:check`、相关 app 测试和样式边界测试；涉及共享 UI 时同时检查 `build:ui` 与 `build:game`。
- 性能先同环境同入口记录基线，再做前后对照；不以减少死关键帧的字节数宣称解决首次窗口长帧。
