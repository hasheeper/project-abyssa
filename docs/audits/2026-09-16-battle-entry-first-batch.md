# 战斗进场第一批：旧庄园场景与木板

## 范围

- 普通旧庄园远征：首次出征、刷新续战、从完整剧情返回战场。
- 保留现有皮肤、美术、战斗规则、骰面、存档及战斗演出队列。
- 教学、回忆、旧裂隙不接入新的木板模式。
- 本批不做骰子落盘、角色/敌人错峰、短对白联动，也不改换房的走路/遭遇/白闪时序。

## 实现

1. `manor-scene.ts` 从当前展示房间生成场景描述。外层背景、内战场、房间标识读取同一描述，不再由皮肤决定外背景。
2. 场景、敌方立绘、队员肖像和当前框体资源通过共享图片解码缓存准备。准备中接入路由 readiness；失败释放黑幕并提供重试，不把缺图当作准备完成。重试不发送游戏指令。
3. 旧庄园请求短黑幕 `fade`（620ms），未接入的战斗内容保留原来的 `panel-drop`。页面卸载后自动解除请求。
4. `SceneSequence` 的 `board` 模式用于初次挂载和剧情返回。背景不作纵向位移；只有木板作 -34px → 0、960ms 缓落，透明度独立在320ms内显现。沿用角色/地图/商店的实体木板语言，战斗页节奏稍缓。
5. 入场与准备期间锁定操作；血量、骰面和一般数据更新不重播木板。减弱动态和切后台直接收束动画。

## 首段跳帧修正

用户反馈第一版缓落忽然、像跳帧后，补做了浏览器内 `requestAnimationFrame` 采样（未同时运行测试或构建），而不是继续用外部 DOM 轮询判断流畅度。

- 修改前：刷新入场43个采样帧、最大间隔98ms；地图「继续远征」46帧、最大间隔85ms，卡顿出现在入场前段。
- 原实现把复杂木板完全透明隐藏，未提前准备其合成层。图片解码完成不代表SVG、滤镜、立绘等已完成首绘。只增加预绘制和临时合成层后，同入口最大间隔降到21ms，定位到首段绘制准备不足。
- `prepare` 使用肉眼不可见的0.001透明度，并在准备/运动期申请 `will-change: translate, opacity`，落定后释放。保留原34px、820ms曲线，不靠缩小幅度或延长时间遮盖卡顿。
- 首入与剧情返回都先挂载准备态，跨两个绘制回调再起播。以木板位移轨道的 `animationend` 收尾，忽略短淡入和子元素动画，不再按挂载时的820ms定时器提前切终态。保留3倍时长的缺失动画保险；后台/减弱动态仍直接收束。
- 最终诊断：刷新与地图返回均52个采样帧，最大间隔分别23ms、26ms，均无超过34ms的间隔；采样覆盖到CSS动画时间820ms和位移0，落定后phase=idle、will-change=auto。
- 这是当前机器、当前旧庄园首房的rAF对照，不是GPU呈现帧的跨设备性能保证；剧情返回由状态机回归覆盖，未在这里冒充实机帧率数据。临时诊断代码与可见输出已移除。

### 后续节奏微调

在修复首绘后，按用户「前面不那么着急、整体稍微慢一点」的反馈，缓落从820ms调整为960ms（增加140ms），曲线从 `(.32, 0, .18, 1)` 改为 `(.38, .08, .34, 1)`，淡入从240ms调整为320ms。34px幅度和520ms离场保持不变。前200ms理论位移从约11px减至约6px；不加额外等待，不改预绘制与实际动画结束事件。上面的帧间隔数据属于此前820ms版本，不作为新参数的实测数据。

实机从地图「继续远征」捕获了进场中的计算样式：`animation-duration: 0.96s, 0.32s`，曲线为上述新值；三名敌人存在。落定后 `phase=idle`、`translate=none`、`will-change=auto`，诊断输出已不存在。

节奏微调后，串行回归4个文件18项通过：木板状态机、真实入场、格挡/道具/菜单交互、剧情往返。测试只推进有限的木板预绘制与结束事件；持续悬浮连线保持原生rAF，避免将常驻效果误作可清空的计时器。单独复测时多道具用例约5.4秒；此前与构建并行时曾触及15秒限时，未通过删断言或延长该用例限时规避。
