# 洋馆经历结算卡住与恢复修复

日期：2026-10-01（Asia/Shanghai）。运行源码：`d393ac53f0f48934e21d7992284321d92a0a9b0c`。

## 原因与修复

截图对应「两张不同的整备表」行动反馈后的经历结算。用内容28正式事务构造同一事件，确认以下问题：

- 已读阶段反馈与经历结算同时挂载两个模态输入层。存在待结算边界时，由结算面板单独接管。
- 完成阅读后仍按交谈进行中锁住页面、导航和行动。前端入口与程序检查统一忽略已完成阅读；未读交谈仍保留原锁定，未结算经历仍禁止出征。
- 取消后保底分支重新创建同一个任务，记账导致输入中的来源版本变化，触发 `Existing task has different input; use explicit refresh`。保底结算现在复用该边界已有任务，保留冻结输入和尝试记录。
- 从结算进入连接设置时，嵌套 portal 的输入所有权与绘制顺序不一致；设置还继承了洋馆禁用鼠标的状态。系统层按嵌套深度排列、输入守卫选择实际顶层，并明确恢复系统界面的鼠标输入。后台提示轨道仍不占用整个画布。

收起只是界面操作，不调用模型，也不写交谈暂停事实。跨页面使用同一个后台驱动；菜单上可以直接重新打开当前结算，不必重新进入洋馆。停止请求记录取消及供应商端结果未知；刷新后持久化的 running 尝试由玩家明确标记中断，不自动重发。
