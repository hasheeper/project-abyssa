## 1. 结论

**本轮扫描没有发现当前真实API Key进入正式game产物、受检报告或Git可达历史。S1～S5已修并通过本地定向复验；源码来源尚未冻结，公网与完整玩家流程尚未验收。**

## 2. 初次审计问题与整改结果

### S1：更换连接绕过Key误填拦截——已修

- 入口：[useDirector.ts](../../src/game-client/airp-director/useDirector.ts)，`reconnect`第80～84行；落盘：[reducer.ts](../../src/game-application/airp-director/reducer.ts)，第151～155行。
- 导入／保存配置会拒绝Key出现在模型名、地址等非敏感字段；首次准备日程也会扫描材料。但失败后“确认使用当前连接”直接将当前model配置写入任务，没有复用该检查。
- 复现使用**内容28、内存档和合成Key**：准备场景→制造一次正文失败→把合成Key同时设为当前Key和模型名→确认连接。导入校验拒绝同样配置，但重连命令成功，任务`connections[].config.model`和完整导出存档均含该合成值。随后驱动还到达了替代provider一次；未发送网络请求。
- 影响是误填凭据被当作普通模型配置持久化、随完整备份分享。不是说正常填写的Key必然入档，也没有发现实际用户档已发生此问题。
- 修正：在“确认连接”提交之前统一校验实际生效的地址／模型配置与所有当前Key，保持凭据仅在私有连接容器内；运行阶段同样校验重连后的实际配置。不要把Key传给游戏命令、日志或回执来做检查。
- 验收：普通导入、保存、临时手填、首次准备、失败重连采用相同边界；违规操作不能修改存档，不能请求provider，不能在错误或导出中保留合成Key。
- 已实施：导入／保存与重连共用纯配置凭据校验；重连在游戏命令之前拒绝，驱动在请求前复核冻结材料、当前模型和输入。合成Key回归确认替代provider未被调用且未新增尝试。此检查针对当前连接已知Key；已经外传的旧备份无法靠代码自动收回。

### S2：开发服务器可以提供私有报告和配置副本——已修

- 位置：[create-config.mjs](../../config/vite/create-config.mjs)第29行及[.gitignore](../../.gitignore)。
- 审计时仅明确拦截`airp-test.local.json`这个文件名及常见env／证书文件。Git也仅对指定的本地JSON配置名作例外保护，改名副本没有同等保障。
- 使用临时目录和当时同一套Vite配置，分别请求普通路径和`/@fs`路径，结果如下。所有文件都是合成数据，没有经HTTP读取真实配置或私人报告。

| 合成路径 | 普通HTTP | /@fs |
| --- | ---: | ---: |
| `config/airp-test.local.json` | 403 | 403 |
| `config/connection-copy.local.json` | 200 | 200 |
| `dist/reports/private/example.archive.local.json` | 200 | 200 |

- 默认监听127.0.0.1限制了暴露范围；这不是已部署站点的任意文件读取证明。但`--host`、隧道或共享开发端口会扩大风险，Git忽略也不能阻止HTTP读取。
- 修正：统一私有配置命名／目录，并对副本、私有归档和报告目录添加服务拒绝规则与Git保护；测试普通、`/@fs`和public复制边界。面向试玩者继续提供构建产物服务。
- 已实施：Vite拦截所有`*.local.json`和`dist/reports/**`；Git忽略`*.local.json`。相同合成路径的普通与`/@fs`请求全部返回403。本地配置权限由0644收紧为0600；它仍是本机明文文件。

### S3：发布隐私检查未形成统一门禁——本地门禁已接通

- 位置：[package.json](../../package.json)、[prepare-airp-pages.mjs](../../scripts/prepare-airp-pages.mjs)第18～22行、[airp-pages.mjs](../../scripts/lib/airp-pages.mjs)的`privateMarkers`／`scanPrivateMarkers`。
- 审计时`build:game`只构建，`release:check:game`也未串入Pages隐私检查。只有`prepare:pages`／`check:pages`执行已有私密值扫描及发布控制文件检查。
- 原有扫描按当前本地配置的Key／端点检索所有产物字节且不打印值；缺少本地配置时只有空标记集合，未知Key若进入合法`assets/*.js/json/txt`不能仅靠目录白名单发现。
- `public`整体复制，动态素材目录也递归复制，所以在合法资源目录中的内容仍需扫描。
- 初次只读发布检查因缺少发布控制文件而失败；上次准备的报告不能替代重新build后的验收。
- 修正：统一正式发布命令，把构建、资源闭合、目录白名单、通用凭据扫描、可选已知私密值扫描、404／CSP、产物摘要复核串成失败即停止的流程。CI无需拿到开发者真实Key，通用扫描与合成泄漏测试必须独立可用。检测结果仅报告路径和类型。
- 已实施：Pages全字节扫描加入通用凭据形态与赋值字段检测，并检查已知值的Base64形式；CI在构建后运行准备与严格复查，`release:check:game`也串入两步。UI包检查复用同一套通用／已知值扫描。最新`prepare:pages`、普通`check:pages`、UI包检查和game资源闭合均通过。通用扫描不能证明发现任意自定义密钥或任意编码，故保留已知Key扫描和人工清单复核。

### S4：CI整目录上传报告，私人材料没有上传白名单——已修

- 位置：[ci.yml](../../.github/workflows/ci.yml)：审计时两个job均在`always()`条件下上传整个`dist/reports`。

### S5：UI包发布基线已落后，检查确定失败——已修

- 已实施：数量基线改为116／44，并显式要求`ConfirmationDialog`同时由根入口和patterns入口导出。UI包检查已通过，npm试打包清单仅含允许的UI文件与包元数据。

已知Key扫描覆盖原文、JSON转义、URL编码和Base64表示。通用模式扫描是辅助检测，不能识别任意自定义令牌或任意编码。没有读取玩家浏览器数据库，没有扫描Git不可达对象、仓库外备份、所有历史视频／二进制以及依赖目录的全部文件；不作“所有地方绝无秘密”的保证。

以下已有防护应保留：

- 独立连接IndexedDB，以AES-GCM密文和不可导出的CryptoKey保存，正常路径不把Key写进游戏档或明文localStorage；它不防同源恶意脚本或已被控制的浏览器。
- 请求把Key放Authorization，`credentials: omit`、`redirect: error`、`cache: no-store`；拒绝URL用户信息／查询／片段，拒绝正文直接回显当前Key。
- 日志对Key、Bearer和URL脱敏，导出调用日志排除冻结材料／端点配置。完整游戏备份为了恢复会携带冻结端点，不能当成公开诊断摘要。
- 缓存Worker仅处理同源GET，不缓存模型POST或跨域API请求。
- Pages目录白名单、符号链接阻断、全字节已知私密值扫描、快照核验和CSP已接入发布门禁。
