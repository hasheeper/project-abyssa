# M2：共享预设与组件库收口

日期：2026-09-17。对应[动效合并计划](../plans/2026-09-17-ui-motion-consolidation.md)的 M2。仅收拢现有动作、参数和真实预览，不重新设计页面，不实施 M3。

## 实际变更

1. 角色→商店→出征依次接入 `shared/ui/motion/page-board.css`。现有容器继续拥有动画，未新增 DOM wrapper。三份 settle／appear 共 6 个旧关键帧移除，改为 2 个共享定义；商店资产、地图图景的纯淡入也复用 appear，保留原子内容时长和延迟。
2. 原 `tokens.json` 新增 `pageBoard`、`manorWindow`。洋馆框体、退出距离、暗幕、正文、头尾节奏均来自这里；减弱时长继续复用原 surface 的 80ms。TS 在 Motion 边界转秒，CSS 生成毫秒，没有另一份手工维护的参数表。
3. 扩展原 `motion:tokens`／`motion:check`：除控件外，生成和校验 `page-board.css`、`modal-tokens.css`。按消费者引入；没有新增依赖或动画引擎。
4. `Foundation/UI Motion` 新增 Page Board、Page Board Reduced、Manor、Manor Reduced。木板直接消费同一变量，洋馆直接使用现有 RpgModal 和 manor-utility 布局；没有演示专用 keyframes。支持重播、内容更新和关闭中重开。

| 共享预设 | 保留的参数 |
| --- | --- |
| 三页主板 | 上方 34px；缓落 820ms `(.32,0,.18,1)`；显现 240ms `(.3,0,.5,1)` |
| 洋馆框体 | 上方 30px／760ms `(.28,.08,.24,1)`；面板淡入 240ms、暗幕 180ms |
| 洋馆正文 | 380ms、延迟 140ms、8px；头／尾／导航 360ms、延迟 100ms |
| 洋馆退出／减弱 | 上移 8px／200ms；减弱无位移、80ms 淡变 |

默认 surface、控件、内容替换的参数均未改。Logo、标题菱形与菜单、menu 视差、角色切换与 TAB 交接、地图纸片弹簧、战斗／骰子、洋馆时间幕与天气未改。战斗 960ms 主板只登记为独立演出，不迁入 820ms 预设。

`useCharacterIntro`、`useShopIntro`、`useMapIntro`、`useMansionIntro` 与本批修改前的源码逐字对照相同；没有调整资源准备、黑幕交接、提前输入、后台收束或收尾计时。新增检查保证主板和本地 CSS 子动作结束在页面收尾之前，M3 再处理共享生命周期。

## 运行验收

本机 5190、1280×720、独立 QA 存档。只浏览页面及开关窗口，不购买、不更换出战队伍／携带物、不推进剧情、时间或远征。

- 角色、商店、出征在冷启动的 `playing` 阶段均实际读到 `abyssa-page-board-settle, abyssa-ui-appear`，时长 `0.82s, 0.24s`，曲线与上表相同；没有只在组件库生效。
- 连续只读采样分别获取 12、13、15 个不同的中间位移。角色始终保留原 `transform:matrix(.950538,0,0,.950538,0,14.4)`，独立 translate 从上方移动；其 TAB 和资料仍在同一个宿主层次中。
- 三页 ready 终态保存的 animation／duration／opacity／translate／transform／DOMRect 与迁移前 JSON 比较完全相同。记录的主板盒尺寸：角色约 875×684.625、商店 1280×837.15、地图 1280×720；这些是宿主盒读数，不把商店宿主盒高度解释为可见面板尺寸。
- 洋馆仓库、日志、整备均实际读到 manor 与正文 `380ms / delay 140ms / cubic-bezier(.22,.6,.24,1)`，存在框体移动及正文后显的中间状态。结束后 panel `translate:0px`、`will-change:auto`，正文 `translate:none`。仓库关闭后焦点返回仓库按钮。
- 组件库 Page Board 同样读到共享动画与时长；保留预览框自带的 `.96` 缩放。Page Board Reduced 重播时 `animation:none / opacity:1 / translate:none`。
- Manor 预览与真实窗口正文时序一致；“下一条”更新后框体保持原位、`will-change:auto`；关闭中重开保留记录 2，不重置内容。Manor Reduced 正文不播位移，框体保持原位。减弱预览通过局部 Provider，不修改用户系统或持久化设置。

新增生成文件过程中，开发服务曾报一次嵌套 CSS 引用失败；窗口参数改为模块直接导入后返回 200，三个页面均重新冷启动验收。该中间状态没有作为验收结果。预览首次截图还发现无尺寸示例挤窄招牌，现已直接复用正式 manor-utility 窗口布局，未修改生产美术或尺寸。

## 回归与产物

- 15 个 app 测试文件，105 项通过：角色页 4 文件／25 项；商店＋窗口＋参数 5 文件／43 项；地图＋共享动效＋样式边界 6 文件／37 项。
- 新增 `presets.test.ts` 保护保留参数和单一引用；`ui-motion-presets.test.mjs` 保护生成同步、真实消费者、共享关键帧、收尾时钟、manor CSS 与预览接线。连同 M1 和 route-styles，共 9 项 Node 测试通过。
- `typecheck:app`、`boundaries:check`、`motion:check`、`git diff --check` 通过。
- `build:ui`、`build:game`、`build-storybook` 通过。Storybook 仍有自身大 chunk 提示，不更改构建阈值掩盖它。
- 游戏输出中共享主板为单一 `page-board-*.css`（约 0.47kB／gzip 0.23kB）；UI 包的 `abyssa-ui.css` 中对应关键帧也只定义一次。两种产物均不再含三页旧主板关键帧。

这证明动作和参数已合并到真实消费者，不等于所有页面动效已统一，也不等于卡顿已解决。上述浏览器采样用于确认中间状态和布局，不是逐帧性能基准。下一批为 M3，当前未开始。
