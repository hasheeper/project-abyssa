# 文风基线之后：单次生成的逻辑与人物演绎审查

日期：2026-09-23。用户已暂定接受r8文风；本轮不继续修改文风、不新增故事调用、不恢复大纲模型。这里只分析[冻结基线](../baselines/airp-style-r8/README.md)这一个样本，区分确定性错误、叙事缺口与质量判断。

证据：[场景输入](../baselines/airp-style-r8/scene.json)、[原始响应](../baselines/airp-style-r8/response.json)、[带差分中文审阅稿](../baselines/airp-style-r8/sample-expressions.md)、[实际输入的艾洛拉全文卡](../baselines/airp-style-r8/context/elora.txt)。以下段号沿用[诊断记录](../baselines/airp-style-r8/diagnostic-review.json)中的23个自然段，不含选项。中文审阅稿两处协议错误已标明，不拿人工润色后的内容审查。

## 结论

现在能写出可读的句子，但还没有稳定做到“同一组事实贯穿一回合、人物按自身目的行动、在明确决策点交还给玩家”。外部大纲可能有帮助，但现有证据不能证明唯一原因是少了一个模型：Gemini内部仍有原三段ICOT与一次角色台词校正，不是完全没有规划。

文风接受与逻辑缺陷是两个验收维度。下面的问题不通过加重文学风格、增加感叹号或让所有人更激动来解决。

## 1. 问题的性质在漂移，因果桥没补齐

- 输入：两张整备表有一处记录对不上，需要尤斯缇丝在原纸上确认。
- 第10／12段：“包布……好像写得多了一点点”“两边在耗材数量上的确差了几个记号”。读者收到的是数量不一致。
- 第13／14段变成：“是看不太清么”“字迹被压到了”。接下来又以重抄浪费羊皮纸作为主要顾虑。

“字迹不清导致抄错数”本来可以成立，因此不能直接判成硬矛盾；问题是文本没建立这条因果。究竟是已确认数量有差、只是读不清，还是誊抄有误，没有分清事实与猜测。读者难判断该核对库存、辨字还是找原记录者确认。

另一个状态缺口：第11段说右边已经是“艾洛拉自己誊抄的入库单”，后面又担心“猜着重抄”。可能是再抄一次，也可能这栏尚未完成；文本没有说明。不是不允许展开设定，而是关键单据状态一旦生成，就应被后文承接。

## 2. NPC有打算，但玩家的参与理由没有落到明确请托

第19／20段只说“我想直接拿原本去给尤斯缇丝小姐看一下”“她应该能想起来”，然后就等待凯尔回应。艾洛拉的方案已经自足，尚未讲清她希望凯尔陪同、帮忙确认，还是只听听意见。

这是互动节点缺口，不是要求每段强行出冲突。平静日常也可以有完整的“眼前问题→人物的打算→向玩家提出具体互动→在答复前停住”。当前最后一步主要由选项替正文补出来，所以体感像听了一段汇报，再被要求选一个任务方案。

原输入只给了一个简短场景，没有详细玩家参与理由，也没有事件卡的当前步骤／可用行动。这个缺口有一部分来自测试输入，不能全归咎于Gemini凭空没有想好剧情，更不能从该样本推断正式GM所有功能都没有实现。

## 3. 选项比正文知道得更多，而且主要在分配做事方式

选项1提出“陪她一起去房间找尤斯缇丝”，但场景和本篇正文未建立她就在房间。选项3“可能还在休息”明确是推测，不能当作已知日程；它可以是玩家猜测，但不应由后续系统直接写成确定状态。

三项是陪同、辨认、晚点核对。前两项都是协助，第三项是调整时间，仍偏处理方案，不是本项目短态度标签式的明显不同立场。不能说三项完全相同，但“玩家对她如何回应”被“玩家替她如何处理单据”挤掉了。

这些选项尚未发生，本篇也未续写结果。因此问题是选项设计和条件依据，不是已经替玩家接受了任务。

## 4. 条件口癖变成常驻可爱标签，关系口吻变泛

实际整张角色卡确实进入了请求，不是这次漏喂卡。卡中明确：平时努力自称“我”，在情绪激动、着急或委屈时才跑出“艾洛拉”。第7段只有“稍微有点犯愁”，第14段仍是解释纸张问题，却连续用了第三人称自称；文本没有铺到相应触发强度。这是条件化演绎不足，不宜简单归结为“缺少可爱台词”。

“尤斯缇丝小姐”也比卡中的队友“哥哥／姐姐”更泛化；不是绝对不能叫小姐，但既有熟人关系的口吻没有稳定用起来。

同时保留公平判断：她爱惜纸张、主张问原记录者、讲话认真礼貌，都与“小管家”基本自洽。不能为了让角色活起来，强行把她写成对谁都挑衅或事事爆发。欠缺的是“为什么此刻以这个口吻、对这个人这样说”，而非整个人设全部错误。

## 5. 具体设定与场面连续性没有守住

| 证据 | 判断 |
| --- | --- |
| 角色卡是“大大的、纯白平顶高筒神官帽，印金色圣纹”；第22段变为“金色的小神官帽” | 明确外观偏差：把装饰颜色扩成主体颜色，尺寸也反了。不是世界书缺失。 |
| 第2段坐在长椅边；第23段静静站在凯尔身侧，中间未交代起身 | 连续性缺口。小说可以略过普通动作，不是绝对物理矛盾；但在短AVG演出里容易让场面状态跳变。 |
| 先确立单块木质写字板，第18段“合了合手里的木板” | 道具动作含混：没建立它是可合拢的夹册，也可能原意是拢纸。应先保持道具形态一致。 |
| 第21段已等待回应，22／23段继续加外貌、站姿并再次强调等待 | 决策停点拖尾。不是旁白单句过长，而是节点结束后又补无新作用的镜头。 |

不建议靠把每个动作都写出来解决连续性；应该在生成时保持状态一致，只交代对当下画面有意义的变化。

## 6. 三段ICOT有形式，却未产生清晰的回合进展

本篇大体是“出现问题→再解释问题→说出找人确认的原定打算”，大部分信息都围着同一张纸打转。三段不需要各来一次反转，也不该再次把大纲做成逐句指挥；但每一段至少应带来有用的新认知、关系反应或互动条件，而不只是换一笔动作重述。

这是一项质量判断，不是协议错误；也不能仅因23段、8段台词就断言因果必然失败。已经接受的文风不需要为此撤销。

## 不是本次主要问题的部分

- 凯尔“是看不太清么”属于已允许的自然衔接问句，没有替玩家接受、拒绝、承诺或发表价值判断，不应重新一刀切禁止玩家衔接。
- 8个差分ID都合法，缺席者没有发言。未用>_<并不算失败，也不应强制变脸提高表现度。
- 一处缺日文、一处日中倒置属于交付协议问题，应与剧情逻辑分开处理；本轮没有偷偷放宽读取器。
- 文风是否喜欢由用户决定：用户已经接受这一轮。单次样本不能证明所有人物／场景的稳定水平，也不能证明恢复Sol一定改善。

## 建议的下一层职责（仅分析，未实施）

先固定最小回合事实：当前人物与位置、已知事实／待确认问题、这一步的事件目标、NPC希望玩家做什么、玩家尚未决定的事项、可以停下来的节点。把世界观全文和角色卡保留给Gemini，不用摘要替代。

若恢复大纲模型，它只应守住上述事实、因果和推进方向；不写台词，不规定每段旁白，不安排固定表情轨迹，不再用大纲抢走Gemini的文笔与角色口吻。输出是内容边界，不是逐句演出脚本。

另需在输出后检查：新增地点／日程是否有依据、单据与道具状态是否承接、人设条件是否触发、是否越过玩家决定、选项是否引入未确定事实。明确哪些可用程序检查，哪些需要语义审阅；不能把JSON可解析或ID合法当作这些检查已经通过。

建议优先顺序：事实与因果明确 → 玩家请托／停点明确 → 条件化角色演绎 → 连续性与协议交付。此处不指定恢复哪个模型，也不增加一次生成的写作任务量。本次已完成的只有文风基线归档和问题分析。
