# 洋馆首次开窗长帧：后续调查与保守修复

日期：2026-09-17。状态：**仅日志冗余滚动重置已修；整备长帧未解决。试验性预绘制方案已撤销，不交付。**

承接 [M4 遗留](2026-09-17-ui-motion-m4.md)。本轮不改变木板美术、布局、动画参数、Logo 或其他独立演出。

## 保留的修复

`game-client/JournalBrowser.tsx` 原先在阅读区首次挂载时直接写 `scrollTop = 0`。新 DOM 的滚动位置本来就是 0；写入仍可能触发布局同步，没有必要。

现用上一次实际选中记录 ID 判断：首次挂载不读写滚动位置，同一记录内容更新不回顶；切换记录或当前记录被移除后切换到后备记录，仍回到顶部。没有把滚动恢复改成延迟任务，也没有改选择逻辑。

新增测试验证首次挂载没有 scrollTop 写入、同 ID 更新保留 150px 滚动位置、实际切换记录时仅写一次 0。这是移除确定无用的布局触发，不据此宣称整备帧率改善。

## 定位证据

在独立 QA 原点、原游戏构建中加过临时计时，结束前全部移除：

- 整备首次 `modalFocusables` 约 31～37ms，随后的 focus 约 0.3～0.4ms，Motion 动画启动不到 1ms。
- 把 offsetParent 检查改为可见性检查后，检查变为约 8.6ms，但 focus 变为约 23.3ms。说明并未消除首次布局，只是把工作推到了下一次强制同步点；该替换不保留。
- 一次分项样本中 style 约 7.3ms、总检查约 36.7ms；测试点的 `document.fonts.status` 为 loaded。这不能进一步定位字体成形、图形首次绘制或具体浏览器布局函数。
- 日志另有首次 scrollTop 写入。仅推迟父窗口焦点，不会消除这条独立布局触发。

以上证据不支持「Motion 插值本身很慢」的判断，也不证明所有同步焦点都是无效工作。

## 未通过的方案与实际回退

试验过将 manor 窗口挂载与启动动画隔开一个自然绘制机会，预绘制面板／正文图层，准备后聚焦并开始原 760ms 动画；同时保护提前 Escape、退出输入隔离、重开和卸载。默认 surface 不延迟。

候选版本的点击处理里，强制样式／布局可降为 0；但仍有无脚本归因的长帧，不能只看 onclick 改善就交付。一次中间候选测到 147.7ms 长帧；调整正文层准备后继续重复测试，仍没有稳定的整体收益。

同机内置 Chromium、1280×720，同一独立 QA 档；每轮刷新洋馆，准备完成后依次打开整备、日志、仓库，等入场结束再关闭。每版三轮，不并行运行构建／测试。统计窗口从点击前 20ms 至关闭动作前，最长 1100ms，实际约 816～946ms；覆盖入场，排除退出。未清空资源缓存，也未控制整机负载，属于小样本回归，不是严格 FPS 基准。

两版这三轮的日志／仓库均未记录到大于 50ms 的 LoAF；不能把零记录解释为完全没有帧间抖动。原版整备两次可归因 onclick 的强制样式／布局为 34.5／33.5ms；候选第 3 轮 onclick 为 5.6ms、强制样式／布局为 0，但其后仍有 79.2ms 无脚本归因帧。

因此没有证据证明候选整体更顺；采用保守回退，不将其称为性能成果。以下全部恢复成本轮开始时的实现：

- UiModal 的启动时机、初始透明度、图层提示与 CSS。
- useModalPresentation 的同步焦点、输入与清理行为。
- 临时尺寸／布局 containment、可见性替换、准备帧属性与探针扩展。
- 候选专属测试；原有完整窗口测试保留。

实际对照期间三窗终态均为 x=208、y=112、864×496（显示像素），焦点位于对应关闭按钮，世界暂停有效；这仅证明布局／行为未变，不能抵消性能验收未通过。
