# 洋馆建筑渲染稳定性检查与修复

## 现象与判断边界

用户报告 Edge 中建筑和界面出现不规则矩形缺块、头像连同姓名/气泡消失、悬浮异常、天空黑色拖尾，夜间最明显。

检查发现旧场景在 5162×1910 的建筑 Canvas 周围叠加全世界大小的滤镜、multiply/screen 混合、地下遮罩和动态灯光，同时存在多层缩放、translate3d 和常驻 will-change。时段变化时建筑 Canvas 没有反复清空重画；单纯延长图片预加载不能解释文字/图钉一起消失。

这些证据更符合浏览器合成/栅格化链路异常，但没有抓到可稳定复现的旧版故障帧，不能把某条 CSS 或浏览器 GPU 日志认定为唯一已证实根因。本次修复消除了这条复杂的实时合成链路，而不是只增加等待时间。

## 新渲染约束

1. 图层全部解码后，在未挂载的 Canvas 中合成建筑、天空、地下压暗及相位灯光。请求 `willReadFrequently`，但不把它视为跨浏览器的软件渲染保证。
2. 编码为不透明 PNG，再等待新图片自身 `decode()` 完成，才发布 `MansionArtwork`。所有工作 Canvas 随即释放；页面中没有建筑 Canvas。
3. 页面直接挂载已经解码的同一个 Image 元素。下一张图准备期间保留旧图，新图与对应时段一起提交，替换后释放旧图及 Blob URL。
4. 世界及交互祖先不再使用全局滤镜、混色、遮罩或常驻图层提升。世界尺寸缩放和相机变换合并成一个二维变换。
5. 头像、姓名、气泡和房间热区保留为独立 DOM/SVG。只在夜间保留三个小范围普通叠色灯光的透明度变化；静态光色已经烘入景致。
6. 加载界面保持完全不透明，直到实际挂载的图片全部就绪；失败保留进度并提供重试。重试只读取进度，不再次推进时段。
7. 异步准备捕获对应时钟，不能把旧时段图片标为新时段；离开后取消发布。资源退休延迟至微任务检查，避免 Fast Refresh/效果重放销毁仍在显示的图片。

色调、建筑素材、人物安排和房间位置继续沿用现有数据。边缘暗角改为离屏四边渐变近似；原来的大范围动态光照改成静态底图加局部微光。这不是像素完全相同的着色实现。

## 验证记录

环境：原生 Microsoft Edge 153.0.4234.32，macOS 14.8.7 / Apple M2，原有页面缩放 110%，硬件加速保持开启。GPU 页面显示 Skia Graphite / GraphiteDawnMetal、Zero-copy tile update、Partial Raster；旧日志没有页面归属，因此不作为本页故障的直接证明。

测试使用独立本机端口和内存 GameSession，未读取或修改用户存档；既检查独立洋馆页，也通过实际 GameShell 路由检查菜单往返。

- 首轮逐一检查晨、昼、昏、夜的画面与人物安排。
- 完整路由中从第 1 天夜晚连续推进 **40 次**，到第 11 天夜晚。每次检查状态与图像时段一致，各夜间截图抽查未见黑块/缺块。
- 第 1 天及第 11 天夜晚执行菜单→洋馆往返，均恢复完整画面和正确时钟。
- 夜间横向浏览到宿舍、温室房间聚焦/退出、退出后的悬浮描边及房间文字正常。
- 夜间 9 个角色按钮（8 张头像与缇比首字回退）完整。渲染统计始终一张建筑图片、零个可见 Canvas；第 11 天最终统计新增 43 张、移除 42 张，未累计挂载旧世界。
- 内置浏览器补充检查：准备中加载界面完全遮住世界；撤下后景致完整；世界祖先计算样式均为 filter/mask none、blend normal、will-change auto。控制台未见错误或警告。

自动化验证：

npm run typecheck:app

9 个测试文件、51 项测试通过；类型检查与构建通过。覆盖实际 Image 挂载、图层解码屏障、编码/解码发布屏障、备用合成图、取消和资源释放、外部时钟变化、双击保护、失败后重试以及推进时间的持久化/去重。

结论：本轮修复后的原生 Edge 测试未复现用户报告的渲染异常。截图抽查不是逐帧录像，也不等于所有设备/驱动组合都不会发生 GPU 问题；若仍复现，应以刷新后的版本录制故障帧并关联具体渲染状态，不再默认归因于下载顺序。

## 后续：时段过场与整页显现柔化

在上述稳定渲染结构上，加载层增加 `cover → work → paint → reveal → ready` 的节奏：旧景压暗 280ms 后才执行推进；准备与实际图片解码期间保持完全遮挡；就绪停留至少 420ms，再以 720ms 渐隐加载层。前段先退场时段文字/图标，后段揭开完整景致，不对建筑、头像或四角组件做分批入场。首访直接从不透明的 work 开始，不暴露未准备的世界。

时钟光点按四时段顺向转动，夜→晨跨越 360°；文字、图标采用小幅移动和淡入。路由幕布未打开时暂停图标动效，完整路由回到 idle 后才启动揭幕，避免返回洋馆时入场动画已经播完。减少动态效果设置跳过装饰性等待，但仍等待实际图片解码。

后续验证独立记录：57 项测试、类型检查、构建、diff 检查通过。新增覆盖压暗完成前不提交推进、揭幕完成前不解锁交互、动画时长不能代替解码屏障、揭幕中外部时钟变化、路由幕布与揭幕顺序、夜→晨转动方向。内置浏览器检查四时段切换和菜单往返，揭幕透明度采样从 1 连续下降至 0，场景始终一张完整图片、零个可见建筑 Canvas，未见控制台错误。原生 Edge 控制连接在本次后续验证时超时，不能将上方 40 次 Edge 循环结果冒充为这次新增淡入淡出的复测结果。

## 后续：组件库风格统一与图标向上换挡

过场复用 `RpgFrame`、只读 `RpgFacetDiamond` 及共享缺口按钮造型。独立 `AbyssaProvider` 保持在洋馆的 inert 范围之外；返回菜单仍为原生链接，和重试按钮共享 `RpgNotchedPillArt`，没有嵌套交互元素。文字、字体、底色、刻度与边缘遵循组件库，取消散排英文、倾斜文字标签和逐项延迟入场。整个仪表 300ms 小幅落定，210ms 整体退出后再揭幕，状态机的 280/420/720ms 时序及资源就绪条件不变。

根据追加反馈，中央去掉厚斜面、铆钉、重描边，保留浅色平面底、八角轮廓与轻刻度。仅内部日月符号向上滚动：旧符号退出顶部，新符号从下方进入，160ms 后开始、460ms 完成。裁切由 88×88 的局部 SVG 视口承担，没有为世界添加滤镜、遮罩或合成层。相同相位初次进入不虚构切换；状态文字更新不会重建滚动轨道。减少动态效果时直接落在新符号，路由暂停同时暂停轨道。

本轮验证：11 个测试文件、70 项测试通过，`typecheck:app`、`build:mansion`、`git diff --check` 通过。使用 **Microsoft Edge 153.0.4234.32 无头测试窗口**，在隔离浏览器存档中检查实际 GameShell 的四时推进与菜单往返。最终追加图标调整后再次推进四次，逐帧采样确认 work/paint 透明度恒为 1、reveal 开始前轨道已到 -88px、交互持续锁定，始终一张建筑图片与零个建筑 Canvas，无页面脚本错误。另检查错误重试、返回链接键盘焦点、暂停/减少动态效果，以及 800×450 舞台下框体由 400px 等比缩至 200px。

本轮浏览器结果用于验证呈现与交互；无头 Edge 不等于用户原生窗口的 GPU 环境，也不将其作为旧版随机黑块问题已在所有设备消失的证明。截图与局部滚动帧位于 `dist/reports/mansion-time-style/`，该目录为本地测试产物。

## 后续：夜间光源校准、可见度与天空

旧光照把每个房间的中心上方（宽度 50%、高度 34%）当作光源，再用宽泛的 screen 光团抬亮暗部。大厅的亮点因此在烟囱而不在炉膛，书库又被驻在默认暖灯覆盖。现以原画 5162×1910 坐标登记 `mansion-light-sources.ts`：大厅炉口 (1601,1271)、守望小屋炉口 (3888,1181)、书库四盏蓝焰、结界中央红晶与两侧蓝灯等各有独立锚点。温室补齐蓝草 (3373,1167) 与金草 (3420,1163)，不再将“温室不点室内灯”误读为发光植物也不发光。

远处反光使用局部 soft-light 保留线稿，近处发光才使用小范围 screen。根据正常世界缩放下光源偏弱的反馈，增强光芯与近场、扩大到最多核心半径的 3.2 倍，同时限制在反光范围的 80% 内；不恢复整房间雾状光团。三处实时呼吸改为大厅炉口、小屋炉口和核心红晶，与烘焙光共用坐标，最大边长 168px。原画长椅前是食物托盘，没有可见篝火，因此撤掉椅背黄光；没有可见发光体的缝纫机和未点燃瞭望台也不再凭空发光。

夜空原有横向半径约 1755px 的月光团与全图补光已撤掉。独立夜空绘制采用纵向深蓝层次、半径 32px 的明确月轮、最多 128px 半径的局部晕光、固定但不平铺的 156 个疏密星点及少量薄云。夜空仍一次性合成在场景图片中，没有新增实时天空 Canvas、全景滤镜或动态混合层，晨昼昏的天空逻辑保持原样。

验证：14 个测试文件、81 项测试通过，类型检查、洋馆构建与 diff 检查通过。新增覆盖源点位置、蓝灯和温室双色草、静态/动态锚点一致、发光范围上限、非夜间不加实物灯光、夜空月晕上限及星点重访稳定性。Edge 153 无头隔离存档检查完整夜景、温室键盘聚焦，以及夜→晨→昼→昏→夜循环；始终一张世界图片、零个可见建筑 Canvas、三处局部动态光源，夜间九个角色按钮仍在，未见页面脚本错误。对照与最终截图在 `dist/reports/mansion-lighting/`。

## 后续：地下三间局部提亮与封印门红光

书库、结界核心室与封印门的原画暗度较高，统一夜间 `brightness(.7)` 再叠加地下压暗、色染和底部暗角后，室内细节不易辨认。仅这三间在离屏建筑绘制中覆盖局部曝光：书库与核心室改为 `.94`，封印门改为 `1`；共同夜间色染及地下阴影仍保留。源图裁切边界直接使用房间矩形，复用同一建筑 Canvas，不新增页面图层。书库和核心室局部截图的平均亮度分别提高约 30% / 31%，封印门含新红光约 51%，没有整体抬亮地下或天空。

封印门从极弱的灰绿色反光改为赤红封印光，锚点为门缝 (2763,1788)、锁链交点 (2756,1798)、左右符纹 (2647,1800) / (2877,1799)。狭长局部光芯贴近原画，仍为静态烘焙，不增加第四处实时呼吸或整门泛光。

本轮 14 个文件、83 项测试、类型检查及洋馆构建通过。新增测试覆盖夜间仅三间局部曝光、非夜间保持原滤镜、滤镜状态正确恢复、门缝与符纹均有红色发光且不新增动态光。Edge 无头隔离存档从晨推进到夜，检查实际总览与封印门聚焦：一张世界图片、零个可见建筑 Canvas、三处动态微光、九个角色按钮，无页面脚本错误。局部前后对照及实景截图保存在 `dist/reports/mansion-lighting/`。

## 后续：撤去月亮、替换带状云与补齐工坊炉光

按反馈撤去夜空月轮、月面及月晕，不改顶部时段指示图标。原四条极扁 Bézier 云带会产生横向硬轮廓，现完全移除：`mansion-night-clouds.ts` 用固定散列噪声、多尺度浓度、坐标扰动和倾斜云区生成疏密破碎的淡云，边缘透明渐退，没有连续封闭带状轮廓。云纹只生成一次 1291×275 的 CPU 像素数据；绘制时借用离屏小画布后立即释放，再与星空和建筑一起编码成原有的一张不透明景致。没有新增下载资源、可见天空 Canvas、动态噪声、CSS 模糊或混合层。

工坊原画左侧锻炉确有火焰，但固定灯表与光源锚点均遗漏。现添加夜间暖橙炉光 `(1472,1525)`，光芯半径 18×19、反光半径 97×89，照在炉内和近处砖石；不依赖是否有人驻在，不加第四处实时动画。前轮地下三间局部提亮及蓝灯、封印门红光保持原样。

本轮 15 个测试文件、87 项测试、类型检查、洋馆构建及 diff 检查通过。测试约束无月亮/月晕、无 Bézier 云带、云纹留白与透明渐变、云画布异常时释放、工坊无人时仍点亮，以及所有工作画布在景致发布前释放。Edge 无头隔离存档从晨→昼→昏→夜检查真实页面与工坊聚焦，仍为一张世界图片、零个可见建筑 Canvas、三处动态微光、九个角色按钮，无页面脚本错误。最终天空和炉光截图在 `dist/reports/mansion-lighting/night-clouds-final.png`、`workshop-forge-night.png` 与 `clouds-workshop-game-night.png`。
