## 2. 隐藏黑幕仍在运行的活动点

五页稳定态发现：`scene-transition-spinner` 已暂停，但隐藏的三个 `scene-transition-activity` 仍为 `running`。黑幕常驻挂载，仅不可见不会自动停止 CSS 动画。

在 `shared/transition/transition.css` 添加：

```css
.scene-transition:not([data-active]) .scene-transition__activity i {
  animation-play-state: paused;
}
```

复验：idle 时三点均暂停；切场 closing、`data-active=true` 时三点仍运行，周期仍为 1.35s，延迟仍为 0／225／450ms。closing／closed／opening 的标记由组件测试保护。六面骰仍为六个独立平面，黑幕资源等待、输入锁和揭幕编排不变。

这是减少隐藏动画空转，不是让可见进场减速，也不据此宣称 FPS 提升。`getAnimations()` 可能仍返回 paused 动画，不能将对象存在当成运行中或内存泄漏。

首帧脚本归因为 `DIV#root.onclick`。**整备首次打开的同步样式／布局是后续最明确的性能调查点，尚未定位到具体函数，本轮未解决。** 下一次应围绕这一个入口追踪挂载、尺寸读取与写入时序并多次对照，而不是再改全库曲线或重做窗口。

三窗口关闭后焦点均返回各自触发按钮，世界暂停标记解除；日志／整备打开完成时另核对 `data-world-paused=true`、云层 computed `animation-play-state:paused`、面板 `will-change:auto`。页面进场状态始终 ready，没有因窗口更新而重播。三窗关闭后的动画快照仅云层运行，黑幕四个动画对象均 paused。

模态期间 QA 快照按钮被正常输入门禁拦截；因此窗口内的云层暂停采用 computedStyle 验证，不能拿按钮被拦截前的旧快照判断它仍在运行。

监听清理由既有 `usePageUiIntro` StrictMode waiting／playing／ready 卸载测试核对 add/remove 对称、计时器归零、内容更新不重订阅且无 RAF；没有对整个浏览器做实时监听总量统计，不宣称全页监听数已减少。

## 6. 工具使用与限制

```sh
npm run motion:check
npm run motion:audit
npm run build:game
npm run motion:audit -- --json --build
npm run motion:profile
```

`motion:profile` 服务正式构建，只在内存覆盖验收 HTML、`game-assets.json` 与 `game-cache.js` 三个响应；同步重算验收 HTML 的哈希／字节与 manifest 版本，仍启用资源完整性校验。默认静态产物服务继续返回原始字节，磁盘构建和游戏 JS/CSS 不变。此工具只在本机独立原点使用，不发布为游戏服务器。

工具初版只注入 HTML 时曾触发资源哈希不匹配；已修正为上述三响应同步，之后页面成功加载。该中间错误来自 QA 工具，不记成游戏缺陷；浏览器保留的旧错误记录也不作为修正后新错误。

探针被动记录 PerformanceObserver longtask／long-animation-frame、限定五个页面阶段属性和点击时间；显式按钮才读取动画快照。不启动 RAF、轮询、计时器，不替换事件原型，不联网或修改玩法。每类数组最多 300 条，溢出标记 `truncated`；不支持的性能类型明确列出，不能视为零。探针本身有少量观测开销，这些数据不替代正式性能录制。

JSON 位于 DOM `#abyssa-motion-audit`。pagehide 时断开观察器、移除监听和按钮，标记 `stopped=true`；从 bfcache 恢复后须刷新再采样。修改构建或探针后须重启该服务器再刷新。此批实测使用同一被动采样机制；最终增加的 stopped 标记／无 PerformanceObserver 守卫经单元测试验证，未重新采集整套性能样本。
